# icd_utility 项目文档

## 项目概述

`icd_utility` 是一个独立整理的 C++17 ICD（接口控制文档 / Instrumentation and Control Description）工具库。其主要职责是：

- 读取 ICD 配置与帧定义
- 支持 XML 和 JSON 两种输入格式
- 将原始输入解析为统一的 schema 中间模型
- 通过 builder 构建 `Repository / Frame / Node` 运行时对象
- 通过 `Loader::init(...)` 提供统一的对外加载入口
- 使用 `tl::expected`（兼容 `std::expected` 语义）返回错误

---

## 总体架构

项目采用严格的分层架构，各层职责分明：

```
Loader (加载入口)
   │
   ▼
Parser (格式解析: XML / JSON)
   │
   ▼
Schema (中间模型)
   │
   ▼
Builder (构建器)
   │
   ▼
Core (运行时对象: Repository / Frame / Node)
```

### 数据流

```
Loader::init(config_path, format)
   │ 检测格式 (auto_detect / xml / json)
   ▼
parse_config() ──► XML/JSON parser ──► SchemaConfig
   │                                    │
   │  对每个文件条目:                      │
   ▼                                    ▼
parse_frame() ───► XML/JSON parser ──► SchemaFrameDef
   │                                    │
   ▼                                    ▼
Schema::build_repository() ─────────► Repository (内含 Frame / Node)
```

## 模块详解

### 一、公开头文件（`include/icd/`）

#### 1. export.hpp —— 导出宏

定义 `ICD_UTILITY_API` 宏，用于控制动态库导出/导入符号。

- Windows：根据 `ICD_UTILITY_STATIC` / `ICD_UTILITY_BUILDING_DLL` / `ICD_UTILITY_SHARED` 分别处理
- Linux / GCC：使用 `__attribute__((visibility("default")))`
- 默认情况下（CMake 中 `BUILD_SHARED_LIBS=OFF`）定义为空，即静态链接

---

#### 2. error.hpp —— 错误类型

**`ErrorCode` 枚举**定义所有错误类别：

| 值 | 含义 | 典型场景 |
|---|---|---|
| `invalid_argument` | 参数无效 | 节点解码参数非法、set_value 类型不匹配 |
| `io_error` | IO 错误 | 文件无法打开 |
| `parse_error` | 解析错误 | XML/JSON 文件格式损坏 |
| `schema_error` | 模式错误 | XML/JSON 缺少必填字段 |
| `duplicate_frame_id` | 重复帧 ID | 构 Repository 时 ID 冲突 |
| `duplicate_frame_name` | 重复帧名称 | 构 Repository 时名称冲突 |
| `invalid_node` | 无效节点 | Node 名称为空 |
| `unsupported_format` | 不支持的格式 | 文件扩展名无法识别 |
| `not_found` | 未找到 | 可选字段不存在 |

**`Error` 结构体**包含四个字段：

```
Error {
    ErrorCode code;            // 错误码
    std::string message;       // 错误描述
    std::filesystem::path file; // 关联文件路径（可选）
    std::string path_hint;     // 路径/字段提示（可选）
}
```

所有可能失败的操作都通过 `tl::expected<T, Error>` 返回错误，避免异常。

#### 3. types.hpp —— 基础类型定义

**格式枚举：**

```
enum class Format { auto_detect, xml, json };
```

`Loader::init()` 通过此参数指定输入格式。`auto_detect` 根据文件扩展名（.xml / .json）自动判断。

**帧类型枚举：**

```
enum class FrameType { data, cmd, data_cmd };
```

标记帧的数据语义：

- `data`：普通数据帧
- `cmd`：指令帧
- `data_cmd`：数据/指令混合帧

**字节序枚举：**

```
enum class ByteOrder { little_endian, big_endian };
```

用于帧级字节序设置，影响多字节数值在解码时的读取顺序。

**值类型枚举 `ValueType`：**

| 值 | C++ 类型 | 说明 |
|---|---|---|
| `boolean` | `bool` | 布尔值，宽度通常为 1 位 |
| `byte_` | `std::uint64_t` | 单字节，宽度 8 位，无符号 |
| `bytes` | `std::vector<std::byte>` | 多字节原始数据 |
| `word` | `std::uint16_t` | 双字节，宽度 16 位，无符号 |
| `shortint` | `std::int64_t` | 单字节有符号，宽度 8 位 |
| `smallint` | `std::int16_t` | 双字节有符号，宽度 16 位 |
| `longword` | `std::uint32_t` | 四字节，宽度 32 位，无符号 |
| `integer` | `std::int32_t` | 四字节有符号，宽度 32 位 |
| `ulong_` | `std::uint64_t` | 八字节，宽度 64 位，无符号 |
| `single` | `double` | 单精度浮点（解码后存为 `double`），宽度 32 位 |
| `double_` | `double` | 双精度浮点，宽度 64 位 |
| `string_` | `std::string` | 字符串，按字节读取 |
| `unknown` | — | 未知/不支持的类型 |

**标记枚举 `Tag`：**

```
enum class Tag {
    none, head, length, count, sum, sum2,
    xor_, xor1, xor2, init_value,
    signal_in_value, big_endian_value
};
```

用于标记节点的特殊语义角色（如校验和、长度域等）。具体含义取决于 ICD 协议设计。

**解码模式枚举：**

```
enum class DecodeMode { eager, lazy };
```

- `eager`：解码时立即计算所有节点的值
- `lazy`：仅标记为"已修改"，在首次访问时按需解码

**节点属性 `NodeAttrs`：**

```
struct NodeAttrs {
    std::string system_name;        // 所属系统名
    std::string group_name;         // 所属组名
    std::string unit;               // 物理单位（如 "V", "A", "度"）
    std::string value_text_list;    // 值-文本映射（枚举说明）
    std::string scale_formula;      // 缩放公式描述
    std::string scale_convertor;    // 缩放转换器描述
    std::string link_to;            // 关联/链接目标
    std::optional<float> min;       // 物理最小值
    std::optional<float> max;       // 物理最大值
    std::optional<float> scale_a;   // 缩放系数 A
    std::optional<float> scale_b;   // 缩放系数 B
    bool is_scaled {false};         // 是否经过缩放
};
```

这些属性在 XML/JSON 解析时从文件中读取，存储在运行时 `Node` 对象中供查询使用。

**节点值变体 `NodeValue`：**

```
using NodeValue = std::variant<bool, uint16_t, int16_t, uint32_t, int32_t,
                               uint64_t, int64_t, double, std::string,
                               std::vector<std::byte>>;
```

统一表示解码后的节点值。使用 `std::holds_alternative<T>()` 和 `std::get<T>()` 访问。

#### 4. node.hpp —— Node 类

`Node` 是数据层级中的基本单元，表示帧中的一个数据字段。

**类关系：**

- 每个 `Node` 可能有一个 `parent_`（父节点）和一个 `frame_`（所属帧）
- 每个 `Node` 可以有多个子节点（`children_`），形成树形结构
- 叶子节点承载具体的数据值

**核心 API：**

| 方法 | 返回值 | 说明 |
|---|---|---|
| `name()` | `std::string_view` | 节点名称 |
| `description()` | `std::string_view` | 节点描述 |
| `offset()` | `int` | 字节偏移（在帧数据中的起始位置） |
| `bit_offset()` | `int` | 位偏移（在起始字节内的位偏移） |
| `bit_width()` | `int` | 位宽度（占据的总位数） |
| `value_type()` | `ValueType` | 值类型 |
| `tag()` | `Tag` | 标记 |
| `attrs()` | `const NodeAttrs&` | 节点属性 |
| `parent()` | `const Node*` | 父节点指针 |
| `children()` | `icd::span<const unique_ptr<Node>>` | 子节点列表 |
| `find(name)` | `const Node*` | 递归查找子节点 |
| `add_child(node)` | `void` | 添加子节点 |
| `get_value()` | `tl::expected<const NodeValue*, Error>` | 获取当前值 |
| `resolve_value()` | `tl::expected<const NodeValue*, Error>` | 从帧数据解码值 |
| `set_value(value)` | `tl::expected<void, Error>` | 设置值（写回帧缓冲） |
| `decode(bytes, order)` | `tl::expected<NodeValue, Error>` | 从字节序列解码值 |
| `modified()` | `bool` | 值是否已被修改 |

**解码机制：**

`decode()` 方法根据节点的 `offset`、`bit_offset`、`bit_width` 和 `value_type`，从原始字节序列中提取并解释数据：

1. 整数类型：按字节序读取，可选符号扩展
2. 浮点类型：使用 `icd::bit_cast` 从整数位模式转换
3. 布尔类型：提取指定位
4. 字符串/字节数组：按字节对齐读取

`resolve_value()` 检查帧的解码缓冲，若存在则调用 `decode()` 并将结果缓存在 `value_` 中。

`set_value()` 验证类型匹配后将值写入帧的解码缓冲，并递归标记子节点为"已修改"。

#### 5. frame.hpp —— Frame 类

`Frame` 表示一个完整的 ICD 帧，对应 ICD 协议中一条独立的消息定义。

**核心 API：**

| 方法 | 返回值 | 说明 |
|---|---|---|
| `id()` | `int` | 帧 ID |
| `name()` | `std::string_view` | 帧名称 |
| `description()` | `std::string_view` | 帧描述 |
| `type()` | `FrameType` | 帧类型 |
| `order()` | `ByteOrder` | 字节序 |
| `roots()` | `icd::span<const unique_ptr<Node>>` | 根节点列表 |
| `nodes()` | `icd::span<Node* const>` | 所有节点的扁平列表 |
| `find(name)` | `const Node*` | 在帧内按名称查找节点 |
| `decode(bytes, mode)` | `tl::expected<void, Error>` | 解码帧数据 |
| `add_root(node)` | `void` | 添加根节点 |

**内部状态：**

- `roots_`：根节点列表（树结构起点）
- `nodes_`：所有节点的扁平向量（用于快速名称查找和批量解码）
- `decode_buffer_`：最近一次解码的原始字节缓冲
- `has_decode_buffer_`：表示是否有缓存的帧数据

**`decode()` 流程：**

```
Frame::decode(frame_bytes, mode)
   │
   ├─ 复制 frame_bytes 到 decode_buffer_
   │
   ├─ eager 模式：遍历所有节点，依次调用 resolve_value()
   │   ├─ resolve_value() 调用 decode(frame_buffer)
   │   │   ├─ 按 offset/bit_offset/bit_width 从缓冲中提取位
   │   │   ├─ 按 value_type 解析为对应 C++ 类型
   │   │   └─ 返回 NodeValue
   │   │
   │   └─ 缓存结果到 Node::value_
   │
   └─ lazy 模式：仅设置所有节点的 modified_ = true
       实际解码延迟到首次 get_value()/resolve_value() 时
```

调用 `add_root()` 时，节点会被自动注册到帧的扁平索引中（通过 `index_subtree()`），同时设置节点的 `frame_` 指针。

---

#### 6. repository.hpp —— Repository 类

`Repository` 是运行时 ICD 模型的根容器，管理所有 `Frame` 对象。

**核心 API：**

| 方法 | 返回值 | 说明 |
|---|---|---|
| `frames()` | `icd::span<const unique_ptr<Frame>>` | 所有帧的只读视图 |
| `find(id)` | `const Frame*` | 按整数 ID 查找帧 |
| `find(name)` | `const Frame*` | 按名称查找帧 |
| `find(frame_name, node_name)` | `const Node*` | 跨帧按名称查找节点 |
| `add_frame(frame)` | `void` | 添加帧 |

**内部索引：**

- `frames_by_id_`：`unordered_map<int, Frame*>`，ID → 帧的快速查找
- `frames_by_name_`：`unordered_map<string, Frame*>`，名称 → 帧的快速查找

`add_frame()` 在添加帧时自动填充上述索引。

#### 7. loader.hpp —— Loader 类（入口）

`Loader` 是唯一推荐的对外加载入口，封装了整个加载流程。

**静态方法：**

```
static tl::expected<Repository, Error>
    Loader::init(const std::filesystem::path& config_path,
                 Format format = Format::auto_detect);
```

**参数：**

- `config_path`：ICD 配置文件路径（XML 或 JSON）
- `format`：指定输入格式，默认 `auto_detect`（根据文件扩展名判断）

**返回值：**

- 成功：`Repository` 对象，包含所有解析后的帧和节点
- 失败：`Error`，含具体错误码和上下文信息

### 二、Schema 层（`src/schema/`）

#### 1. schema.hpp —— 中间模型定义

Schema 层是独立于输入格式的中间数据模型，充当解析结果与运行时对象之间的桥梁。

**`SchemaNodeDef`** —— 节点的中间表示：

```
struct SchemaNodeDef {
    std::string name;                    // 节点名称
    std::string description;             // 描述
    int offset {};                       // 字节偏移
    int bit_offset {};                   // 位偏移
    int bit_width {};                    // 位宽度
    ValueType value_type {unknown};      // 值类型
    Tag tag {none};                      // 标签
    NodeAttrs attrs;                     // 节点属性
    vector<SchemaNodeDef> children;      // 子节点（递归）
};
```

**`SchemaFrameDef`** —— 帧的中间表示：

```
struct SchemaFrameDef {
    int id {};                              // 帧 ID
    std::string name;                       // 帧名称
    std::string description;                // 描述
    FrameType type {data};                  // 帧类型
    ByteOrder order {little_endian};        // 字节序
    vector<SchemaNodeDef> roots;            // 根节点列表
};
```

**`SchemaFileEntry`** —— 文件条目（config 中引用单个帧文件）：

```
struct SchemaFileEntry {
    optional<int> id;              // 可选的帧 ID 覆盖
    std::string logical_name;      // 逻辑名称
    std::string description;       // 描述
    std::string path;              // 帧文件路径（相对 config 文件）
    optional<FrameType> type;      // 可选的帧类型覆盖
    optional<ByteOrder> order;     // 可选的字节序覆盖
    Format format {auto_detect};   // 帧文件格式
};
```

**`SchemaConfig`** —— 配置文件的中间表示：

```
struct SchemaConfig {
    vector<SchemaFileEntry> files;    // 配置文件中的文件条目
    vector<SchemaFrameDef> frames;    // 已解析的帧定义
};
```

#### 2. schema.cpp

当前阶段保持最小化，仅包含头文件的包含实现，为后续扩展预留空间。

#### 3. builder.hpp/cpp —— 构建器

负责将 Schema 中间模型转换为运行时对象。

**核心函数：**

```
tl::expected<Repository, Error>
build_repository(const SchemaConfig& config);
```

**构建流程：**

1. 遍历 `config.frames`，为每个 `SchemaFrameDef` 创建 `Frame` 对象
2. 对每个帧，递归遍历 `roots` 中的 `SchemaNodeDef`，创建 `Node` 树
3. 校验每个 `Node` 的名称不能为空
4. 检查帧 ID 和名称的唯一性（`unordered_set` 去重）
5. 将构建好的 `Frame` 依次添加到 `Repository`

**校验规则：**

| 校验项 | 错误码 | 条件 |
|---|---|---|
| 节点名非空 | `invalid_node` | `SchemaNodeDef.name.empty()` |
| 帧 ID 唯一 | `duplicate_frame_id` | 两个帧的 `id` 相同 |
| 帧名唯一 | `duplicate_frame_name` | 两个帧的 `name` 相同 |

**子节点处理：**

`build_node()` 是递归函数，对每个 `SchemaNodeDef`：
1. 创建 `Node` 对象
2. 递归处理 `children` 列表
3. 调用 `node->add_child()` 建立父子关系

### 三、格式层（`src/format/`）

#### 1. xml_parser.hpp/cpp —— XML 解析器

将 XML 格式的 ICD 文件解析为 Schema 中间模型。

**公开接口：**

```
tl::expected<schema::SchemaConfig, Error>
parse_xml_config(const std::filesystem::path& path);

tl::expected<schema::SchemaFrameDef, Error>
parse_xml_frame(const std::filesystem::path& path);
```

**`parse_xml_config()` 流程：**

1. 加载并解析 XML 文件
2. 查找 `<ICDConfig>` 根元素
3. 遍历 `<Files>` → `<FileInfo>` 条目
4. 对每个条目提取：Name、Path、ID、Type、ByteOrder、Description
5. 填充为 `SchemaFileEntry`，存入 `SchemaConfig`

**`parse_xml_frame()` 流程：**

1. 加载并解析 XML 文件
2. 查找 `<ICDData>` 根元素
3. 读取 `<Name>` 作为帧名称
4. 遍历 `<Data>` → `<Item>` 节点
5. 递归调用 `parse_node()` 解析每个 Item
6. 填充为 `SchemaFrameDef`

**`parse_node()` 解析过程：**

```
每个 <Item> 节点解析为 SchemaNodeDef：

必填字段：
  <Offset>      → node.offset
  <StartBit>    → node.bit_offset
  <BitWidth>    → node.bit_width
  <Type>        → node.value_type
  <Name>        → node.name
  <Description> → node.description
  <IsScaled>    → node.attrs.is_scaled

可选字段：
  <GroupName>   → node.attrs.group_name
  <SystemName>  → node.attrs.system_name
  <Unit>        → node.attrs.unit
  <ValueTextList> → node.attrs.value_text_list
  <ScaleFormula> → node.attrs.scale_formula
  <ScaleConveror> → node.attrs.scale_convertor
  <LinkTo>      → node.attrs.link_to
  <ScaleA>      → node.attrs.scale_a
  <ScaleB>      → node.attrs.scale_b
  <Min>         → node.attrs.min
  <Max>         → node.attrs.max
  <Tag>         → node.tag

子节点：
  <Childs> → <Item> → 递归调用 parse_node()
```

**内部辅助函数：**

- `parse_int(node, child_name, file)`：解析必填整数字段，缺失或无效时返回错误
- `parse_float(node, child_name, file)`：解析可选浮点字段
- `parse_optional_int(node, child_name)`：解析可选整数字段，缺失时返回 `nullopt`
- `parse_value_type(type)`：将字符串类型名映射为 `ValueType` 枚举
- `parse_frame_type(raw)`：将整数映射为 `FrameType` 枚举
- `parse_byte_order(raw)`：将整数映射为 `ByteOrder` 枚举
- `load_xml_document(path)`：使用 pugixml 加载和解析 XML 文件

#### 2. json_parser.hpp/cpp —— JSON 解析器

将 JSON 格式的 ICD 文件解析为 Schema 中间模型，API 与 XML 解析器对称。

**公开接口：**

```
tl::expected<schema::SchemaConfig, Error>
parse_json_config(const std::filesystem::path& path);

tl::expected<schema::SchemaFrameDef, Error>
parse_json_frame(const std::filesystem::path& path);
```

**`parse_json_config()` 流程：**

1. 加载并解析 JSON 文件
2. 检查 `files` 数组存在
3. 遍历数组条目
4. 对每个条目提取：name、path、id、type、byteOrder、description
5. 填充为 `SchemaFileEntry`，存入 `SchemaConfig`

**`parse_json_frame()` 流程：**

1. 加载并解析 JSON 文件
2. 读取 `name` 字段作为帧名称
3. 遍历 `data` 数组
4. 递归调用 `parse_node()` 解析每个元素
5. 填充为 `SchemaFrameDef`

**`parse_node()` 解析过程：**

```
每个 JSON 对象解析为 SchemaNodeDef：

必填字段：
  "offset"      → node.offset
  "startBit"    → node.bit_offset
  "bitWidth"    → node.bit_width
  "type"        → node.value_type
  "name"        → node.name
  "description" → node.description
  "isScaled"    → node.attrs.is_scaled

可选字段：
  "groupName"      → node.attrs.group_name
  "systemName"     → node.attrs.system_name
  "unit"           → node.attrs.unit
  "valueTextList"  → node.attrs.value_text_list
  "scaleFormula"   → node.attrs.scale_formula
  "scaleConveror"  → node.attrs.scale_convertor
  "linkTo"         → node.attrs.link_to
  "scaleA"         → node.attrs.scale_a
  "scaleB"         → node.attrs.scale_b
  "min"            → node.attrs.min
  "max"            → node.attrs.max
  "tag"            → node.tag

子节点：
  "childs" → 数组 → 递归调用 parse_node()
```

**内部辅助函数：**

- `load_json_document(path)`：使用 nlohmann/json 加载和解析 JSON 文件
- `required_int(object, key, path)`：提取必填整数
- `optional_float(object, key, path)`：提取可选浮点
- `parse_value_type(type)`：将字符串类型名映射为 `ValueType` 枚举

### 四、加载层（`src/loader/`）

#### loader.cpp —— 加载流程实现

实现 `Loader::init()` 的完整流程。

**`init()` 方法内部流程：**

```
Loader::init(config_path, format)
   │
   ├─ 1. 格式自动检测（如 auto_detect）
   │     根据文件扩展名判断 .xml / .json
   │
   ├─ 2. 解析配置文件
   │     parse_config() 分发到 xml_parser / json_parser
   │     得到 SchemaConfig（含 file entries）
   │
   ├─ 3. 遍历文件条目，解析每个帧文件
   │     for each FileEntry:
   │       ├─ 构建帧文件完整路径（相对于 config 目录）
   │       ├─ parse_frame() 分发到对应解析器
   │       ├─ 覆盖元数据（ID / name / description / type / order）
   │       └─ 收集到 SchemaConfig.frames
   │
   ├─ 4. 构建 Repository
   │     schema::build_repository(merged)
   │     ├─ 校验帧 ID 唯一性
   │     ├─ 校验帧名称唯一性
   │     ├─ 构建 Frame 对象
   │     └─ 递归构建 Node 树
   │
   └─ 5. 返回 Repository
```

**格式检测：**

```
detect_format(path) 内部逻辑：
  .xml   → Format::xml
  .json  → Format::json
  其他   → Format::auto_detect
```

如果自动检测失败（如 `.unsupported` 扩展名），返回 `unsupported_format` 错误。

**元数据覆盖：**

当 config 文件中的 `FileEntry` 包含可选字段（id、type、order 等）时，这些值会覆盖帧文件中读取的对应值。这允许在不修改帧文件本身的前提下，在配置层面调整帧属性。

### 五、Core 核心层（`src/core/`）

#### 1. node.cpp —— Node 实现

**值解码实现细节：**

`Node::decode()` 根据 `value_type_` 分发到不同的解码逻辑：

| 值类型 | 解码逻辑 |
|---|---|
| `boolean` | 调用 `extract_bits()`，提取指定位，转换为 bool |
| `byte_` | 调用 `read_integer_bits()`，结果为 `uint64_t` |
| `word` | 调用 `read_integer_bits()`，结果为 `uint16_t` |
| `smallint` | 调用 `read_integer_bits()` + `sign_extend()`，结果为 `int16_t` |
| `longword` | 调用 `read_integer_bits()`，结果为 `uint32_t` |
| `integer` | 调用 `read_integer_bits()` + `sign_extend()`，结果为 `int32_t` |
| `ulong_` | 调用 `read_integer_bits()`，结果为 `uint64_t` |
| `shortint` | 调用 `read_integer_bits()` + `sign_extend()`，结果为 `int64_t` |
| `single` | 调用 `read_floating<float>()`，结果存为 `double` |
| `double_` | 调用 `read_floating<double>()`，结果为 `double` |
| `bytes` | 调用 `read_bytes()`，结果为 `vector<byte>` |
| `string_` | 调用 `read_bytes()`，转为 `string` |

**内部位操作函数：**

- `extract_bits(frame_bytes, offset, bit_offset, bit_width)`：从字节序列的指定位偏移处提取 `bit_width` 位，返回 `uint64_t`
- `read_integer_bits(frame_bytes, offset, bit_offset, bit_width, order)`：按字节序读取整数（对字节对齐的情况做优化，逐字节拼接；非对齐时回退到 `extract_bits()`）
- `read_bytes(frame_bytes, offset, bit_offset, bit_width)`：按字节对齐读取原始字节
- `read_floating<T>(...)`：调用 `read_integer_bits()` 后使用 `icd::bit_cast` 将位模式转为浮点数
- `sign_extend(value, bit_width)`：将有符号整数的位模式符号扩展到 64 位

**值写入实现细节：**

`Node::set_value()` 将值写回帧的解码缓冲：

- 所有写入操作都通过 `write_integer_bits()` 或 `write_bytes()` 完成
- 写入前校验值类型与节点声明的 `value_type_` 是否匹配
- 对有符号类型调用 `ensure_signed_fits()` 校验范围
- 对无符号类型调用 `ensure_unsigned_fits()` 校验范围
- 写入成功后缓存值到 `value_`，标记 `modified_ = false`
- 调用 `mark_children_modified()` 递归通知子节点"值已过时"

#### 2. frame.cpp —— Frame 实现

- `roots()` / `nodes()` 返回 `icd::span` 视图，不拷贝数据
- `find(name)` 遍历 `nodes_` 向量进行线性查找
- `decode()` 支持 eager 和 lazy 两种模式
- `add_root()` 自动建立节点到帧的关联索引
- `index_subtree()` 递归遍历子树，将所有节点注册到 `nodes_` 扁平列表并设置 `frame_` 指针

#### 3. repository.cpp —— Repository 实现

- `frames()` 返回 `icd::span` 视图
- `find(int id)` 通过 `unordered_map` 进行 O(1) 查找
- `find(string_view name)` 通过 `unordered_map` 进行 O(1) 查找
- `find(frame_name, node_name)` 先查找帧，再在帧内查找节点
- `add_frame()` 自动维护 `frames_by_id_` 和 `frames_by_name_` 两个索引

### 六、Compat 兼容层（`src/compat/`）

为 C++17 环境提供 C++20/23 特性的替代实现，使项目无需升级编译器标准即可使用现代化 API。

#### 1. span.hpp —— span 替代实现

`icd::span<T>` 是 `std::span` 的最小替代，提供对连续内存区域的只读/读写视图。

**功能：**

- 默认构造（空 span）
- 指针+大小构造
- 容器构造（通过 SFINAE 检测 `.data()` 方法）
- `data()`、`size()`、`empty()`
- `begin()` / `end()` 迭代器
- `operator[]` 下标访问
- `first(n)` / `last(n)` 子视图

**设计约束：实现仅覆盖本项目实际使用的 API，不追求完全兼容 `std::span`。**

#### 2. bit.hpp —— bit_cast 替代实现

`icd::bit_cast<To, From>()` 是 `std::bit_cast` 的替代实现。

**实现原理：**

```cpp
template <typename To, typename From>
To bit_cast(const From& src) noexcept {
    To dst;
    std::memcpy(&dst, &src, sizeof(To));
    return dst;
}
```

- 编译时校验：`sizeof(To) == sizeof(From)`、两者均为 trivially copyable
- 用于 `node.cpp` 中 float/double 与整数位模式之间的转换

### 九、设计准则总结

#### 分层边界

| 层 | 职责 | 不负责 |
|---|---|---|
| `format/` | 解析输入文件（XML/JSON） | 仓储查询、运行时模型 |
| `schema/` | 统一中间表示、构建校验 | 文件 IO 调度、格式解析细节 |
| `core/` | 运行时对象与查询 | 输入格式解析、schema 规则 |
| `loader/` | 装配流程编排 | 复杂 schema 规则、格式细节 |
| `compat/` | C++17 缺失特性补丁 | 业务逻辑 |

#### 核心约定

1. **错误处理**：所有可能失败的操作返回 `tl::expected<T, Error>`，不使用异常
2. **分层依赖**：上层可依赖下层，反向禁止
3. **接口稳定性**：`include/icd/` 下的头文件为稳定公开接口
4. **最小改动原则**：扩展功能时优先沿现有路径，不做无关重构
5. **第三方库隔离**：pugixml（XML 解析）仅在 `format/` 层使用；nlohmann/json（JSON 解析）仅在 `format/` 层使用；两者不暴露到上层

#### 扩展指南

- **新增输入字段**：parser → schema → builder → runtime model
- **新增输入格式**：新建 parser → 输出 Schema 模型 → Loader 接入
- **新增查询能力**：扩展 Repository 或 Frame，保持不与 schema/format 耦合
