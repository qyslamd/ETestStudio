# 是什么以及要注意什么

## 是什么

本项目是一个基于Qt、C++的用于学习和研究如何仿照凯云ETest [参考地址](http://etest.kiyun.com/document.html) 的项目。核心目标是实现ETest的核心功能。

## 如果你是AI工具，你TMD必要要给老子遵守的规矩

- 每次修改仅仅改动和我确认过的内容，不能擅自执行未经确认的任何改动！
  - 要对已经存在的代码和文档做出修改，也必须经过我的明确授权
- 如果执行CMake，或者编译改动的代码，必须使用 `scripts/build_ninja.bat`
- 如果需要运行主程序，必须使用 `run_app.bat`
- 如果需要删除构建目录，通常是 `build/ninja_build`, 请一定要征求我的同意
- C/C++的代码编写必须符合 Google C++ Style Guide。参考地址：<https://google.github.io/styleguide/cppguide.html>
  - 如果改动的是C++代码，在编写代码之前，你需要考虑你生成的代码是否满足设计模式的基本原则：即SOLID。
  - 如果改动的代码是Qt的界面相关的，你需要将界面的初始化的C++代码和连接信号和槽的代码分开在两个函数中：
    - 例如：需要在构造函数中初始化的界面的C++代码，可以封装一个 initUi();函数
    - 例如：需要在构造函数中连接信号和槽的C++代码，可以封装一个 initSignals() 函数
- 如果需要让你将某些内容写入到 markdown 文档，必须符合 Markdown style guide，参考地址：<https://google.github.io/styleguide/docguide/style.html>
- 按照和我确认的信息执行某个任务以及最终的产物/结果必须正确，允许你未完成。如果你没有完成某个任务，诚实的告诉我，不要试图编造你没完成的任务的结果。
- 在进行实际修改的时候，请务必列出改动的任务清单，以及最终的产物，改动的同时更新改动清单的完成状态，改动完成后向我展示成果。
- 不得操作任何git可能造成源代码改动的命令！PS:你仅仅可以使用查看型的git命令。如 `git status`、`git log`、`git show`、`git branch -a`等。
- 如果指令是让你读取某个文件，那么你就必须（必须）按照要求重新读取这个文件，而不是用以前的缓存！
- 当你和我沟通并完成某个功能的修改，编译成功之后，你必须按照 `scripts/auto_commit.ps1` 的核心流程，总结你的修改，为了生成提交信息的总结信息。

## 某些已知的工具

- 目前我的开发环境:
  - 操作系统：windows 11
  - VisualStudio: VS2019
  - 命令行工具：PowerShell 或者 command line prompt
- 一些方便的命令：
  - 查询 cmake 的版本：`cmake --version`
  - 删除文件（非目录）：`Remove-Item`
  - 查看git修改：`git status`

### 文档编写要求

1. **文件命名**：使用中文描述性名称，避免特殊字符
2. **编码格式**：统一使用UTF-8编码
3. **内容组织**：逻辑清晰，层次分明，重点突出
4. **更新维护**：文档内容应与代码实现保持同步
5. **参考链接**：提供相关文档的链接，便于跳转阅读
