## 二、各模块技术细节
### 1. 插件框架
- 基于Qt Plugin原生框架实现，核心基类：
  - `DevicePlugin`：每个总线类型对应一个插件，负责设备枚举、创建设备实例、提供配置参数元数据
  - `DeviceChannel`：每个通道对应实例，提供统一的同步/异步读写接口
- 插件部署：编译为独立动态库（Windows.dll/Linux.so），存放在`plugins/devices`目录，程序启动自动扫描加载
- 附加能力：支持插件加载状态查询、版本管理

### 2. 各总线插件实现方案
| 总线类型 | 实现细节 |
|----------|----------|
| 串口（RS232/422/485） | 基于Qt`QSerialPort`实现，仅支持标准波特率，无硬件/软件流控 |
| TCP客户端 | 基于Qt`QTcpSocket`实现，支持远程IP/端口配置 |
| TCP服务端 | 基于Qt`QTcpServer`实现，支持多客户端连接，支持监听端口配置 |
| UDP | 基于Qt`QUdpSocket`实现，仅支持单播模式，支持本地端口、远程IP/端口配置 |
| 模拟AI/AO/DI/DO | 模拟模式实现，支持Lua脚本自定义数据生成逻辑，预留实际硬件对接接口 |
| CAN | 预留插件框架，后续对接具体CAN卡SDK时无需修改核心代码 |

### 3. 统一通道接口设计
同时提供同步和异步两种接口：
```cpp
// 异步接口（推荐）
virtual bool open() = 0;
virtual void close() = 0;
virtual void asyncWrite(const QByteArray &data) = 0;
// 信号：void dataReceived(const QByteArray &data); // 异步收到数据
// 信号：void stateChanged(bool isConnected, const QString &errorMsg); // 状态变化

// 同步接口（可选，阻塞调用）
virtual bool syncWrite(const QByteArray &data, int timeout = 1000) = 0;
virtual QByteArray syncRead(int timeout = 1000) = 0;
```

### 4. 设备配置与管理
- 配置界面：基于通用表单自动生成，根据插件提供的参数元数据自动渲染配置项
- 配置存储：设备配置信息保存在项目文件中，支持导出/导入为JSON格式，方便批量部署
- 设备状态展示：新增"设备管理器"侧边栏视图，展示所有设备的连接状态、通道列表，支持快捷打开/关闭、配置修改操作

### 5. 设备自检功能
- 基础自检：尝试打开设备，检测连接状态，返回连接成功/失败结果
- 通道回环测试：支持通道收发回环验证（需要硬件支持回环模式）
- 结果输出：自检结果写入日志系统，后续可根据UI设计增加可视化展示

## 三、跨平台适配要点
1. 插件编译配置：CMake中配置动态库编译规则，自动输出到对应平台的plugins目录
2. 串口/网络API：Qt原生组件已跨平台兼容，无需额外适配
3. Lua脚本引擎：跨平台编译适配，确保Windows/Linux下Lua脚本执行行为一致
4. 动态库加载：使用Qt`QLibrary`加载插件，自动处理不同平台动态库后缀差异
