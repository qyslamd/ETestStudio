# 使用Qt开发仿凯云ETest计划
## 一、核心功能分析报告
### 1. 整体架构
基于凯云ETest核心能力，Qt实现版本划分为5个核心模块：
| 模块 | 核心功能 |
|------|----------|
| 基础框架层 | 类VSCode的UI布局，项目/文件管理，基础工具链，通用插件框架，基础设施 |
| 设备管理层 | 常用总线设备配置、连接管理、状态监控，统一通道读写接口，插件化架构 |
| ICD协议管理层 | 图形化协议编辑，XML/Excel导入导出，协议打包解包能力，支持分层结构 |
| 测试用例编辑层 | 表格拖拽式可视化用例编辑，支持常用动作和流程控制，参数化支持，Lua脚本集成 |
| 测试执行层 | 用例调度执行，实时监控，数据记录，测试报告生成，断点调试 |

### 2. 各模块详细功能
#### 2.1 设备管理层
- 支持的总线类型：串口（RS232/422/485）、CAN（预留对接具体硬件SDK）、TCP客户端/服务端、UDP、模拟量输入输出（AI/AO）、开关量输入输出（DI/DO）
- 功能：设备参数配置、连接状态监控、通道抽象层（为上层提供统一的read/write接口）、设备自检、配置导入导出
- 架构：插件化设计，后续扩展新总线无需修改核心代码

#### 2.2 ICD协议管理层
- 图形化协议编辑器：支持字段增删改、拖拽排序、属性配置（名称、类型、长度、偏移、默认值、字节序）
- 导入导出：支持XML、Excel格式导入导出，对齐凯云ETest模板，支持批量导入，支持与YAML格式互转，支持导出C/C++结构体头文件
- 核心能力：协议自动打包解包，提供C++原生接口供测试用例调用，支持CRC/和校验/异或校验
- 存储格式：同时支持XML和JSON格式，分层结构支持嵌套结构体/数组

#### 2.3 测试用例编辑层
- 表格拖拽式编辑：支持动作拖拽添加、移动、复制、删除
- 支持的动作类型：基础动作（变量声明、延时、打印、自定义脚本、退出）、IO动作（数据/报文收发、模拟量/数字量采集输出）、测试动作（合格/失败断言、数值限度测试）、流程控制（if判断、while循环）
- 脚本引擎：集成Lua引擎，与凯云ETest脚本格式兼容，每个用例独立虚拟机，权限隔离
- 高级特性：支持用例参数化，内置参数列表，多轮循环执行

#### 2.4 测试执行层
- 执行调度：支持用例启动、暂停、继续、终止、重新执行，单线程串行执行，普通断点、单步调试
- 实时监控：展示通道数据、执行日志、变量上下文、执行进度，分级着色显示
- 数据存储：SQLite数据库存储全量执行过程数据，永久保留，支持备份导出/导入
- 测试报告：自动生成HTML/Excel/PDF三种格式测试报告，支持自定义PDF页头页脚/Logo
- 性能指标：动作延时误差≤10ms，冷启动≤3s，常规运行内存≤200MB

## 二、开发计划（最终版，适配2人中高级开发资源）
### 总周期：20~22周（约5个月），包含2~4周缓冲时间（应对学习成本、未知问题、BUG修复）
### 开发模式：阶段1完成后，阶段2（设备模块）与阶段3（ICD模块）并行开发，压缩总周期
| 阶段 | 周期 | 人员安排 | 核心交付内容 |
|------|------|----------|--------------|
| 阶段1：基础框架搭建 | 3周 | 2人共同开发，同步学习Lua基础 | 完整基础框架、第三方依赖集成、跨阶段接口规范、数据自动备份功能 |
| 并行开发阶段 | 3周 | 开发A负责阶段2（设备模块），开发B负责阶段3（ICD模块） | 设备管理层完整功能、ICD协议管理层完整功能 |
| 阶段4：测试用例编辑层开发 | 3周 | 2人共同开发 | 完整用例编辑功能、Lua脚本集成、参数化支持 |
| 阶段5：测试执行层开发 | 3周 | 2人共同开发 | 执行引擎、监控面板、存储模块、报告生成功能 |
| 阶段6：测试与优化 | 4周 | 2人共同测试、优化、打包 | 全流程测试、体验优化、全平台软件包、交付文档 |
| 预留缓冲 | 2~4周 | 灵活安排 | 应对未知问题、需求调整、BUG修复 |

### 兼容平台
- Windows：Windows 7/10/11 64位
- Linux：Ubuntu 20.04/22.04 64位

### 交付产物
1. 软件包：
   - Windows：Innosetup安装包，包含所有运行时库，免额外依赖
   - Linux：绿色压缩包，解压即可运行
2. 文档：
   - 用户操作手册
   - 开发API文档
   - 示例项目（包含示例ICD、测试用例、设备配置）

## 三、质量标准
1. 单元测试：整体覆盖率≥80%，所有用例100%通过
2. BUG遗留：严重BUG（崩溃、核心功能失效）零遗留，次要BUG≤3个
3. 稳定性：连续24小时运行无崩溃、无内存泄漏，单用例重复执行1000次无异常
4. 性能：动作延时误差≤10ms，冷启动≤3s，常规运行内存≤200MB
