# 综合性自动化测试平台 (IATP) 详细设计规格说明书

## 1. 项目概述
本项目旨在开发一款面向工业自动化、航空航天及车载总线领域的通用化、综合性测试平台。通过硬件抽象层 (HAL)、接口控制文档 (ICD) 及 脚本执行引擎，实现测试逻辑与物理硬件的高度解耦。

## 2. 总体系统架构
采用五层解耦架构，支持跨平台运行（Windows, Linux, QNX/VxWorks），并预留 Web 化升级空间。

### 2.1 架构分层
1.  **用户界面层 (Application/UI)**: 基于 Qt (Widgets/GraphicsView) 实现，提供可视化交互。
2.  **执行引擎与业务层 (Engine & Logic)**: 负责测试流转、脚本解释及用例管理。
3.  **ICD 数据映射层 (Data Mapping)**: 负责信号语义解析、大/小端转换及工程值换算。
4.  **实时数据池 (Real-time Data Pool)**: 系统的“数据底座”，负责信号最新值 (CVT) 与流数据 (Streaming) 的高并发调度。
5.  **硬件抽象层 (HAL & Plugins)**: 插件化硬件驱动，支持多进程隔离保护机制。

---

## 3. 硬件支持与管理

### 3.1 硬件覆盖范围
* **模拟/数字 IO**: AD (低速)、DA (低速/任波)、IO 开关量、脉冲信号。
* **通讯总线**: 
    * 串行: RS232, RS422, RS485。
    * 航空: A429, 1553B。
    * 车载: CAN, CANFD, LIN, Flexray。
    * 网络: TCP, UDP, WebSocket, MQTT。
* **程控仪器 (VISA/SCPI)**: 电源、示波器、万用表、摄像头。

### 3.2 硬件管理机制
* **插件化加载**: 基于 `QPluginLoader` 动态加载各厂家驱动。
* **硬件树展示**: 
    * 一级：厂家 (Manufacturer)
    * 二级：分类 (Class, 如 AD/CAN)
    * 三级：具体设备实例 (Status/Self-test 实时显示)。
* **多进程隔离保护 (高级建议)**: 
    * 采用“驱动代理 (Driver Proxy)”模式。
    * 核心引擎为父进程，不稳定插件运行在独立的子进程中，通过共享内存 (Shared Memory) 交换数据，防止单点崩溃导致系统停机。

## 4. 可视化设计器

### 4.1 硬件连接拓扑编辑器
* 基于 `Qt GraphicsView` 框架。
* 支持通过连线描述“硬件通道”与“被测设备 (UUT) 接口”的映射关系。
* 生成 JSON 格式的拓扑描述文件。

### 4.2 帧协议编辑器
* 可视化定义数据帧结构：起始位、位长、大小端、编码方式。
* **反向同步机制 (高级建议)**: 引入 UUID 机制。当帧结构修改时，ICD 信号通过 UUID 自动同步，无需手动修改测试用例。

---

## 5. ICD (接口控制文档) 层

* **信号 (Signal) 定义**: 信号是工程意义的最小单位（如“迎角”、“油压”）。
* **双向转换逻辑**: 
    * 工程值 -> 比特流 (设置操作)
    * 比特流 -> 工程值 (读取/验证操作)
* **属性描述**: 名称、单位、量程、有效性范围、转换公式 ($y = kx + b$ 或查表法)。

---

## 6. 测试用例管理与 DSL

### 6.1 测试用例描述方式
支持人话描述与结构化 JSON 描述。

#### JSON DSL 示例
```json
{
  "name": "测试用例集",
  "cases": [
    {
      "name": "温度验证",
      "steps": [
        { "cmd": "SET", "who": "温度传感器", "value": 37.5 },
        { "cmd": "VERIFY", "who": "温度传感器", "value": 37.5, "tolerance": {"min": -0.1, "max": 0.1} },
        { "cmd": "DELAY", "value": 1000, "unit": "ms" }
      ]
    }
  ]
}
```

### 6.2 脚本执行引擎
* **语言选型**: Lua (推荐，Sol2 嵌入)、Python 或 JavaScript。
* **自动化转换**: 平台自动将 JSON 用例转换为脚本代码。
* **调试功能**: 支持单步执行、断点设置、变量实时监视。
* **Dry Run (影子运行)**: 提供空跑模式，不加载物理硬件，仅验证脚本逻辑。

## 7. 高级特性与优化建议

### 7.1 实时数据池 (RTDP)
* **双表架构**: 
    * **CVT (Current Value Table)**: 存放最新工程值。
    * **Buffer**: 针对高频数据（如示波器）的环形缓冲区。
* **性能保证**: 静态内存分配，避免测试过程中的动态内存申请 (Malloc Free)。

### 7.2 故障注入 (Fault Injection)
* 支持在 ICD 层模拟硬件错误：CAN 报文丢包、CRC 错误、信号值超限、信号死滞。

### 7.3 数据记录与报表
* **双轨存储**: 
    * 逻辑日志：SQLite 记录步骤结果。
    * 原始信号：采用 **MDF4** 标准格式存储，支持高速回放与专业分析工具对接。

### 7.4 行业标准兼容
* 建议参考 **ASAM XIL** 标准定义接口，提升软件的专业认可度。

---

## 8. 实施路径 (MVP)
1.  **Phase 1**: 搭建 C++ 核心骨架、实现 HAL 基础接口。
2.  **Phase 2**: 实现一个总线插件 (如 CAN) 和一个 IO 插件，验证 ICD 转换逻辑。
3.  **Phase 3**: 集成脚本解释器，跑通“JSON -> 脚本 -> 数据池 -> 硬件”的闭环。
4.  **Phase 4**: 完善可视化编辑器与多进程保护机制。
