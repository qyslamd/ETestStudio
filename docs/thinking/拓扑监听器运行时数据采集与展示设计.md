# 拓扑监听器运行时数据采集与展示设计

> **版本**: v2.1
> **日期**: 2026-07-16
> **状态**: 设计定稿（经代码验证修正）

## 1. 背景

拓扑编辑器中的监听器（Monitor）功能已完成可视化编辑侧的开发：

- ✅ 数据结构 `TopologyMonitor` / `TopologyMonitorTap`
- ✅ 可视化 `MonitorItem` / `MonitorPortItem`（信号条、通道点矩阵、hover）
- ✅ 交互：拖拽 MonitorPort → Connection 挂载、点击点取消挂载
- ✅ Undo/Redo 全命令支持
- ✅ JSON 序列化/反序列化
- ✅ 剪贴板复制/粘贴、对齐/分布、大纲导航

**未覆盖部分**：引擎运行时的数据采集、展示和持久化完全空白。本文档覆盖这部分的设计决策。

## 2. 已明确的决策

### 2.1 数据采集方式

| 项目 | 决策 |
|------|------|
| 采集策略 | **被动嗅探（Passive Snooping）** — 不主动采样，在每个 SET/CHECK/VERIFY 步骤经过 tapped connection 时顺带记录 |
| 采集时机 | StepRunner 执行 `execSet`/`execCheck`/`execVerify` 完成后，将经过 ICD 编解码的值送入监听记录器 |
| 数据内容 | 每个采样保存 **原始值（raw）** + **解析后的工程值（eng）** |
| 原始值定义 | 从硬件读出的二进制/整数（如 `0x0A8B`），或写给硬件的帧字节 |
| 工程值定义 | 经过 ICD 编解码（coeff/offset 线性映射）后的可读值（如 `5.0V`） |
| execSet 限制 | **execSet 记录的是写入的命令值（step.value），非硬件回读值**。SET 是写操作，硬件不回读，被动嗅探只能记录"写了什么"。CHECK/VERIFY 记录的是硬件实际读到的值 |
| WAIT 盲区 | execWait 不发射采样信号（轮询会过量采样），挂在 WAIT 目标信号上的 tap 采不到样 |

### 2.2 引擎架构 — MonitorManager

| 项目 | 决策 |
|------|------|
| 架构 | **独立 MonitorManager 组件**，StepRunner 不感知监听器 |
| 数据流 | StepRunner 在每次硬件操作完成后 emit `hardwareOperationFinished(deviceId, portName, rawFrame, rawValue, engValue)`，MonitorManager 订阅该信号自行查表 |
| 查表 | MonitorManager 每次 `start()` 时重新加载拓扑文档中 monitors + taps，建立 `(deviceId, devicePort) → QList<MonitorTapInfo>` 查表。**tap 直接持有 deviceId，无需经 connection 中转**。不跨运行缓存，避免拓扑修改后查表过时 |
| 理由 | 职责分离、可独立测试、扩展性好（将来其他被动记录需求只需订阅同一信号） |

```cpp
// 查表结构
struct MonitorTapInfo {
  int monitorIndex;
  int channelIndex;
  QString deviceId;
  QString devicePort;
};

// 采样记录
struct MonitorSample {
  int monitorIndex;
  int channelIndex;
  double engValue;       // 工程值，如 5.0V

  // 原始值（二选一，视信号类型使用哪个字段）：
  double rawValue = 0.0;     // AD/DA 单整数，如 0x0A8B → 2699
  QByteArray rawFrame;       // CAN/Serial/A429 帧字节

  QDateTime timestamp;
};
```

**信号签名：**

```cpp
// StepRunner 发射（5 参数，rawFrame 和 rawValue 分开承载）
signals:
  void hardwareOperationFinished(const QString& deviceId,
                                  const QString& portName,
                                  const QByteArray& rawFrame,
                                  double rawValue,
                                  double engValue);
```

emit 处填充规则：
- AD/DA：`rawFrame` 留空 `QByteArray()`，`rawValue` 填 `codec_->encode(...).toDouble()`
- 帧类（CAN/Serial/A429）：`rawFrame` 填帧字节，`rawValue` 留 `0.0`

MonitorManager::onHardwareOpFinished 直接把两参数原样填进 MonitorSample，无需判断类型。

**发射时机：**
- `execSet`/`execCheck`/`execVerify` 中，**硬件读写成功后、return 前发射**，与步骤 PASS/FAIL 无关（CHECK 值不匹配但 read 成功也发射）
- 异常（DeviceException/TimeoutException）不发射
- `execDelay`/`execLoop`/`execWhile`/`execIf`/`execWait` 不发射

**查表键来源（关键修正）：**

`TopologyMonitorTap` 新增 `deviceId` 字段（UUID），拓扑编辑器挂载 tap 时由 `tap.deviceName` 查 `devices[].id` 填入。查表直接用 `tap.deviceId + tap.devicePort`，绕开 connection，彻底消除 deviceName 重名歧义。

**线程安全（修正描述）：**

MonitorManager 在**主线程**创建（engine 在主线程 createEngine）。`connect(runner_, signal, monitor_manager_, slot)` 跨线程走 `Qt::QueuedConnection`，slot 在 receiver 所在线程（主线程）执行，**不在工作线程**。

- `buffer_` 写入、`flushSamples` 读取、`subscribe` 的 `std::function` 回调**全部在主线程串行执行**，无真并发，无需加锁
- `subscribe` 是 `std::function` 同步调用，不是信号槽
- 副作用：采样数据排队到主线程事件循环，`timestamp` 在 slot 里取 `currentDateTime()` 会有毫秒级排队延迟。被动嗅探是步骤级（非高频采样），此延迟可接受

> 注：`QList` 不是线程安全的，但因全主线程串行访问，此处使用 `QList` 足够。

**channelCount 与 taps 的关系：**
- `channelCount` = 监听器声明的硬件通道容量（如 4 通道 AD 卡）
- `taps.size()` = 实际挂载的 tap 数（≤ channelCount）
- `channelIndex` = `taps[]` 数组下标（0..taps.size()-1），**非物理通道号**
- 未挂载的通道不参与查表，不产生采样

### 2.3 持久化方案

| 项目 | 决策 |
|------|------|
| 方案 | **嵌入 `.etlog`** — 监听数据作为 `.etlog` JSON 的一个顶级数组 `monitors[]` |
| 理由 | 监听数据与执行结果强关联（时间线绑定），回看只需打开一个文件；量级可控（几百~几千条/次运行）；无需新文件格式/新依赖 |
| 否决选项 | 独立 `.emonitor`（文件关联维护成本高）、SQLite（轻度场景偏重） |
| 向后兼容 | `monitors[]` 是 JSON 顶级数组，旧版解析器遇到未知 key 自动忽略，不会报错 |

**flush 时序（关键）：**

`saveReport(etlogPath)` 由 `ExecutionPanelController` 的 `engineFinished` 回调（主线程）触发。内部流程：

```
TestExecutionEngine::saveReport(etlogPath)
  -> collector_->setMonitorData(monitor_manager_->flushSamples())  // 主线程读 buffer_，安全
  -> collector_->saveToFile(etlogPath)
```

`flushSamples()` 在主线程调用，此时工作线程已退出，`buffer_` 无写入，读取安全。不在 `onWorkerFinished` 里调 saveToFile。

#### 挑战与应对

设计过程中识别出三类关键场景，驱动了 UI 架构的决策：

| 场景 | 挑战 | 应对方案 |
|------|------|---------|
| **1000 个信号要监听** | 平铺卡片不现实，需要导航筛选 | 信号树（按监听器→通道分组）+ 搜索框 |
| **AD 采集看波形** | 数值文本不够直观，需要时序视图 | 按信号类型切换可视化组件，AD 用 WaveformWidget |
| **串口开关量看状态** | 数值 0/1 不直观，需要状态指示 | 按信号类型切换可视化组件，离散量用 StateLEDWidget |

### 3.2 Ribbon 的跨页面适配

Ribbon 是编辑态和运行态共享的全局组件（不在 central_stack_ 内）。运行态下 Ribbon 需要以下调整：

**QuickAccessBar（左上角，不随 tab 切换）：**

```
[📁][📂][💾] [↩][↪] | [🔀 运行/编辑] [👤 登录状态] [⚙ 设置]
      文件操作            模式切换    登录       设置
```

| 按钮 | 来源 | 说明 |
|------|------|------|
| 🔀 运行/编辑 | 新增 | 编辑态显示"🔀 运行"，运行态显示"🔀 编辑"，点击切换 `central_stack_` 页面 |
| 👤 登录状态 | 从 ActivityBar 底部迁入 | 显示当前登录用户，点击弹出登录/用户信息菜单 |
| ⚙ 设置 | 从 ActivityBar 底部迁入 | 打开设置对话框 |

> 迁走后 ActivityBarWidget 简化为纯页面导航，移除底部的 login_btn_ 和 settings_btn_。

**Ribbon tab 切换行为：**

Ribbon tab 切换和 `central_stack_` 页面切换是**两个独立机制**，互不影响：

| 切换机制 | 控制方式 | 影响范围 |
|---------|---------|---------|
| `central_stack_` 页面切换 (page 0 ↔ page 1) | QuickAccessBar "🔀 运行/编辑"按钮 | 切换编辑态/运行态 |
| Ribbon tab 切换 (主页/视图/运行/工具/帮助) | 点击 Ribbon tab | 只切换 Ribbon 显示的面板，不改变 `central_stack_` 当前页 |

| 场景 | 行为 |
|------|------|
| page 1 运行态时，用户点 Ribbon 的"主页"tab | Ribbon 切到主页面板。`central_stack_` 保持在 page 1。用户看到灰色的编辑 action，但不影响波形图运行 |
| page 1 运行态时，用户点 QAB "🔀 编辑" | `central_stack_` 切回 page 0。Ribbon 在之前切到的哪个 tab 就停留在哪 |

> 设计意图：Ribbon tab 仅仅是功能面板的分类切换，不应影响运行态/编辑态的切换。模式切换统一由 QAB 按钮管理。

**运行态视觉反馈：**

| 手段 | 说明 |
|------|------|
| Ribbon 底部指示线 | 运行态时给 RibbonBar 设 objectName（如 `RunningMode`），QSS 选择器加 `border-bottom`。编辑态移除 objectName |
| QAB 切换按钮 | `setCheckable(true)`，编辑态 unchecked（"🔀 运行"），运行态 checked（"🔀 编辑"） |

**运行态 Action 状态管理：**

进入 page 1 时禁用以下 action，切回 page 0 时恢复：

| tab | 禁用的 action | 理由 |
|-----|--------------|------|
| 主页-文件 | 保存、另存为、保存所有、关闭文件、关闭所有 | 编辑器不可见，无文件可操作 |
| 主页-编辑 | 撤销、重做、剪切、复制、粘贴、查找、替换、跳转行 | 同上 |
| 视图-面板 | 日志/输出/问题/终端/辅助侧边栏显隐 | page 1 不使用 page 0 的面板 |
| 工具 | 独立编辑器启动（拓扑/协议/测试程序） | 运行态不应打开新编辑器 |

| tab | 保持可用的 action | 理由 |
|-----|------------------|------|
| 主页-文件 | 新建项目、打开项目、关闭项目 | 切换项目不依赖当前编辑状态 |
| 运行 | 全部（运行/暂停/停止/验证/运行全部/统计） | 运行核心操作 |
| 工具 | 设置 | 任何时候都可用 |
| 帮助 | 全部 | 信息查询不受模式影响 |

### 3.3 SignalTreePanel

**职责**：导航和筛选所有监听器通道，提供实时值缩略。

```cpp
class SignalTreePanel : public QWidget {
  Q_OBJECT
  // 树结构：TopologyMonitor → channel
  // 每个叶节点显示当前实时值缩略
 signals:
  void signalSelected(int monitorIndex, int channelIndex);
  void signalDragStarted(int monitorIndex, int channelIndex);
  void selectionChanged(QList<QPair<int,int>> selectedSignals);
};
```

**设计要点：**

| 项目 | 说明 |
|------|------|
| 树结构 | 顶级 = 监听器名称，二级 = 通道（带信号类型图标） |
| 实时值 | 每个叶节点右侧显示当前最新值缩略（如 `5.02V` / `● ON` / `0x7FF`），由 `sampleCaptured` 信号更新 |
| 搜索框 | 顶部固定，按名称/设备/端口模糊过滤，实时缩小树 |
| 交互 | 勾选 checkbox = 固定到可视化区；单击 = 选中（高亮但不影响可视化区） |
| 选中态 | 多选由 checkbox 控制，被勾选的信号全部展示在可视化区 |
| 图标 | 每种信号类型（AD/DA/CAN/SERIAL/A429）有独立图标，一目了然 |

**1000 个信号的应对：**
- 树本身支持折叠/展开，默认只展开正在产生数据的通道
- 搜索框支持模糊匹配，用户知道名字就直接搜
- 树节点分页/懒加载（1000 个节点对 QTreeView 来说是小量，不需要虚拟化）
- 实时值更新只更新**可见节点**（不可见时跳过刷新）

### 3.3 VisualizationArea（中央主区域 — QGraphicsView 容器）

**职责**：展示被勾选信号的详细可视化内容。采用 `QGraphicsView + QGraphicsScene` 作为容器，每个可视化组件通过 `QGraphicsProxyWidget::setWidget()` 嵌入为图元。

**为什么用 QGraphicsView：**

| 优势 | 说明 |
|------|------|
| 布局灵活性 | QGraphicsGridLayout 或手动布局，新增/移除图元自动排列 |
| 大量图元 | 100+ 可视化卡片场景下依然流畅 |
| 内置滚动缩放 | `setDragMode(ScrollHandDrag)` + 滚轮缩放，全盘一览或聚焦局部 |
| setWidget 嵌入 | 每个 SignalVisualizer 子类作为普通 QWidget 开发，通过 `QGraphicsProxyWidget` 嵌入，不改动现有组件体系 |

> **性能说明**：QGraphicsProxyWidget 增加了一层 paint() 间接调用，但监听器数据来自被动嗅探（步骤级，刷新频率数帧/秒），开销可忽略。**兜底方案**：如果后续出现高频采样场景，WaveformWidget 可改为直接实现 `QGraphicsItem` 子类。|

```cpp
class VisualizationArea : public QGraphicsView {
  Q_OBJECT
 public:
  explicit VisualizationArea(QWidget* parent = nullptr);

  void addVisualizer(int monitorIndex, int channelIndex,
                     SignalVisualizer* visualizer);
  void removeVisualizer(int monitorIndex, int channelIndex);
  void clearAll();

 private:
  QGraphicsScene* scene_;
  QHash<QPair<int,int>, QGraphicsProxyWidget*> visualizer_items_;
  // 布局策略：自动网格排列
  void relayout();
};
```

**交互方式：**

| 操作 | 效果 |
|------|------|
| 信号树中**勾选 checkbox** | 对应通道被固定到可视化区，自动创建对应类型的 SignalVisualizer |
| 信号树中**取消勾选** | 从可视化区移除该信号 |
| 可视化区 **x 关闭按钮** | 移除该信号（同时取消信号树中的勾选） |
| 可视化区右键菜单 | 切换显示模式、配置显示参数 |
| 鼠标滚轮 | 缩放可视化区整体视图 |
| 拖拽空白区域 | 平移可视区（ScrollHandDrag 模式） |

**布局策略：**

勾选的信号数量变化时自动重新排列。同类信号（如同为 AD 通道）默认叠加到同一张波形图上，异类信号分格展示：

| 数量 | 布局 |
|------|------|
| 0 | 显示引导文字："在左侧信号树中勾选要观测的信号" |
| 1 | 单个可视化组件占满全区域 |
| 2~4（同类） | 叠加到同一组件，不同颜色区分 |
| 2~4（异类） | 网格 2×2 |
| 5~16 | 自动增加列数（3列、4列），每个格子自适应缩小 |
| 16+ | QGraphicsView 原生滚动支持，所有格子等大排列 |

用户也可通过右键菜单手动指定某个可视化组件是否叠加更多信号或独占一格。

    ↓

    ↓

    ↓
⑥ 执行过程中，数据流:
    StepRunner → hardwareOperationFinished → MonitorManager

    ↓

    ├─ 波形图停留在最后状态，可滚动回顾

    ↓

    ├─ 解析 monitors[] 段，重建信号树 + 波形回放（静态）
    └─ 用户可逐通道查看历史采样
