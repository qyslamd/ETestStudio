# 综合性自动化测试平台 (IATP) 核心技术白皮书

## 1. 项目核心愿景
构建一个**硬件无关、逻辑驱动、工业级稳定**的综合性测控平台。通过“硬件抽象”与“信号建模”，屏蔽底层物理差异，使用户能够专注于测试业务逻辑。

## 2. 核心架构：五层解耦模型
| 层级 | 名称 | 关键职责 | 核心价值 |
| :--- | :--- | :--- | :--- |
| **L5** | 用户界面层 | 拓扑/帧/ICD编辑器、可视化监控 | 降低用户操作门槛 |
| **L4** | 配置管理层 | 解析 JSON/YAML/Excel 配置及 ICD | 实现数据驱动 |
| **L3** | 执行引擎层 | 嵌入式脚本解释器 (Lua/Python/JS) | 实现复杂的分支与逻辑控制 |
| **L2** | ICD 映射层 | “比特流”与“工程值”的双向转换 | 业务逻辑与物理数据的桥梁 |
| **L1** | 硬件抽象层 | 插件化加载、多进程驱动隔离 | 硬件即插即用，保障系统不死机 |

## 3. 三大核心技术关键点

### 3.1 硬件插件化与稳定性方案 (HAL)
* **两级接口设计**：
    * **IPlugin**: 负责生命周期管理（初始化、自检、退出）。
    * **IDeviceInterface**: 针对 AD/DA、总线、VISA 分别定义专用操作接口。
* **【关键优化】驱动隔离代理**：为了防止不稳定的第三方硬件 SDK 导致主程序崩溃，建议将每个驱动运行在独立的 **Driver Proxy 进程** 中，通过共享内存进行 CVT 数据交换。

### 3.2 ICD 信号转换引擎 (核心灵魂)
* **信号建模**：定义信号的量程、单位、偏移量及转换公式（$y = kx + b$ 或多项式）。
* **映射机制**：信号可以自由映射到 AD 通道、CAN 报文位偏移、或 VISA 查询指令。
* **数据池 (Data Pool)**：引入异步信号总线，硬件层将数据“推”入池，应用层从池中“取”数据，解决生产者与消费者频率不一致问题。

### 3.3 测试用例引擎与 DSL
* **混合编辑模式**：
    * **低代码模式**：基于 JSON 的结构化 DSL，适合简单流程。
    * **全代码模式**：自动将 DSL 转换为 Lua/Python 脚本，支持复杂的循环、跳转和算法。
* **影子运行 (Dry Run)**：支持硬件模拟模式，在不连接真实设备的情况下，验证脚本的业务逻辑闭环。

## 4. 关键技术特性
1.  **全局授时同步**：基于 PTP (IEEE 1588) 或高精度系统时钟，为所有采集数据打上统一时间戳，解决不同频率硬件的数据对齐难题。
2.  **故障注入 (Fault Injection)**：在 ICD 层允许模拟丢包、校验错误或值超限，用于验证被测设备的鲁棒性。
3.  **行业标准兼容**：
    * 支持 **MDF4** 格式导出，对接通用分析工具。
    * 参考 **ASAM XIL** 标准定义接口。

## 5. MVP (最小可行性产品) 实施路径
1.  **骨架搭建**：完成 Qt 插件加载机制及核心信号总线（数据池）。
2.  **闭环验证**：实现一个 CAN 插件 + 一个 AD 插件，跑通“物理信号 -> ICD 转换 -> 脚本判断”的闭环。
3.  **工具完善**：开发可视化 ICD 编辑器与拓扑连线工具。
