# 测控领域综合性测试软件初步计划

## 一、初始需求概述
> 我打算用Qt和python/lua/javascript来编写一个综合性的在测控领域的测试软件。这个软件的大致思路是这样的。首先我需要测试的东西有这么些 AD、DA、IO、RS232/422/485、A429、CAN、Flexray、1553B、TCP/IP、基于VISA的电源、示波器、万用表。我打算这样做：基于Qt的插件机制定义统一的基本接口，然后对每一类的卡/设备再定义操作接口。然后加载这些插件，我就能获取到连接到计算机的所有硬件板卡/设备，在此基础之上，我将引入测控领域的ICD层，打算使用基于信号的测试方式，ICD用于定义需要测试的信号的工程值和硬件设备的通道或者某些数据字段的关系。然后在ICD的基础之上，可以通过编辑测试用例，组织测试流程。完成对不同硬件在某一测试场景下的测试。测试用例需要测试引擎负责执行，这其中还需要考虑很多东西。

## 二、整体架构设计
采用四层松耦合架构设计，从上到下依次为：
```
┌─────────────────────────────────────────┐
│  应用层 (Application Layer)             │
│  - 主界面、编辑器、监控面板、报告生成    │
├─────────────────────────────────────────┤
│  测试引擎层 (Test Engine Layer)         │
│  - 用例解析、执行调度、脚本引擎、结果管理│
├─────────────────────────────────────────┤
│  ICD信号层 (ICD Signal Layer)           │
│  - 信号定义、硬件映射、转换引擎、信号总线│
├─────────────────────────────────────────┤
│  硬件抽象层 (Hardware Abstraction Layer)│
│  - 插件接口、设备插件、硬件IO、连接管理  │
└─────────────────────────────────────────┘
```

## 三、各层详细设计

### 1. 硬件抽象层（HAL）
#### 核心设计：两级插件接口
**基础插件接口（所有插件必须实现）**
```cpp
class IPlugin {
public:
    virtual ~IPlugin() = default;
    virtual QString pluginId() const = 0;      // 插件唯一ID
    virtual QString pluginName() const = 0;    // 插件名称
    virtual QString pluginType() const = 0;    // 插件类型
    virtual QString pluginVersion() const = 0; // 插件版本
    
    virtual bool initialize() = 0;     // 初始化
    virtual void shutdown() = 0;       // 关闭
    virtual bool isInitialized() const = 0;
};
```

**设备专用接口（按类型继承）**
- AD/DA采集卡接口：通道配置、采集控制、数据读写
- 总线接口（CAN/429/1553B等）：总线配置、报文收发、状态获取
- VISA仪器接口：SCPI命令交互、数据读写
- IO板卡接口：数字量输入输出、计数器功能

#### 核心组件
- **插件管理器**：统一扫描、加载、管理所有设备插件
- **设备连接池**：管理设备连接生命周期，支持多线程并发访问
- **设备模拟器**：虚拟设备实现，支持离线开发调试

### 2. ICD信号层
#### 核心设计：信号抽象与硬件透明
**信号模型**
```cpp
// 信号元数据
class SignalInfo {
public:
    QString signalId;          // 唯一ID
    QString signalName;        // 名称
    SignalValueType valueType; // 数据类型
    QString unit;              // 工程单位
    double minValue, maxValue; // 量程范围
    double warnLow, warnHigh;  // 告警阈值
};

// 信号实时值
class SignalValue {
public:
    QString signalId;
    QVariant value;            // 工程值
    qint64 timestamp;          // 微秒级时间戳
    bool isValid;              // 有效性
    int quality;               // 数据质量
};
```

**ICD映射模型**
- 信号与硬件通道/数据字段的映射关系
- 支持linear/polynomial/enum/script多种转换方式
- 信号分组管理（按系统、按功能、按设备）

#### 核心组件
- **信号转换引擎**：实现原始值到工程值的双向转换
- **信号总线**：异步发布订阅机制，支持跨模块信号流转
- **ICD编辑器**：可视化编辑信号定义、映射规则、转换参数

### 3. 测试引擎层
#### 核心设计：可视化+脚本双模式支持
**测试用例模型（四级结构）**
```
TestProject（测试项目）
└── TestSuite（测试套件）
    └── TestCase（测试用例）
        ├── setupSteps（前置步骤）
        ├── steps（测试步骤）
        │   ├── Wait/Log/SetVariable（基础操作）
        │   ├── CheckSignal/SetSignal（信号操作）
        │   ├── IfElse/ForLoop/WhileLoop（流程控制）
        │   ├── CallTestCase/RunScript（扩展操作）
        │   └── ParallelExecution（并行执行）
        └── teardownSteps（后置步骤）
```

**执行引擎核心特性**
- 完整流程控制：分支、循环、跳转、异常处理
- 执行控制：暂停/恢复/终止、断点、单步调试
- 并发支持：多用例并行、步骤级并行执行
- 超时处理：步骤级超时配置与异常触发

#### 核心组件
- **表达式求值引擎**：类Python语法，支持算术/比较/逻辑运算与内置函数
- **脚本引擎管理器**：统一封装Python/Lua/JS引擎，提供一致API
- **变量管理系统**：支持全局/套件/局部三级变量，支持信号绑定
- **报告生成器**：支持PDF/HTML/Excel多格式报告导出

### 4. 应用层
采用停靠式模块化布局，核心功能模块：
- **ICD管理模块**：ICD编辑、导入导出、版本管理
- **用例编辑模块**：可视化拖拽编辑 + 脚本编辑双模式
- **测试执行模块**：执行控制、实时监控、状态展示
- **设备管理模块**：设备扫描、配置、状态监控、模拟功能
- **数据可视化模块**：示波器、曲线、仪表盘等数据展示
- **报告管理模块**：报告生成、历史数据查询、结果对比

## 六、验证方案
1. **单元测试**：核心模块（插件管理器、信号总线、表达式引擎）单元测试覆盖率≥80%
2. **集成测试**：端到端测试场景，验证从硬件采集→信号转换→测试执行→结果输出全流程
3. **性能测试**：验证1000+信号并发采集（1ms采样率）、10000+步用例执行的稳定性
4. **兼容性测试**：测试主流厂商板卡和仪器的兼容性

## 七、核心设计优势
1. **高度模块化**：插件化设计，扩展新设备/新功能不需要修改核心代码
2. **硬件透明**：ICD层屏蔽硬件差异，测试逻辑不绑定具体硬件
3. **灵活测试方式**：可视化+脚本混合编辑，兼顾易用性和灵活性
4. **高实时性**：异步信号总线支持1ms级数据采集处理
5. **开放生态**：插件接口完全开放，支持用户自定义扩展
