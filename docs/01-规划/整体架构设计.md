# 整体架构设计

本文档描述仿凯云ETest项目的整体架构设计和技术路线。

## 一、项目目标

开发一个基于Qt、C++的嵌入式测试系统开发环境，实现ETest的核心功能，包括：
- 统一硬件驱动抽象层
- 可视化协议编辑和测试配置
- 多种脚本语言支持（Lua、Python）
- 实时测试执行引擎
- 跨平台支持（Windows、Linux）

## 二、架构设计原则

1. **分层架构**：清晰的功能边界，便于维护和扩展
2. **插件化设计**：核心功能模块化，支持动态加载
3. **跨平台兼容**：代码可移植，支持多种操作系统
4. **实时性保障**：满足嵌入式测试的实时性要求
5. **可扩展性**：易于集成新硬件和新协议

## 三、技术栈选择

### 3.1 核心技术
- **Qt框架**：Qt 5.15 LTS或Qt 6，提供GUI和基础库
- **C++17标准**：现代C++特性，兼顾性能和可维护性
- **CMake构建系统**：跨平台构建支持

### 3.2 第三方依赖
- **Qt Advanced Docking System**：VSCode风格停靠布局
- **QScintilla**：高级文本编辑器，支持语法高亮
- **spdlog**：高性能日志系统
- **gtest/gmock**：单元测试框架
- **Lua**：轻量级脚本语言支持
- **Python**：丰富生态脚本支持

### 3.3 数据库选择
- **SQLite**：轻量级嵌入式数据库
- **二进制文件存储**：原始波形数据存储

## 四、核心模块设计

### 4.1 硬件抽象层（HAL）
- 统一设备接口定义（IBusInterface）
- 多厂商驱动适配框架
- 支持1553B、ARINC429、CAN、FlexRay等总线
- 设备通道管理和状态监控

### 4.2 协议管理系统
- 可视化协议编辑器
- 协议模板定义和解析
- 字段自动匹配和验证
- 协议代码生成

### 4.3 测试执行引擎
- 异步事件循环架构
- 测试脚本调度器
- 实时数据采集和记录
- 结果分析和报告生成

### 4.4 用户界面框架
- 主窗口布局（6区域设计）
- 项目管理界面
- 代码编辑器集成
- 实时监控面板

## 五、开发阶段规划

### 5.1 第一阶段：基础框架（4周）
- 项目搭建和依赖集成
- 核心基础设施开发（日志、配置、异常处理）
- 通用插件框架实现
- 主窗口框架搭建

### 5.2 第二阶段：总线支持（14-18周）
- 1553B总线支持（6周）
- ARINC429总线支持（4周）
- CAN/CAN FD支持（4周）
- FlexRay支持（4周）
- AD/DA/IO支持（4周）

### 5.3 第三阶段：高级功能（14周）
- 协议模板系统（6周）
- 测试引擎开发（6周）
- 完整UI界面开发（8周）

### 5.4 第四阶段：集成优化（4周）
- 系统集成测试
- 性能优化
- 文档编写

**总周期**：约10个月（一人开发，AI辅助）

## 六、关键技术难点

### 6.1 实时性保障
- 使用高优先级线程
- 异步I/O操作
- 避免主循环阻塞
- 精确时间调度

### 6.2 多板卡同步
- IRIG-B时间码同步
- 软件时间戳校正
- 统一时间基准

### 6.3 跨平台兼容
- Windows DLL动态加载
- Linux SO动态加载
- 国产操作系统适配

## 七、代码组织结构

```
src/
├── core/                    # 核心框架
│   ├── base/               # 基础类定义
│   ├── event/              # 事件循环
│   └── thread/             # 线程管理
├── hal/                     # 硬件抽象层
│   ├── interface/          # 接口定义
│   └── drivers/            # 驱动实现
├── protocol/               # 协议处理
│   ├── parser/             # 协议解析
│   ├── template/           # 协议模板
│   └── codec/              # 编解码器
├── engine/                 # 测试引擎
│   ├── executor/           # 执行器
│   ├── scheduler/          # 调度器
│   └── recorder/           # 数据记录
├── ui/                     # 用户界面
│   ├── widgets/            # 自定义组件
│   ├── dialogs/            # 对话框
│   └── mainwindow/         # 主窗口
├── scripting/              # 脚本支持
│   ├── lua/                # Lua集成
│   └── python/             # Python集成
└── main.cpp                # 入口文件
```

## 八、质量保证

### 8.1 代码质量
- 遵循Google C++ Style Guide
- 单元测试覆盖率>80%
- 代码静态分析
- 持续集成

### 8.2 文档要求
- 设计文档及时更新
- API文档完整
- 用户指南详细
- 示例代码丰富

## 九、风险评估

### 9.1 技术风险
- 硬件驱动兼容性问题
- 实时性无法达到要求
- 跨平台适配难度大

### 9.2 缓解措施
- 前期充分调研和原型验证
- 采用成熟的技术方案
- 保持模块间的松耦合

## 十、总结

本项目采用渐进式开发策略，先构建稳定的基础框架，逐步添加总线支持和高级功能。注重代码质量和可维护性，为后续扩展奠定基础。
