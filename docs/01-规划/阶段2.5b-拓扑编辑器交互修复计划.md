# 阶段2.5b — 拓扑编辑器：Item/大纲/属性面板/监听器交互修复

## 背景

拓扑编辑器（阶段2.5已完成7项增强 + Monitor功能）当前存在若干 Bug 和未完成功能，尤其是场景中的图形项（Item）、导航大纲（TopologyOutlineWidget）、属性面板（PropertyPanelWidget）和监听器（Monitor）之间的交互。

## 问题清单

### Bugs

1. **大纲 tap 子节点 ItemTag 错误**
   `TopologyOutlineWidget::addMonitorItem()` 中 tap 子节点用了 `ItemTag::Category`，导致不可点击、不可导航。

2. **放置监听器后不居中**
   `onDropMonitor()` 第714行有 `// TODO: center on the new monitor item` 未实现。

3. **监听器移动无 Undo**
   `TopologyScene::mouseReleaseEvent()` 不为 `MonitorItem` 创建 `MoveMonitorCommand`，移动监听器后无法撤销。

4. **删除连接不清理关联 tap**
   `RemoveConnectionCommand` 只移除连接本身，不级联清除监听器中引用该连接的 `TopologyMonitorTap`，导致脏数据残留在 `mon->taps` 中。

5. **连接删除后 tap 可视化未同步更新**
   由于第4点，`updateTapVisuals()` 中的虚线可能因找不到 `ConnectionItem` 而不显示（隐式修复），但文档中的脏数据仍存在。

### 缺失功能

6. **属性面板无解除挂载 UI**
   `UnTapConnectionCommand` 已存在但无触发入口。属性面板中 taps 表格为 `NoEditTriggers` 只读。

7. **大纲无解除挂载右键菜单**
   同上，无 UI 入口。

8. **大纲重建丢失展开状态**
   `rebuildTree()` 每次完全重建，所有节点折叠。筛选文本也丢失。

9. **复制/粘贴排除监听器**
   `onCopy()` / `onPaste()` 只处理 UutItem 和 DeviceItem，MonitorItem 被跳过。

10. **对齐/分布排除监听器**
    `doAlign()` / `doDistribute()` 只处理 UutItem 和 DeviceItem，MonitorItem 不参与。

## 实施计划

按依赖关系分 6 个批次，每批次执行完立即编译验证。

---

### 批次 A：简单 Bug 修复（低风险）

#### A1. 修复大纲 tap 子节点 ItemTag

**背景：** 大纲中 Monitor 的 tap 子项使用 `ItemTag::Category`（值 -1），导致 `onTreeItemClicked()` 中判断为类别节点而跳过导航。同时 `setFlags(... & ~Qt::ItemIsSelectable)` 使它们不可点击。

**做法：**
- `TopologyOutlineWidget.h`：`ItemTag` 枚举添加 `Tap = 6`
- `TopologyOutlineWidget.cpp` `addMonitorItem()`：tap 子项 tag 改为 `ItemTag::Tap`，移除 `setFlags` 限制使其可选
- `TopologyEditorWidget.cpp` `onOutlineNavigate()`：添加 `case static_cast<int>(ItemTag::Tap)`，导航到对应 Monitor 并选中

**涉及文件：** `TopologyOutlineWidget.h`、`TopologyOutlineWidget.cpp`、`TopologyEditorWidget.cpp`

#### A2. 放置监听器后居中

**背景：** 拖放 Monitor 后无视觉反馈，用户不知道 Monitor 被放在了哪里。第714行有 TODO 注释。

**做法：**
- `TopologyEditorWidget.cpp` `onDropMonitor()`：替换 TODO 为：
  ```cpp
  if (auto* monItem = scene_->findMonitorItem(cmd->monitorIndex())) {
    monItem->setSelected(true);
    view_->centerOn(monItem);
  }
  ```

**涉及文件：** `TopologyEditorWidget.cpp`

---

### 批次 B：Undo 完整性

#### B1. 添加 MoveMonitorCommand

**背景：** `TopologyScene::mouseReleaseEvent()` 中只有 `UutItem` 和 `DeviceItem` 的移动命令分支，`MonitorItem` 移动后无法撤销。

**做法：**
- `UndoCommands.h`：新增 `MoveMonitorCommand` 类，与 `MoveDeviceCommand` 相同模式
  - 构造函数：`(TopologyDocument* doc, int monitorIndex, const QPointF& oldPos, const QPointF& newPos)`
  - `undo()`：设置 `mon->position = old_pos_`
  - `redo()`：设置 `mon->position = new_pos_`
- `UndoCommands.cpp`：实现上述方法
- `TopologyScene.cpp` `mouseReleaseEvent()`：添加 `MonitorItem` 分支，push `MoveMonitorCommand`

**涉及文件：** `UndoCommands.h`、`UndoCommands.cpp`、`TopologyScene.cpp`

#### B2. 删除连接级联清理 tap

**核心问题：** 删除连接时，所有监听器中引用该连接（通过 productName/portName/deviceName/devicePort 匹配）的 tap 应被自动清理。

**做法：**
- `UndoCommands.h` `RemoveConnectionCommand`：添加 `struct SavedTap { int monitorIndex; TopologyMonitorTap tap; };` 和 `QVector<SavedTap> saved_taps_`
- `UndoCommands.cpp` `RemoveConnectionCommand` 构造函数：
  - 扫描所有 monitor 的 taps，找到端点与 `conn_` 匹配的 tap，保存到 `saved_taps_`
- `redo()`：先执行 `for (auto& st : saved_taps_)` 从文档中移除 tap，再 `doc_->removeConnection(index_)`
- `undo()`：先 `doc_->addConnection(conn_)`，再 `for (auto& st : saved_taps_)` 恢复 tap

**涉及文件：** `UndoCommands.h`、`UndoCommands.cpp`

---

### 批次 C：解除挂载 UI

#### C1. 属性面板 tap 右键菜单

**背景：** 属性面板 Monitor 页面的 taps 表格是只读的，用户无法从属性面板解除挂载。

**做法：**
- `PropertyPanelWidget.h`：添加 `void onTapTableContextMenu(const QPoint& pos)` 槽
- `PropertyPanelWidget.cpp` `buildMonitorPage()`：
  - 设置 `setContextMenuPolicy(Qt::CustomContextMenu)`，连接 `customContextMenuRequested`
- `onTapTableContextMenu()` 实现：
  - 获取当前行 row（无选中行则不操作）
  - 弹出 QMenu，添加"解除挂载" action
  - 触发时 push `new UnTapConnectionCommand(doc_, editing_monitor_index_, row)`

**涉及文件：** `PropertyPanelWidget.h`、`PropertyPanelWidget.cpp`

#### C2. 大纲 tap 右键菜单

**做法：**
- `TopologyOutlineWidget.h`：
  - 添加信号 `void unmountRequested(int monitorIndex, int tapIndex)`
  - 添加 `void onTreeContextMenu(const QPoint& pos)` 槽
- `TopologyOutlineWidget.cpp`：
  - 构造函数：设置 `setContextMenuPolicy(Qt::CustomContextMenu)`，连接信号
  - `onTreeContextMenu()`：
    - 获取点击位置的 item，判断 tag 是否为 `ItemTag::Tap`
    - 弹出 QMenu，添加"解除挂载" action
    - 触发时 emit `unmountRequested(mainIdx, subIdx)`
- `TopologyEditorWidget.cpp` `initSignals()`：
  - 连接 `unmountRequested` → `doc_->undoStack()->push(new UnTapConnectionCommand(...))`

**涉及文件：** `TopologyOutlineWidget.h`、`TopologyOutlineWidget.cpp`、`TopologyEditorWidget.cpp`

---

### 批次 D：大纲展开状态

**做法：**
- `TopologyOutlineWidget.h`：添加 `QSet<QString> expanded_keys_` 成员 + `saveExpandedState()` / `restoreExpandedState()` 方法
- `TopologyOutlineWidget.cpp` `rebuildTree()`：
  - `tree_->clear()` 前：递归遍历所有可见项，用 `"catIdx/mainIdx/subIdx"` 键路径保存展开状态
  - 重建后：遍历恢复展开状态
  - 若 `expanded_keys_` 为空（首次加载），则 `expandAll()`

**键路径示例：** `"2/0"` = Connections 类别下第一个连接，`"0/1/2"` = UUTs 类别下第二个 UUT 的第三个端口

**涉及文件：** `TopologyOutlineWidget.h`、`TopologyOutlineWidget.cpp`

---

### 批次 E：复制/粘贴监听器

**做法：**
- `TopologyEditorWidget.cpp` `onCopy()`：
  - 在产品和设备序列化后，遍历选中项中的 `MonitorItem`
  - 序列化 `name`、`deviceType`、`positionX/Y`、`taps[]` 数组到 JSON
  - 写入 `root["monitors"]`
- `onPaste()`：
  - 读取 `root["monitors"]` 数组
  - 对每个 monitor，名称冲突时追加 `_copyN` 后缀
  - push `AddMonitorCommand`
  - tap 数据通过端点名称引用，与文档中已有或后续粘贴的连接匹配

**涉及文件：** `TopologyEditorWidget.cpp`

---

### 批次 F：对齐/分布监听器

**做法：**
- `TopologyEditorWidget.cpp`：
  - `updateAlignDistributeActions()`：计数条件中添加 `MonitorItem`
  - `doAlign()` / `doDistribute()` 收集阶段：添加 `MonitorItem` 条目
  - 命令创建阶段：Monitor 条目使用 `MoveMonitorCommand`
  - 用 `ItemKind` 枚举（`Product`/`Device`/`Monitor`）替代 `isProduct` bool 简化识别

**涉及文件：** `TopologyEditorWidget.cpp`
