# 项目结构树设计

## 问题

当前 FileExplorerWidget 使用 `QFileSystemModel` 直接展示项目目录的原始文件系统树，类似 VSCode 的文件资源管理器。但本系统是面向测试任务的 IDE，用户的操作对象是"协议""拓扑""用例"等**领域概念**，而非通用文件。

目标：将文件资源管理器改造为**按领域分类的项目结构树**，成为用户浏览和管理项目资产的统一入口。

## 设计原则

1. **项目中心**：以项目为核心组织测试资产，但**不强制要求**用户必须创建项目才能使用编辑器
2. **双模式设计**：无项目时可独立创建/编辑任何支持格式的文件；有项目时展示领域分类树
3. **领域分类**：文件按领域归类，不暴露原始文件系统结构
4. **双向关联**：项目结构树与领域管理器（协议管理器、拓扑管理器等）共享同一份数据
5. **渐进增强**：先实现基础浏览和文件操作，后续再叠加高级功能

## 双模式设计

系统在两种模式下工作：

| 特性 | 无项目模式 | 有项目模式 |
|------|-----------|-----------|
| 项目结构树 | 显示欢迎/快捷操作 | 显示领域分类树 |
| 文件操作 | 通过 Ribbon 菜单新建/打开 | 项目结构树 + Ribbon 菜单 |
| 编辑器 | 所有编辑器可用 | 所有编辑器可用 |
| 拓扑/协议/用例面板 | 显示"请打开项目"引导 | 正常工作 |
| 搜索 | 文件系统级搜索 | 项目范围搜索 |
| 运行调试 | ❌ 不可用 | ✅ 可用 |
| 版本管理 | ❌ 不可用 | ✅ 可用 |
| 报告 | ❌ 不可用 | ✅ 可用 |

切换流程：

```
启动 → 无项目模式
  ├─ 新建文件（Ribbon → 新建 → 协议/拓扑/用例/文本）
  ├─ 打开文件（Ctrl+O）
  ├─ 有最近文件 → 从 Welcome 页或 Ribbon 打开
  └─ 新建/打开项目 → 切换到有项目模式

有项目模式
  ├─ 领域分类树展示
  ├─ 文件操作通过树视图
  └─ 关闭项目 → 回到无项目模式
```

## 项目目录结构

ProjectManager 创建项目时生成以下标准子目录：

| 目录 | 领域分类 | 文件类型 |
|------|----------|----------|
| `protocol/` | 协议 | `.eproto` |
| `topology/` | 拓扑 | `.etopo` |
| `cases/` | 测试用例 | `.tcase` |
| `scripts/` | 脚本 | `.lua` |
| `reports/` | 报告 | `.pdf` `.xlsx` `.html` `.txt` `.csv` |
| `config/` | 配置 | `.json` `.xml` `.ini` |
| `backup/` | 备份 | 各类文件 |

项目根目录下的杂项文件归入"其他文件"分类。

非标准子目录（用户自行创建）及其内部的目录树在"其他文件"分类下递归展开显示，子目录可折叠。

### 规则

- 每个领域分类节点**始终显示**（即使数量为 0），保证用户知道项目有哪些资产类型
- 括号内数字为该分类下的文件数量
- 只显示文件，不显示分类目录本身（即不显示 `protocol/` 这个目录条目，直接显示其下的 `.eproto` 文件）
- 文件名完整显示（含扩展名）
- 双击文件 → 打开对应编辑器
- 可折叠/展开分类节点

## 组件设计

### 类名：ProjectStructureWidget

**继承关系**：`QWidget`，不继承 `FileExplorerWidget`，从零新建。

**文件**：新建 `src/app/ProjectStructureWidget.h`、`src/app/ProjectStructureWidget.cpp`

### 核心结构

```
ProjectStructureWidget
├── 无项目模式: QWidget 占位（欢迎/快捷操作）
├── 有项目模式: QTreeView (树视图)
│   └── QStandardItemModel
│       ├── RootItem ("项目名称")
│       │   ├── CategoryItem ("协议")
│       │   │   ├── FileItem (can_bus.eproto)
│       │   │   └── FileItem (arinc429.eproto)
│       │   ├── CategoryItem ("拓扑")
│       │   │   └── FileItem (test_rig.etopo)
│       │   ├── ...
│       │   └── CategoryItem ("其他文件")
│       │       └── FileItem (...)
│       └── QFileSystemWatcher (文件监视)
└── QStackedWidget 切换两种模式
```

### 双模式行为

Widget 内部使用 `QStackedWidget` 容纳两种视图：

**模式 0 — 无项目**（index 0）：
- 显示提示信息："没有打开的项目"
- 提供快捷按钮：新建协议、新建拓扑、新建用例、新建脚本
- 这些按钮触发 Ribbon 相同的"新建"操作，但弹出文件保存对话框让用户选择保存位置
- 默认保存路径：从 `ConfigManager` 读取上次使用路径，回退到 `%USERPROFILE%/Documents/`，用户确认后记住路径

**模式 1 — 有项目**（index 1）：
- 显示完整的领域分类树视图
- 通过 `setProjectPath()` 切换到此模式
- 通过 `clear()` 切回到无项目模式

### 数据模型

使用 `QStandardItemModel`（而非自定义 `QAbstractItemModel`），开箱即用的树模型，减少模板代码。

节点结构通过 `QStandardItem` 的 role 数据区分类型：

```cpp
// 自定义 role 常量（Qt::UserRole + 偏移）
enum ProjectNodeRole {
    NodeTypeRole = Qt::UserRole + 1,  // "root" | "category" | "file"
    RelativePathRole,                  // 相对于项目根目录的路径
    CategoryIdRole,                    // category 的标识（如 "protocol"）
};

struct CategoryInfo {
    QString id;          // 目录名，如 "protocol"
    QString displayName; // 显示名，如 "协议"
    QString dirPath;     // 相对于项目根的实际路径
};
```

### 数据加载流程

**进入项目模式（无项目 → 有项目）：**

```
ProjectManager::projectOpened(path)
  → ProjectStructureWidget::setProjectPath(path)
    → QStackedWidget 切换到模式 1 (树视图)
    → loadFromDirectory(path)
      → 扫描项目根目录下的标准子目录
      → 为每个非空标准目录创建 QStandardItem(Category) + 子 Item(File)
      → 为空的标准目录创建 QStandardItem(Category) (count: 0)
      → 扫描根目录杂项文件，创建 "其他文件" CategoryItem
      → 设置 QFileSystemWatcher 监视各子目录
```

**回到无项目模式：**

```
ProjectManager::projectClosed()
  → ProjectStructureWidget::clear()
    → QStackedWidget 切换到模式 0 (无项目占位)
    → 清空 QStandardItemModel
    → 移除 QFileSystemWatcher
```

### 文件监视

使用 `QFileSystemWatcher` 监视所有标准子目录。当检测到文件变化时：

```
QFileSystemWatcher::directoryChanged(path)
  → 延迟 200ms 后调用 refreshCategory(path)
    → 重新扫描该目录
    → 计算差异（新增/删除的文件）
    → 增量更新模型
```

延迟 200ms 是为了避免短时间内多次触发刷新（例如批量创建文件）。

## 文件操作

### 新建文件

右键菜单在分类节点上提供领域感知的"新建"操作：

| 分类 | 菜单项 | 创建的文件类型 |
|------|--------|---------------|
| 协议 | 新建协议文件 | 空的 `.eproto` 文件 |
| 拓扑 | 新建拓扑文件 | 空的 `.etopo` 文件 |
| 测试用例 | 新建测试用例 | 空的 `.tcase` 文件 |
| 脚本 | 新建脚本 | 空的 `.lua` 文件 |
| 报告 | （不可新建，由运行产生） | — |
| 配置 | 新建配置文件 | 空的 `.json` 文件 |
| 备份 | （不可新建，由备份产生） | — |
| 其他文件 | 新建文件 / 新建文件夹 | 用户指定 |

**命名规则**："新建协议" → `新建协议.eproto`（与 Windows 资源管理器的"新建文件夹"行为一致，自动递增）。

**新建后行为**：
- **领域文件**（协议/拓扑/用例/脚本）：新建后**自动打开对应编辑器**（用户意图明确）
- **普通文件**（在"其他文件"分类下新建）：进入行内重命名模式（当前 FileExplorerWidget 行为）

### 删除文件

- 删除文件 → 物理删除，同时通知 `EditorManager` 关闭已打开的编辑器
- 禁止删除标准子目录本身（`protocol/` 目录不可删，但其中的文件可删）

### 重命名

- 文件名支持重命名
- 禁止重命名分类节点

### 外部变化

如果用户在外部（Explorer、Git 检出等）增删了文件，`QFileSystemWatcher` 触发自动刷新。

### 领域管理器联动

项目结构树中的文件操作需要同步到各领域管理器（`ProtocolManagerWidget`、`TopologyManagerWidget`、`TestProgramManagerWidget`）。

**机制**：ProjectStructureWidget 在文件创建/删除后发出信号，MainWindow 根据文件扩展名路由到对应管理器的 `refreshList()`：

```
ProjectStructureWidget::fileCreated(path)
  → MainWindow lambda
    → .eproto: protocol_mgr_->refreshList()
    → .etopo:  topology_mgr_->refreshList()
    → .tcase:  tp_mgr_->refreshList()

ProjectStructureWidget::fileDeleted(path)
  → 同上
```

ProjectStructureWidget 不需要感知谁在监听，各管理器也不需要知道文件变化来源。

## 与现有组件的关系

### FileExplorerWidget

**移除**，由 `ProjectStructureWidget` 完全替代。项目结构树统一接管侧边栏"项目概览"页面的位置。

`FileExplorerWidget.h/.cpp` 及仅被其引用的 `FileTypeIconProvider.h/.cpp` 从源码中删除。现有 `FileExplorerWidget` 的信号连接由 `ProjectStructureWidget` 的新信号替代。

### ActivityBar ↔ Sidebar 解耦：字符串 ID 关联

**问题**：当前通过 `int index` 关联活动栏按钮和侧边栏页面。调整按钮顺序或增删页面时，MainWindow、ActivityBarWidget、SidebarWidget 三处都要改。

**改造方案**：用字符串 ID 替代数字索引。

    constexpr auto kRun             = "run";
    constexpr auto kReport          = "report";
    constexpr auto kSearch          = "search";
    constexpr auto kGit             = "git";
    constexpr auto kSettings        = "settings";

## 边界情况

| 场景 | 处理 |
|------|------|
| 空项目 | 各分类节点显示 (0)，树不报错 |
| 标准目录不存在 | 分类节点**始终显示**，文件名灰色 + 括号标注（目录缺失），右键新建时自动重建目录 |
| 标准目录中有不支持的文件类型 | 仍显示，归入该分类 |
| 文件数量极多（数百个） | 分类节点默认折叠，减少首次渲染压力 |
| 文件名超长 | 只显示文件名，不显示路径；超长时...截断 |
| 外部文件变化 | QFileSystemWatcher 延迟 200ms 刷新 |
| 非 ASCII 文件名 | QString 天然支持 Unicode，正常显示 |
| 文件被外部删除后双击打开 | EditorManager 处理文件不存在的错误提示 |

2. 手动测试流程：

   **无项目模式：**
   - 启动程序 → 无项目时显示占位视图（提示 + 快捷操作按钮）
   - 点击"新建协议"→ 弹出文件保存对话框 → 选择位置 → 创建空 `.eproto` 文件 → 打开协议编辑器
   - Ctrl+O → 选择任意支持的文件 → 打开对应编辑器
   - Ribbon 的"新建"菜单 → 所有类型可用

   **有项目模式：**
   - 新建项目 → 树展开，显示各分类节点（数量为 0）
   - 在分类节点右键 → 新建协议/拓扑/用例等文件
   - 在文件中右键 → 重命名/删除
   - 双击文件 → 打开对应编辑器
   - 在外部文件管理器增删文件 → 回到程序，树自动刷新
   - 关闭项目 → 回到无项目模式
