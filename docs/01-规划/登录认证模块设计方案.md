# 登录认证模块设计方案

## 参考来源

eph213 项目的登录/权限管理代码（`login_dialog.h/cpp/ui`、`add_edit_user_dialog.h/cpp/ui`、`data_def.h/cpp`）。

## 整体架构

```
src/core/auth/                     ← 纯数据层，无 Qt Widgets 依赖
├── AuthTypes.h                    User / UserRole / Permission 常量
├── PasswordHasher.h /.cpp         抽象基类 + 工厂方法

src/app/resources/icons/svg/
├── account_dark.svg               用户图标（Google 2026 风格）
├── account_light.svg
```

## 核心设计

### 密码安全

初版用 `PlainTextHasher`。预留 `Sha256Hasher` 接口和 `MigratingHasher` 迁移机制，后续通过配置切换。

```cpp
class PasswordHasher {
 public:
  virtual ~PasswordHasher() = default;
  virtual QString hash(const QString& password) const = 0;
  virtual bool verify(const QString& password, const QString& stored) const = 0;
};

class PlainTextHasher : public PasswordHasher { ... };  // 初版
class Sha256Hasher    : public PasswordHasher { ... };  // 后期切换
```

### 数据存储

- 独立 JSON 文件：`AppDataLocation/users.json`
- 不走 ConfigManager（INI 不适合存数组结构）
- JSON 内容当前为明文（base64 编码），后续可升级为加密存储

### 权限模型

```cpp
// AuthTypes.h
enum class UserRole { Admin = 0, User };

// 权限用字符串常量
inline constexpr const char* PERM_USER_MANAGE  = "user.manage";

// AuthService 内部 hardcode role→permissions 映射
// 后期可改成配置或数据库驱动
```

### AuthService 单例

```cpp
class AuthService : public QObject {
  Q_OBJECT
 public:
  static AuthService& instance();

  bool login(const QString& username, const QString& password);
  void logout();
  bool isLoggedIn() const;
  User currentUser() const;
  bool hasPermission(const QString& permission) const;

 signals:
  void loginSucceeded(const User& user);
  void loginFailed(const QString& reason);
  void loggedOut();
};
```

登录状态**纯内存**，不持久化。每次重启需重新登录。

## UI 交互

### LoginDialog

| 属性 | 值 |
|------|-----|
| 基类 | AnimationDialog（frameless + fly-in 动画） |
| 呈现方式 | 非模态 `show()` + `loginSucceeded`/`loginFailed` 信号 |
| 布局 | 全屏遮罩 + 居中卡片，卡片内双栏：左侧蓝色渐变品牌区，右侧表单 |
| 要素 | 用户名输入框、密码输入框、登录按钮、错误提示 Label |
| 交互 | Enter 键触发登录 |

用户点击 QAB 登录按钮 → `LoginDialog::show()` → 用户填写凭据 → 
登录成功：`emit loginSucceeded(user)` → MainWindow 关闭 LoginDialog、更新 QAB 状态
登录失败：`emit loginFailed(reason)` → 显示错误提示

### QuickAccessBar

QAB 布局：`[新建] [打开] [保存] | [撤销] [重做] | [登录]`

**未登录**：显示用户图标，tooltip "登录"，点击弹出 LoginDialog
**已登录 Admin**：显示用户图标 + "admin (Admin)"，点击弹出菜单：[用户管理] [退出登录]
**已登录 User**：显示用户图标 + "zhou (User)"，点击弹出菜单：[退出登录]

所有状态切换由**同一个 QAction** 完成：更新 icon、toolTip、menu。

### UserManagerDialog

| 属性 | 值 |
|------|-----|
| 基类 | AnimationDialog |
| 访问控制 | 仅 Admin 角色可见（QAB 菜单中不出现"用户管理"） |
| 布局 | 标题栏（+ 添加按钮）、用户表格（用户名/角色标签/操作按钮）、提示信息 |
| 行操作 | Admin 用户不可删除。非 Admin 用户可编辑和删除 |
| 添加/编辑 | 弹出子对话框，复用 Mode::Add / Mode::Modify 模式 |
| 密码规则 | 添加/编辑时密码需两次输入确认一致 |

### 功能受限

AuthService 持有登录状态，主窗口 action 在触发前通过 `hasPermission()` 检查。

**初版不做功能限制**，仅用户管理本身受 Admin 权限管控。其他权限点后续扩展。

## QSS 策略

- LoginDialog / UserManagerDialog 样式通过 `setObjectName` 选择器，写在 `default.qss` / `vscode.qss` 中
- 不产生新的 QSS 文件

## 决策记录

| # | 决策 | 结论 |
|---|---|---|
| 1 | 密码策略 | 先 `PlainTextHasher`，留 `Sha256Hasher` + `MigratingHasher` 接口 |
| 2 | 存储格式 | 独立 JSON 文件 |
| 3 | 存储路径 | `AppDataLocation/users.json` |
| 4 | LoginDialog 模态 | 非模态 `show()` + 信号 |
| 5 | 用户管理可见性 | 仅 Admin |
| 6 | QAB 实现 | 单 action 动态切换 |
| 7 | 默认用户 | 仅 `admin/admin123` (Admin) |
| 8 | 登录持久化 | 纯内存 |
| 9 | UserManagerDialog | 列表 + 子对话框 + 删除确认 + 两次密码校验 |
| 10 | LoginDialog 布局 | 全屏浮层 + 双栏卡片 |
| 11 | ActivityBar 用户按钮 | 不要，统一用 QAB |
