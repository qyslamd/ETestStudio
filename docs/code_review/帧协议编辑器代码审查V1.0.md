## 2. 严重问题

### 2.1 帧类型 ComboBox 映射不一致

两个独立 ComboBox 对同一个 `index` 映射到不同 `FrameType`：

| 控件 | index 0 | index 1 | index 2 |
|------|---------|---------|---------|
| 工具栏 `frame_type_combo_` | `cmd` (发送) | `data` (接收) | `data_cmd` (配置) |
| `IcdPropertyPanel::combo_frame_type_` | `data` (数据) | `cmd` (命令) | `data_cmd` (数据/命令) |

**影响**: 用户在工具栏看到帧类型为"接收 (Data)"，在属性面板看到"数据"，两边对不上。代码逻辑也相反——index 0 在工具栏是 `cmd`，在属性面板是 `data`。

**位置**: `ProtocalEditorWidget.cpp:262-265`（创建） vs `ProtocalEditorWidget.cpp:525-529`（映射） vs `IcdPropertyPanel.cpp:164-169`（面板创建） vs `IcdPropertyPanel.cpp:83-97`（面板映射）

### 2.2 Snapshot 全量序列化的撤销/重做

**位置**: `ProtocalEditorWidget.cpp:711-741`

每次 `saveSnapshot()` 将整个 `icd::Repository` 全量 JSON 序列化为 `QByteArray`，undo/redo 时 `restoreSnapshot` 重新解析并重建全部内容。

**问题**:
- 改一个字段名、加一个帧都产生全量副本，大型 ICD 下性能不可接受
- `restoreSnapshot` 始终选择 `repo_.frames()[0]`（第 735 行），undo 后选中帧跳到第一帧，编辑状态丢失
- 撤销历史完全在内存中作为 `QVector<QByteArray>` 保存，数据量线性增长且无上限

### 2.3 异步加载竞态

**位置**: `ProtocalEditorWidget.cpp:141-181`

```cpp
if (load_watcher_) {
    load_watcher_->cancel();
    load_watcher_->deleteLater();
}
```

`cancel()` 不阻止已完成后台任务的 `finished` 信号触发。连续两次 `setEditorId`，旧 watcher 的 finished lambda 可能覆盖新请求加载的数据。

### 2.4 Node/Frame 指针悬空

**位置**: `IcdNodeTreeWidget.cpp:26-33`, `ProtocalEditorWidget.h:93-94`

`IcdNodeTreeWidget` 用 `reinterpret_cast<quintptr>` 将 `icd::Node*` / `icd::Frame*` 存入 `QStandardItem::data(PtrRole)`。当 `ProtocalEditorWidget::repo_` 被重新赋值（加载文件、undo/redo、clearAll），所有旧的指针全部悬空。

**受影响变量**:
- `ProtocalEditorWidget::current_frame_`
- `IcdBitLayoutView::last_frame_`
- `IcdPropertyPanel::current_node_`
- `IcdNodeTreeWidget` 树形视图中的所有指针

## 3. 架构/设计问题

### 3.1 位视图只显示叶子节点

**位置**: `IcdBitLayoutView.cpp:527-536`

```cpp
void IcdBitLayoutView::collectLeafNodes(const icd::Node& node,
                                         QVector<const icd::Node*>& leaves) {
  if (node.children().empty()) {
    leaves.push_back(&node);
  } else {
    for (const auto& child : node.children())
      collectLeafNodes(*child, leaves);
  }
}
```

`loadFromFrame` 只收集叶子节点渲染。如果 ICD 有嵌套层次（如 `header → subfield1, subfield2`），中间节点 `header` 不显示，丢失层级语义。

### 3.2 `valueTypeToString` 重复定义

`IcdNodeTreeWidget.cpp:39-69` 和 `IcdPropertyPanel.cpp:21-38` 有几乎完全相同的 `valueTypeToString` / `valueTypeName` 函数，应抽取为共享工具函数。

### 3.3 `const_cast` 违反 const 安全

**位置**: `ProtocalEditorWidget.cpp:354`

```cpp
property_panel_->showNode(const_cast<icd::Node&>(*node));
```

`IcdPropertyPanel::showNode` 声明为 `icd::Node&`（非 const），但调用方只有 `const icd::Node*`，说明接口设计不当。

### 3.4 帧属性编辑路径割裂

帧的 ID/类型/字节序可以通过工具栏 ComboBox 编辑（`ProtocalEditorWidget.cpp:519-543`），但 `IcdPropertyPanel::showFrame` 中所有帧属性字段都 `setEnabled(false)` / `setReadOnly(true)`。用户必须通过工具栏修改，与属性面板的操作习惯不一致。

### 3.5 `populateFrames + setCurrentFrame` 大量重复

`ProtocalEditorWidget` 中有 9 处出现以下模式：

```cpp
populateFrames();
setCurrentFrame(frame);
```

应抽取为 `void refreshAndSelectFrame(icd::Frame* frame)`。

## 6. 积极评价

- **位布局视图视觉设计出色**：`FieldSectionItem::paint()` 的多色渐变（左侧垂直色条、水平渐变色头、光泽高光、选中高亮边框）质量很高
- **分组语义着色**：根据 `group_name` 或 `tag` 自动映射颜色（header=蓝, payload=绿, checksum=红, length=黄, count=紫, address=青），用户可快速识别字段功能类型
- **UI 布局清晰**：三列 QSplitter（信号树 / 位布局视图 / 属性面板）+ 顶栏帧元数据 + 底部状态栏，信息层级分明
- **主题切换适应**：`IcdBitLayoutView` 和 `IcdPropertyPanel` 监听了 `ThemeManager::themeChanged`，深色/浅色切换后自动刷新
- **属性面板信号管理**：`clearNodeConnections()` + `QVector<QMetaObject::Connection>` 管理动态连接的信号，避免泄漏
- **Loading overlay 可复用**：与 `TopologyEditorWidget` 共用同一样式名 `#PhLoadingOverlay`，便于统一主题
- **帧结构合理性**：`icd::Repository` / `icd::Frame` / `icd::Node` 三层模型清晰，信号/标签/缩放/扩展属性分离

## 7. 总结

| 等级 | 数量 | 关键问题 |
|------|------|----------|
| 严重 | 4 | 帧类型映射不一致；Snapshot 全量序列化 undo；异步加载竞态；Node/Frame 指针悬空 |
| 架构/设计 | 5 | 只渲染叶子节点；`valueTypeToString` 重复；`const_cast`；帧属性编辑路径割裂；重复代码模式 |
| 子模块 | 13 | 树搜索未实现；细粒度信号风暴；`wheel->delta` 废弃；不按偏移排序；`dynamic_cast` 滥用等 |
| 小问题 | 4 | 头文件缺失、`override` 缺失、初始化不一致等 |

**最优先修复的 3 条**:
1. 统一帧类型映射（两个 ComboBox 的 index ↔ `FrameType` 对齐）
2. 将 Snapshot 全量序列化改为增量命令模式（或至少记录选中帧 ID）
3. 解决 `repo_` 重赋值后的指针悬空问题（用 ID 索引替代裸指针）
