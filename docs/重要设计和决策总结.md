## 二、ICD协议

### ICD 可视化核心设计思路

- **状态**：[设计阶段]
- **关联**：无

**关键决策**：
1. 三视图联动（信号树/位布局网格/属性编辑器）作为基本交互范式 -- ICD 数据是位级编码，必须结构/空间/详情三者同步
2. 类型系统只用 byte/word/dword/float/double/string 6 种 -- 以实际 XML Schema 为准，不引入 XML 中不存在的字段
3. Tag 用数值映射（0=none, 1=head, 40=sum/xor, 41=signal_in_value, 60=big_endian_value） -- 对齐实际 XML 数据
4. 文件名即元数据（总线/通道/产品/方向/Label/硬件资源编码在文件名中） -- 帧级属性不在 XML 内
5. 校验内建于编辑流程（位域重叠/帧完整性/Tag 唯一性实时检测） -- 编辑器区别于文本编辑器的核心价值

### icd_utility 彻底融入 etest-demo - 改造计划

- **状态**：[已落地]
- **关联**：无

**关键决策**：
1. icd_utility 作为 `src/` 子目录纳入 CMake 统一管理，移除 standalone 特征 -- 消除独立项目割裂
2. 三方库（pugixml/nlohmann/tl）集中到 `3rdparty/` -- 统一依赖管理
3. 测试迁移到 `tests/icd_utility/` 并改造为 gtest 模式 -- 纳入 `add_etest` 体系
4. 移除 DLL 导出宏定义（ICD_UTILITY_BUILDING_DLL 等），静态编译即可 -- 简化构建配置
5. `src/` 设为 PUBLIC include，确保内部相对路径可解析 -- 兼容 loader.cpp 的 `#include "../format/..."`

### ICD 与协议模块改进计划

- **状态**：[部分落地]（Phase 1-3 已实施，Phase 4-5 待确认）
- **关联**：帧协议编辑器设计、ICD可视化核心设计思路、帧协议解析交互问题

**关键决策**：
1. 引入 `.eprotox` 单文件 XML 格式，与 `.eproto` JSON 共用同一套类型系统（uint8/uint16/int32...） -- 实现完美互转
2. ICDConfig 回写使用 legacy 格式约定（byte/word/dword 类型名、整数 FrameType/ByteOrder/Tag），Tag 映射在序列化层处理 -- 兼容现有 XML 文件
3. Tag 值通过 `tag_to_legacy_int()`/`tag_from_legacy_int()` 查表映射（sum/xor 系列降级为 40） -- 修复 `static_cast<Tag>(40)` 无效枚举值 bug
4. ICDConfig 帧文件统一使用 `.xml` 扩展名，即使 config 本身是 JSON -- 简化文件管理，`serialize_json_frame_file()` 仅用于独立帧导出
5. ICDConfig 识别采用内容检测（前 4096 字节检测 `<ICDConfig>` 根元素）而非文件名匹配 -- 避免误判通用 `.xml`/`.json`
6. ConfigDriven 模式 undo/redo 采用快照+磁盘重建策略（删除旧帧文件->重写所有帧文件->重写 ICDConfig->重建 frame_file_map_） -- 处理文件系统副作用
7. 拼写错误 `scaleConveror`（无 t）作为序列化键名不可"修复" -- 保持与遗留格式兼容

### icd 遗留问题 V1.0

- **状态**：[待确认]（兼容性评估报告，记录问题未修复）
- **关联**：无（隐含关联 IcdSchema.xsd）

**关键决策**：
1. 当前 icd_utility 对 IcdSchema.xsd 仅"部分兼容读取"，写出的 legacy XML 非严格 XSD 有效文档 -- 评估结论定性
2. `DefauleValue`（XSD 原始拼写）完全未建模，parser 不读、serializer 不写 -- 识别为数据丢失风险点
3. `ScaleA/ScaleB/Min/Max` 使用 `std::optional<float>` 而 XSD 是 `xs:double`，存在精度损失 -- 识别为精度降级问题
4. `serialize_xml_frame_file()` 节点字段顺序不符合 XSD 严格 sequence -- 字段顺序不合规
5. `IsScaled` XSD 要求 `xs:int`(0/1)，serializer 当前写出 `true`/`false` -- 类型不匹配

## 三、测试执行引擎

### 硬件接入与测试执行引擎设计

- **状态**：[设计阶段]
- **关联**：硬件接入与测试执行引擎实现计划、测试执行功能重新设计决策记录、UUID实现规划V1.1、测试程序分支循环设计

**关键决策**：
1. 真实硬件驱动也走 Plugin 体系（方案 A） -- 复用已有插件框架，mock 与真实驱动接入路径统一，产线部署仅需替换拓扑文档切换设备
2. 引擎形态为进程内库 + 独立可执行（test-executor GUI / test-executor-cli） -- 同一套 etest_engine 核心同时服务 IDE 调试模式与脱离 IDE 的产线执行
3. 脚本引擎先用 C++ 顺序执行器（非 lua） -- 简化首版实现，14 种测试命令直接 switch 分发，控制流 LOOP/WHILE/IF 递归处理
4. 所有设备类型（AD/DA/Serial/CAN/A429）必经 ICD 编解码 -- 统一信号编解码链路，SignalResolver 查 UUID + ICD Repository 补元数据，SignalCodec 做工程值与原始值/帧字节双向转换
5. etest_engine 不依赖 Qt Widgets（仅 Qt5::Core + spdlog） -- CLI 版可轻量分发（仅几百 KB），核心库可被第三方程序或脚本复用
6. 执行超时从 step.timeoutMs 读取，工作线程用挂 this 的 QTimer + std::atomic<bool> 监测 -- 栈 QTimer 无事件循环永不触发，须挂对象树；超时标志同时响应停止请求

### UUID 实现规划 V1.1

- **状态**：[已落地]
- **关联**：execution-target-display、EtlogViewerWidget实现记录

**关键决策**：
1. UUID 由 (deviceId, portName, frameName, nodePath) 确定性派生（SHA-1 前 32 hex） -- 设备改名不影响 UUID，端口/帧/节点改名失效靠重算工具兜底
2. SignalRegistry 放 etest_core，synchronizeRegistry 桥接放 etest_app -- 跨模块共享且不引入 icd_utility 依赖，保持下层模块纯净
3. IcdSignalSelection 放 etest_app 而非 test_program -- 避免 test_program 反向依赖 icd_utility + etest_app，保护 standalone demo 独立性
4. TopologyDevice 新增持久 id 字段（UUID v4，创建时生成） -- 解决多台同型号设备 UUID 碰撞 + 设备改名失效
5. NodeAttrs::link_to 废弃但代码与格式保留 -- UUID 是其升级，不主动迁移避免破坏老文件

1. 采用容器级统一绘制方案（在 `tabsContainerWidget` 层用统一 painter 遍历所有 tab），弃用 per-tab 自绘 -- per-tab 方案因 `QPainter` 硬裁剪到 `this->rect()` 无法实现 Chrome 标志性的 tab 间熔合效果
2. 通过 `CDockComponentsFactory` 注册自定义 `DockWidgetTabStyle` + `DockAreaTabBarStyle` -- QADS 提供的官方扩展点，避免改源码
3. `DockWidgetTabStyle::paintEvent` 留空，形状由容器统一绘制 -- 子控件（CElidingLabel、关闭按钮）独立收 paintEvent 不受影响
4. 必须同时 `setAttribute(WA_StyledBackground, false)` + QSS `background: transparent` 双保险 -- empty paintEvent 不能阻止 QSS background 绘制
5. `ThemeManager::loadQss()` 末尾需 `emit themeChanged` -- 构造函数首次加载 QSS 后需通知 slot 重新设置 palette/触发重绘

### .etproj root_path 与 recent_files 字段移除方案

- **关联**：无

1. 删除 `root_path` 字段，`rootPath()` 从 `project_file_path_` 推导 -- `.etproj` 永远位于项目根目录内，存储绝对路径是冗余且必然跨平台失效

### Qt 剥离计划 - Phase 1：数据类型本地化

- **状态**：[设计阶段]
- **关联**：无

**关键决策**：
1. Phase 1 只替换数据类型，保留 QObject 继承与信号槽机制不动 -- 控制改动范围，为后续彻底解耦分阶段铺路
2. 信号参数保持 QString 不变，emit 处做 `QString::fromStdString()` 转换 -- 信号签名变更会断裂跨模块的所有 connect 调用方

5. CMake 暂不改，保留 AUTOMOC ON 与 Qt5::Core/Network 链接 -- QObject 继承仍在，需 Phase 2 完成后才能移除

### Linux 平台 CrashHandler 实现方案

- **状态**：[已落地]
- **关联**：linux-build-migration-plan（填补其遗留的阻断点 #6）

**关键决策**：
1. 使用 `sigaltstack` + `SA_ONSTACK` 分配备用栈 -- 栈溢出场景下内核才能在备用栈上调用信号处理器生成日志
2. 采用两级策略：Tier 1 信号安全层（零堆分配）+ Tier 2 富信息层（best-effort） -- 镜像 Windows 的 doCrashHandler + doCrashFallback，保证崩溃日志必定生成
3. 预计算系统/程序信息存入固定 `char[]` 缓冲，信号处理器中只读 -- 避免 std::string 的 SSO/堆分配不确定性
4. 首版不实现 `dladdr` 符号解析，仅用 `backtrace_symbols_fd` 输出原始地址 -- dladdr 持锁可能死锁，事后用 addr2line 解析即可
5. `sigaction` 覆盖 `signal` 注册，LinuxCrashHandler 接管崩溃信号，GlobalExceptionHandler 仅保留 Qt 消息重定向 -- 间接消除现有 signalHandler 中 QString 的 async-signal-safety 违规
