# 调色板监听器入口清理方案

## 问题陈述

当前 `DevicePaletteWidget`（设备调色板）仍然保留着旧 tap 架构下的监听器拖放入口：`addMonitorEntry()` 在列表底部添加一个 "Monitor-4CH (4通道监听器)" 分隔行和拖拽项。该入口在新设计下已无消费路径，属于死代码。

## 现状架构

### 旧设计（已废弃）的监听器创建路径

```
设备调色板 ── 拖放
  DeviceListWidget::startDrag()
    → MIME: {isMonitor: true, deviceType: "Monitor-4CH", channelCount: 4}
    → TopologyScene::dropEvent()
      → obj["isMonitor"] == true
        → emit monitorDropped(scenePos)
          → TopologyEditorWidget::onDropMonitor(pos)
            → new AddMonitorCommand(doc_, mon)
            → 无 connectionId，需要后续手动 tap 连线
```

### 新设计唯一的监听器创建路径

```
右键连线 → TopologyView 上下文菜单
  → emit addMonitorRequested(connItem)
    → TopologyEditorWidget（initSignals lambda）
      → TopologyMonitor mon { connectionId = conn->id, ... }
      → new AddMonitorCommand(doc_, mon)
      → 直接绑定到连线
```

两路完全独立。新路径不依赖调色板，旧路径已无消费者。

### 涉及代码

| 文件 | 旧路径相关代码 |
|------|---------------|
| `DevicePaletteWidget.h` | `MonitorEntry` 结构体，`addMonitorEntry()` 声明 |
| `DevicePaletteWidget.cpp` | `addMonitorEntry()` 函数体，`populateDeviceTypes()` 中第 118-119 行的调用 |
| `DeviceListWidget::startDrag()` | `obj["isMonitor"]` 字段（Monitor 类型永远为 true，Device 类型永远为 false） |
| `TopologyScene.h:71` | `void monitorDropped(const QPointF& scenePos)` 信号 |
| `TopologyScene.cpp:334-335` | `dropEvent()` 中的 `isMonitor` 分支 |
| `TopologyEditorWidget.h:87` | `void onDropMonitor(const QPointF& scenePos)` 声明 |
| `TopologyEditorWidget.cpp:632-635` | `monitorDropped` → `onDropMonitor` 信号连接 |
| `TopologyEditorWidget.cpp:967-983` | `onDropMonitor()` 函数体 |

## 清理方案

### 方案：全链路清理

清理范围包括从调色板入口到场景 drop 事件再到编辑器响应的完整链路，共 6 处改动：

| # | 文件 | 改动 | 理由 |
|---|------|------|------|
| 1 | `DevicePaletteWidget.h` | 移除 `MonitorEntry` 结构体、`addMonitorEntry()` 声明 | 纯监听器入口专用，无其他引用 |
| 2 | `DevicePaletteWidget.cpp` | 移除 `addMonitorEntry()` 函数体、移除 `populateDeviceTypes()` 中第 118-119 行的调用 | 去除死代码 |
| 3 | `DevicePaletteWidget.cpp` `startDrag()` + `populateDeviceTypes()` | 移除第 35 行 `obj["isMonitor"]` 字段；移除第 94 行设备行死赋值 | 不再需要区分 Monitor/Device，`isMonitor` 无消费者 |
| 4 | `TopologyScene.h` + `.cpp` | 移除 `monitorDropped` 信号声明；移除 `dropEvent()` 中第 334-335 行 `isMonitor` 分支 | 不再有 Monitor 拖放 |
| 5 | `TopologyEditorWidget.h` | 移除 `onDropMonitor()` 声明 | 函数体已无调用者 |
| 6 | `TopologyEditorWidget.cpp` | 移除第 632-635 行 `monitorDropped` 信号连接、移除 `onDropMonitor()` 函数体 | 监听器不再从调色板创建 |

### 不清理的内容

| 代码 | 保留理由 |
|------|----------|
| `DeviceListWidget::startDrag()` 整体 | 仍用于设备拖放创建 |
| `kTopologyDeviceMime`（两处） | 设备拖放的 MIME 类型，仍在 Device→Scene 间使用 |
| `TopologyScene::dropEvent()` 整体 | 仍用于设备拖放创建 |
| `TopologyScene::dragEnterEvent/dragMoveEvent` | 仍用于设备拖放预览 |
| `DevicePaletteWidget::populateDeviceTypes()` 整体 | 仍用于设备列表刷新 |
| `DeviceListWidget` 类（包括 `startDrag` 重写） | 仍用于设备拖放数据打包 |
| `TopologyView::addMonitorRequested` 信号及连接 | 右键菜单添加监听器的正式新路径 |

### 影响评估

- **调色板 UI**：不再显示 "─── 监听器 ───" 分隔线和 "Monitor-4CH" 拖拽项，设备列表更简洁
- **场景拖放**：从调色板拖放的条目只有设备类型，`dropEvent()` 不再分支判断 `isMonitor`
- **监听器创建**：唯一入口为右键连线菜单 → 添加监听器，无功能损失
- **前后兼容**：不影响 `.etopo` 文件的读写，不影响现有 Monitor 的序列化/反序列化

## 决策记录

- **决策**：采用全链路清理，而非仅移除调色板条目
- **理由**：`monitorDropped` 信号和 `onDropMonitor()` 已无其他调用方，保留会在后续阅读代码时造成困惑，有违 YAGNI
- **替代方案**：仅在调色板中去掉 `addMonitorEntry()` 调用，保留信号和函数体——优点是改动最小，缺点是遗留死信号/死函数，降低代码可读性
