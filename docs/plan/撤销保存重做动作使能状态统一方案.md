# 撤销/保存/重做动作使能状态统一方案

## 问题陈述

QAB 与编辑分类中的 保存/撤销/重做 三个 action，其使能（enabled）状态由**三条互相竞争、互相覆盖的代码路径**共同维护，导致状态与当前编辑器实际能力不一致：

| 路径 | 位置 | 语义 |
|------|------|------|
| P1 `currentEditorChanged` handler | `MainWindow.cpp:752-849` | 切换编辑器时全量同步，按编辑器类型 dynamic_cast 特判 |
| P2 `EditorManager::modificationChanged` | `MainWindow.cpp:859-860` | 全局信号，**不带编辑器身份** |
| P3 `enable/disableEditActions` | `MainWindow.cpp:2799-2849` | 运行态切换时粗粒度重置 |

### 四个已核实的故障

1. **撤销/重做对 3 类编辑器永久置灰**（P1 else 分支，`MainWindow.cpp:817-823`）
   `currentEditorChanged` 只给 TextEditorWidget（接 `editorStateChanged`）与 TopologyEditorWidget（接 `QUndoStack::indexChanged`）接线；Protocol / TestProgram / RunConfig 三个编辑器**都实现了** `IEditor::canUndo/canRedo/undo/redo`（快照制，已逐一核实：`ProtocolEditorWidget.cpp:250-269`、`TestProgramEditorWidget.cpp:955-987`、`RunConfigEditor.cpp:173-195`），但动态类型不匹配走 else → `setEnabled(false)`。QAB/编辑面板的撤销重做对这三类编辑器永远是灰的。

2. **保存按钮跟踪了错误的编辑器**（P2，`MainWindow.cpp:859-860`）
   `EditorManager::modificationChanged` 由 6 个 binder（`EditorManager.cpp:128,153,172,194,319,361`，含 mockconfig）转发，均不带编辑器身份。后台编辑器 B 变脏 → 触发保存按钮 enable，但当前焦点在干净的 A 上 → 点保存空操作。

3. **运行态切换后状态陈旧**（P3，`enableEditActions` `MainWindow.cpp:2836-2837`）
   退出运行态只按 `hasEditors` 粗粒度恢复撤销/重做；P1 的细粒度 lambda 在 `running_locked_` 期间全部 early-return（`MainWindow.cpp:786,796,810`），退出后不会自动重发 → 撤销/重做停在错误状态直到下一次编辑器事件。启动期初始化块 `MainWindow.cpp:900-901` 同样粗粒度置 `hasEditors`。

4. **根因：IEditor 无统一撤销状态信号，MainWindow 被迫按类型特判**
   `IEditor.h` 只有纯虚 API（canUndo/canRedo/undo/redo），**无任何信号**。各编辑器撤销后端各不相同（QsciScintilla / QUndoStack / 快照列表），状态变化通知方式五花八门（`editorStateChanged`、`QUndoStack::canUndoChanged`、`modificationChanged` 顺带、内部 `updateActions()`），MainWindow 只能 dynamic_cast 逐一特判——else 分支和故障 1/3 由此而来。

**连带发现**：`EditorPanelController::connectCurrentEditor/disconnectCurrentEditor/updateEditorStatus` 及其 `modificationChanged`/`cursorPositionChanged` 信号、`sel_connection_/state_connection_` 成员是**死代码**（全仓无调用，仅作 action 分发器使用）。

## 架构回顾

### IEditor 接口（`src/api/IEditor.h`）

纯虚接口，非 QObject，无信号。提供 `signalObject()` 返回编辑器 QObject。撤销相关仅 `canUndo()/canRedo()/undo()/redo()` 四个可轮询方法。

### 各编辑器状态信号现状（已逐一核实）

| 编辑器 | 撤销后端 | 发射 modificationChanged | 撤销状态通知 |
|--------|----------|--------------------------|--------------|
| TextEditorWidget | QsciScintilla | 是（`textChanged`+Qsci 信号） | `editorStateChanged`，挂 `textChanged`（undo/redo 变文本也会触发） |
| TopologyEditorWidget | QUndoStack | 是（`cleanChanged`→`modificationChanged(!clean)`，`.cpp:707-708`） | `QUndoStack::canUndoChanged/canRedoChanged` 只直连自身 toolbar（`.cpp:703-705`），**不向上转发** |
| ProtocolEditorWidget | 快照列表 | 是（`setModified` `.cpp:1518-1523`） | 无专有信号；`modificationChanged` lambda 顺带刷新自身 toolbar（`.cpp:1110-1113`） |
| TestProgramEditorWidget | 快照列表 | 是（`setModified` `.cpp:1182-1188`） | 无专有信号；内部 `updateActions()`（`.cpp:1197-1228`） |
| RunConfigEditor | 快照列表 | 是（`markModified`/`restoreSnapshot` `.cpp:712-717,783-788`） | 无专有信号；内部 `updateUndoRedoActions()`（`.cpp:791-798`） |
| MockConfigEditor | 无（恒 false） | 是（`markModified` `.cpp:787-792`） | 无（无撤销） |
| ImageViewerWidget | 无（恒 false） | 否 | 无 |
| EtlogViewerWidget | 无（恒 false） | 否 | 无 |

**关键观察**：
- 无任何编辑器提供统一的撤销状态信号；Topology 的 QUndoStack 信号只喂自身 toolbar。
- 快照制编辑器（Protocol/TestProgram/RunConfig）的 `canUndo/canRedo` 变化点分散在 `saveSnapshot/undo/redo/restoreSnapshot` 多处，各有内部刷新函数。
- `modificationChanged` 存在性不一致（Mock 有，Image/Etlog 无），且快照制编辑器把 "modified" 与 "有撤销历史" 混为一谈（`snapshot_index_ != 0`）。

### EditorManager 中继现状（`src/app/EditorManager.h/.cpp`）

- signals：`currentEditorChanged(IEditor*)`、`unsavedChangesChanged()`、`modificationChanged(bool)`（**无身份**）、`fileOpened/fileClosed`。
- 6 个编辑器 binder（text/topology/protocol/testprogram/runconfig/mockconfig）在 `registerEditorTypes` 中永久连接各编辑器 `modificationChanged` → `emit mgr->modificationChanged(modified)` 并更新 dock 标题。
- `modificationChanged` 全仓仅 `MainWindow.cpp:859` 一处消费（tools 独立程序连的是编辑器自身信号，不受影响）——改签名影响面已核实可控。

### MainWindow 现有接线（`MainWindow.cpp`）

- `currentEditorChanged`（752-849）：dynamic_cast 特判 TextEditor（`editorStateChanged`）/ Topology（`undoStack::indexChanged`）/ else 禁用；另有 Qsci `selectionChanged` 用于 cut/copy（783-791）。
- `modificationChanged`（859-860）：`save_action_->setEnabled(modified)`，无身份过滤。
- `enable/disableEditActions`（2799-2849）：运行态锁（engineStateChanged 339-351 驱动 `running_locked_`）粗粒度重置。
- 启动初始化块（886-905）：粗粒度置 `hasEditors`。

### EditorPanelController（`src/app/EditorPanelController.cpp`）

仅作 action 分发器（saveCurrent/undo/redo/cut/... 委托 `editor_mgr_->currentEditor()`）。`connectCurrentEditor/updateEditorStatus/modificationChanged/cursorPositionChanged/sel_connection_/state_connection_` 全部死代码。

## 方案设计

**核心思路**：新增统一 `undoStateChanged()` 信号，各编辑器在 canUndo/canRedo 可能变化处发射；`EditorManager` 作为唯一中继，所有编辑器状态信号**携带编辑器身份**上行；`MainWindow` 只依赖 EditorManager 信号，删除一切 dynamic_cast 特判与粗粒度重置，统一走一个 `syncEditorActions()`。

### 1. 各编辑器新增统一 `undoStateChanged()` 信号

无参数通知式信号（MainWindow 收到后轮询 `canUndo()/canRedo()`，IEditor 已提供）。在各编辑器 `signals:` 块新增，并在撤销状态可能变化处发射：

| 编辑器 | 发射点 |
|--------|--------|
| TextEditorWidget | 在 `editorStateChanged` 触发处（`textChanged` lambda `.cpp:55-56`）同步 `emit undoStateChanged()` |
| TopologyEditorWidget | 新增两行：`connect(undoStack, &QUndoStack::canUndoChanged, this, [this](bool){ emit undoStateChanged(); });` 同 canRedoChanged（`.cpp:703-705` 旁） |
| ProtocolEditorWidget | 在 `undo()/redo()/saveSnapshot()` 状态变更后**无条件** `emit undoStateChanged()`（`.cpp:256-269`、`saveSnapshot` 截断 redo 历史处）。**不要**挂在 `modificationChanged` lambda 上——该信号受 `setModified` 的 `modified_ != modified` 守卫门控，脏→脏 undo 不发射 |
| TestProgramEditorWidget | `updateActions()`（`.cpp:1197-1228`）末尾 `emit undoStateChanged()` |
| RunConfigEditor | `updateUndoRedoActions()`（`.cpp:791-798`）末尾 `emit undoStateChanged()` |
| Mock/Image/Etlog | 不发射（canUndo/canRedo 恒 false；MainWindow 切换时读一次即为灰） |

> 信号命名统一 `undoStateChanged()`，语义"撤销/重做可用性可能已变化，请重新询问 canUndo/canRedo"。

### 2. EditorManager 中继带身份

- 信号签名变更：`modificationChanged(bool)` → `modificationChanged(IEditor* editor, bool modified)`。
- 新增信号：`undoStateChanged(IEditor* editor)`。
- **6 个 binder**（含 mockconfig）统一：`emit mgr->modificationChanged(modified)` → `emit mgr->modificationChanged(editor, modified)`；其中 **5 个支持撤销的编辑器**（text/topology/protocol/testprogram/runconfig，不含 mockconfig）额外新增 `connect(<editor>, &<Type>::undoStateChanged, mgr, [editor, mgr]() { emit mgr->undoStateChanged(editor); })`。

### 3. MainWindow 统一消费

**新增 `syncEditorActions()` 私有方法**：按当前编辑器读取一次真实状态并落盘三个 action：

```cpp
void MainWindow::syncEditorActions() {
  IEditor* editor = editor_manager_ ? editor_manager_->currentEditor() : nullptr;
  save_action_->setEnabled(editor && editor->isModified());
  edit_undo_action_->setEnabled(editor && editor->canUndo());
  edit_redo_action_->setEnabled(editor && editor->canRedo());
}
```

**改造 `currentEditorChanged` handler（752-849）**：
- 删除撤销/重做相关的 dynamic_cast 分支（772-824 的 `editorStateChanged`/`undoStack::indexChanged`/else 禁用），改为无条件调 `syncEditorActions()`。
- 保留 Qsci `selectionChanged` 连接（783-791，cut/copy 专用）与状态栏、save_as/close 等非目标 action 逻辑。
- 删除 `current_editor_state_connection_` 成员及对应 disconnect/connect（MainWindow.h:249）。

**新增两个中继连接**（替代 859-860）：

```cpp
connect(editor_manager_, &EditorManager::modificationChanged, this,
        [this](IEditor* editor, bool modified) {
          if (running_locked_) return;
          if (editor == editor_manager_->currentEditor())
            save_action_->setEnabled(modified);
        });
connect(editor_manager_, &EditorManager::undoStateChanged, this,
        [this](IEditor* editor) {
          if (running_locked_) return;
          if (editor == editor_manager_->currentEditor()) {
            edit_undo_action_->setEnabled(editor->canUndo());
            edit_redo_action_->setEnabled(editor->canRedo());
          }
        });
```

**`enableEditActions`（2823-2848）**：撤销/重做两行（2836-2837）与保存（2827）改为调用 `syncEditorActions()`；其余 action 逻辑不变。`disableEditActions` 不变。

**启动初始化块（886-905）**：保存/撤销/重做三处（897-901）改用 `syncEditorActions()`。

**`running_locked_` 语义保留**：运行期间中继 lambda 跳过刷新（与现状一致），退出运行态 `enableEditActions` → `syncEditorActions()` 兜底刷新。

### 4. 死代码清理（顺手，🟡）

`EditorPanelController.h/.cpp` 删除 `connectCurrentEditor`/`disconnectCurrentEditor`/`updateEditorStatus` 及其 `sel_connection_`/`state_connection_` 成员、`modificationChanged` 与 `cursorPositionChanged` 信号（两者均零消费方）。该类退化为纯 action 分发器。

## 风险与缓解

1. **`EditorManager::modificationChanged` 签名变更**：全仓仅 `MainWindow.cpp:859` 一处消费（已 grep 核实），**6 个 binder** emit 同步改即可（mockconfig 不含 undoStateChanged 转发，仅改 modificationChanged 签名）。tools 独立程序连的是编辑器自身信号，不受影响。**影响面可控。**
2. **`undoStateChanged()` 发射点遗漏导致状态不刷新**：每个支持撤销的编辑器的发射点已在上表逐一指定。注意 Protocol 自身 toolbar 的撤销/重做刷新目前挂在受守卫的 `modificationChanged` 上（既存陈旧 bug），**不能以"自身按钮正常"作发射点覆盖的代理**——按上表在状态变更函数内无条件发射后，可顺带修正之。
3. **快照制编辑器 `setModified` 的 `if (modified_ != modified)` 守卫**：`undo` 到另一脏态时不发 modificationChanged，故各快照制编辑器的 `undoStateChanged` 发射点必须放在**状态变更函数内无条件发射**（Protocol 在 `undo/redo/saveSnapshot` 内；TestProgram/RunConfig 在 `updateActions/updateUndoRedoActions` 内），**不经过该守卫、不依赖 modificationChanged**——避免把撤销状态与 modified 耦合，这是引入独立信号的关键理由。顺带修复 Protocol 自身 toolbar 在脏→脏 undo 时撤销/重做陈旧的既存 bug（`updateToolbar` 不刷新 undo 按钮）。
4. **字符串连接 vs 指针连接**：本方案全部使用**指针到成员连接**（各编辑器声明真实信号），无字符串连接，编译期即校验，无拼写静默失败风险。
5. **跨模块改动**：protocol/topology/test_program/runconfig 四个模块各加一个信号与发射，属纯增量（新增信号 + 发射），不改既有行为；模块独立工具（tools/）不受影响（不连该新信号）。
6. **cut/copy 在 `enableEditActions` 保持粗粒度属既存行为**（非本方案引入的回归）：退出运行态后 TextEditor 无选区时 cut/copy 可点但空操作，精确态仍由 Qsci `selectionChanged` 在下次选区变化时修正。本方案不动。

## 决策记录

| # | 决策 | 结论 |
|---|------|------|
| 1 | 撤销状态信号形态 | 无参通知式 `undoStateChanged()`（否决带 bool 状态：IEditor 已有 canUndo/canRedo 可轮询，信号只负责"变了，去问"） |
| 2 | 中继位置 | EditorManager 带身份中继（否决 MainWindow 字符串连接 signalObject：编译期不可校验、MainWindow 与编辑器信号名耦合；否决轮询：反模式） |
| 3 | 身份过滤位置 | MainWindow 中 `editor == currentEditor()`（binder 永久连接，中继信号必然携带任意编辑器身份，消费方按当前编辑器过滤） |
| 4 | 快照制编辑器是否复用 modificationChanged 顺带 | 不复用。`setModified` 有 `modified_ != modified` 守卫，脏态间 undo 不发；且 "modified" 与 "有撤销历史" 概念应分离（QUndoStack 即分开维护），独立信号语义更清晰 |
| 5 | `syncEditorActions()` | 新增单一同步函数，currentEditorChanged / enableEditActions / 启动初始化三处复用（否决各写一份粗粒度逻辑） |
| 6 | EditorPanelController 死代码 | 顺手清理（🟡，不影响三个 action 修复，若担心改动面可延后单独提交） |

## 实施步骤

1. 各编辑器新增 `undoStateChanged()` 信号并按其发射点补 `emit`（Text/Topology/Protocol/TestProgram/RunConfig 五个文件）
2. `EditorManager.h/.cpp`：改 `modificationChanged` 签名、新增 `undoStateChanged`；**6 个 binder** 更新 modificationChanged emit，其中 **5 个支持撤销的编辑器**（不含 mockconfig）额外新增 undoStateChanged 转发连接
3. `MainWindow.h`：删 `current_editor_state_connection_`；新增 `syncEditorActions()` 声明
4. `MainWindow.cpp`：`currentEditorChanged` 改 `syncEditorActions()` 并删撤销特判与连接；新增两个中继连接；`enableEditActions` 与启动初始化块改用 `syncEditorActions()`
5. （🟡）`EditorPanelController.h/.cpp` 删死代码
6. 编译验证（`scripts/build_ninja.bat -t debug -m ETestStudio`）+ 运行冒烟
7. （可选）Subagent 代码审查
