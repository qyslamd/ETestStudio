# 新建项目和新建文档向导设计方案

## 背景

> **用户**：分开说：在没有加载项目的时候新建文件的入口有哪些？你需要看看ribbon的代码，以及 ProjectStructureWidget 以及 WelcomeWidget

> **用户**：这是不是就意味着，在没有打开项目的时候，我不需要wizard？

> **用户**：接下来我和你讨论的东西都需要写入到文档：`docs\plan\新建项目和新建文档向导设计方案.md` 中记录下来。首先，我一开始的想法是让新建文件需要向导，然后你排查过代码，在没有打开项目的时候，完全不需要向导。接着我考虑到，可能新建项目也是需要向导 wizard 的，然后打开项目之后，app\_menu（`src\app\MainWindow.cpp` Line:2275）需要新增一个新建文件的 action（item），它也是一个独立的向导，第一页用于指定要新建的文件类型，选定了文件类型之后，会走到其它具体文件类型的向导去。因此，我觉得对于每一类当前 IDE 中注册的类型都需要一个新建文件的向导。然后在项目树上的右键菜单的新建，也是需要走到对应文件类型的向导中去的。

## 问题陈述

当前新建文件/项目的流程存在以下不足：

1. **无项目时**：`createStandaloneFile()` 仅弹出 `QFileDialog::getSaveFileName`，用户只能选路径和文件名，无法配置文件初始内容或模板。
2. **有项目时**：`createNewFile()` 在对应分类目录下直接创建空文件（或默认模板），文件名自动递增后进入 inline 重命名，无参数收集步骤。
3. **新建项目**：当前无独立向导，直接弹文件夹选择对话框。
4. **入口分散**：快捷按钮、右键菜单、侧边栏管理器各自实现新建逻辑，缺乏统一的向导框架。

## 目标

- 为新建项目提供向导，引导用户完成项目名称、路径、模板等配置。
- 为每类已注册文件类型提供独立的新建文件向导。
- 统一新建文件入口：app\_menu（ribbon 文件菜单）和项目树右键菜单均指向同一套向导。
- 无项目时的新建文件也纳入向导体系（选类型 → 选保存路径 → 配置初始内容）。

## 现状分析

### 新建文件入口

| 入口位置 | 当前行为 | 有项目时 | 无项目时 |
|---|---|---|---|
| ProjectStructureWidget 占位页快捷按钮 | `createNewFile` / `createStandaloneFile` | 在分类目录下创建空文件，inline 重命名 | `QFileDialog::getSaveFileName` |
| ProjectStructureWidget 树右键菜单（空白区） | `createNewFile(QString(), ...)` | 在项目根目录创建 | 同上 |
| ProjectStructureWidget 树右键菜单（分类节点） | `createNewFile(catId, ext, label)` | 在对应分类目录创建 | 同上 |
| Ribbon Application Button 菜单 | 无新建文件 action | — | — |
| 侧边栏 TopologyManagerWidget | `onNewTopology()` | 弹对话框输入名称 → 创建 | 不可见 |
| 侧边栏 TestProgramManagerWidget | `onNewTestProgram()` | 弹对话框输入名称 → 创建 | 不可见 |
| 侧边栏 ProtocolManagerWidget | `onNewIcdConfig()` / `onNewFrame()` | 创建 ICD 配置/帧 | 不可见 |

### 已注册文件类型（来自 `defaultCategories()`）

| 类型 ID | 显示名 | 扩展名 | 新建标签 |
|---|---|---|---|
| protocol | 协议 | .eproto | 新建协议文件 |
| topology | 拓扑 | .etopo | 新建拓扑文件 |
| testprog | 测试程序 | .etprog | 新建测试程序 |
| script | 脚本 | .lua | 新建脚本 |
| config | 配置 | .json | 新建配置文件 |
| run | 运行 | .erun | 新建运行配置 |

## 方案设计

### 整体架构

```
新建入口
├── 新建项目向导 (NewProjectWizard)
└── 新建文件向导
    ├── 类型选择页 (FileTypeSelectionPage)  ← 从 app_menu 进入时展示
    └── 具体类型向导 (各类型独立 Wizard)
        ├── ProtocolFileWizard
        ├── TopologyFileWizard
        ├── TestProgramFileWizard
        ├── ScriptFileWizard
        ├── ConfigFileWizard
        └── RunConfigFileWizard
```

### 向导入口路由

1. **app\_menu "新建文件" action**：弹出 `NewFileWizard`，第一页为 `FileTypeSelectionPage`，用户选择文件类型后跳转到对应类型向导页。
2. **项目树右键菜单（分类节点）**：根据 `catId` 直接跳过类型选择页，进入对应类型向导。
3. **项目树右键菜单（空白区域）**：弹出 `NewFileWizard`，第一页为 `FileTypeSelectionPage`。
4. **无项目时**：同上，但向导中不显示"保存到项目目录"选项，而是显示路径选择器。

### NewProjectWizard

```
Page 1: 项目基本信息
  - 项目名称 (QLineEdit)
  - 项目路径 (QLineEdit + 浏览按钮)
  - 项目描述 (QPlainTextEdit, 可选)

Page 2: 模板选择
  - 模板列表 (QListWidget)
  - 空项目 / 示例项目 等

Page 3: 确认与创建
  - 显示摘要信息
  - 创建按钮
```

### NewFileWizard（通用入口）

```
Page 1: FileTypeSelectionPage (仅从 app_menu / 空白区右键进入时展示)
  - 文件类型网格/列表 (显示已注册类型的图标和名称)
  - 选择后 dynamically 加载对应类型的向导页
```

### 各类型向导页（以 ProtocolFileWizard 为例）

```
Page 1: 文件信息
  - 文件名称 (QLineEdit, 默认基名自动递增)
  - 保存位置:
    - 有项目时: 显示分类目录路径（只读），支持切换到其他分类
    - 无项目时: 显示路径选择器 (QLineEdit + 浏览按钮)
  - 模板选择 (如有): 空白 / 从模板创建

Page 2: 配置选项 (按类型不同)
  - 协议: 选择字节序、默认帧长度等
  - 拓扑: 选择画布尺寸、网格大小等
  - 测试程序: 选择 Setup/Teardown 模板
  - 脚本: 选择脚本模板 (空白 / Lua 示例)
  - 配置: 选择配置格式 (JSON)
  - 运行配置: 选择初始运行参数

Page 3: 确认与创建
  - 显示摘要
  - 创建并打开
```

### 类注册机制

为支持扩展，采用注册表模式：

```cpp
// 向导工厂注册
struct FileWizardInfo {
  QString typeId;           // "protocol", "topology", ...
  QString displayName;      // "协议文件"
  QString iconName;         // 图标名
  std::function<QWizardPage*(bool hasProject, const QString& projectPath)> createPages;
};

class FileWizardRegistry {
public:
  static FileWizardRegistry& instance();
  void registerWizard(const FileWizardInfo& info);
  QStringList registeredTypeIds() const;
  QWizard* createWizard(const QString& typeId, bool hasProject,
                        const QString& projectPath, QWidget* parent = nullptr);
};
```

### 与现有代码的关系

- `createNewFile()` 和 `createStandaloneFile()` 保留作为兼容入口，内部改为调用向导。
- 侧边栏管理器（TopologyManagerWidget 等）的"新建"按钮改为触发对应类型向导。
- 向导完成后发出 `fileCreated(path)` 信号，由 MainWindow 统一处理打开逻辑。
