# 运行全部合并执行与分段报告方案

## 问题陈述

加载 `demo_mock.etproj`（只有 1 个测试程序）后：

- 选中程序点击「运行」-> 正常执行
- 点击「运行全部」-> 运行结果完全不同

## 根因分析

`run()` 与 `runAll()` 对引擎的处理方式不同：

| 入口 | 引擎处理 | 拓扑加载 |
|---|---|---|
| `run()` | `createEngine()` 复用已有引擎 | `syncProjectTopologies` 首次加载，`loadTopology` 正常 |
| `runAll()` | `runNextInQueue()` 每次 `destroyEngine() + createEngine()` | `monitor_manager_` 跨引擎保持，`monitorTree()` 非空 -> 走 mtime 检测 -> mtime 没变 -> **跳过 `loadTopology`** |

新引擎的 `hw_manager_` 没有加载设备、没有构建 MockUUT，运行时硬件操作全部失败/空转，导致结果完全不同。

## 方案概述

将「运行全部」和「运行多选」从「逐程序重建引擎执行」改为「合并所有程序为一个大 ProgramData 一次性执行」：

- **合并运行**：N 个程序的 `cases` 拼接成 1 个 `ProgramData`，用 `run()` 路径执行（不重建引擎）
- **分段报告**：记录每个程序在合并 `ProgramData` 中的 case 范围，`engineFinished` 时按范围切分报告，每个程序保存一个 `.etlog`

```
程序A (cases: [A1, A2])  ─┐
程序B (cases: [B1])       ─┼-> 合并 ProgramData { suiteName:"全部程序", cases:[A1,A2,B1,C1,C2] }
程序C (cases: [C1, C2])   ─┘   run_segments_ = [{A,0,2}, {B,2,1}, {C,3,2}]

引擎执行完毕 -> current_report_["cases"] = [A1, A2, B1, C1, C2]

engineFinished:
  flushMonitorData()  // 一次性 flush，避免清空后分段丢失
  遍历 run_segments_:
    seg{A,0,2} -> 切 cases[0:2] -> 保存 "电压采集_时间戳.etlog"
    seg{B,2,1} -> 切 cases[2:3] -> 保存 "温度采集_时间戳.etlog"
    seg{C,3,2} -> 切 cases[3:5] -> 保存 "通讯测试_时间戳.etlog"
```

## 改动清单

### 1. ResultCollector -- 新增分段导出

**文件**：`src/engine/ResultCollector.h`、`src/engine/ResultCollector.cpp`

新增方法：

```cpp
void saveSegmentToFile(const QString& etlogPath,
                       const QString& suiteName,
                       int startCase,
                       int caseCount);
```

逻辑：

1. 复制 `current_report_` 作为分段报告基础
2. 替换 `suiteName` 为传入的程序名
3. 切分 `cases` 数组，只保留 `[startCase, startCase+caseCount)` 范围
4. 重算 `summary`（算法见下方）
5. `monitor` 数据完整保留（`monitor_data_` 已由外部提前 `setMonitorData` 设置，所有分段共享）
6. 写入文件

#### summary 重算算法

原 `ResultCollector` 中 `step_count_`（totalSteps）和 `errorCount` 在 `onStepFinished` 入口**无条件**递增（含子步骤），而 `cases` JSON 里的 `steps` 数组只存顶层步骤（`onStepFinished` 里 `if (!stepPath.contains('/'))` 过滤）。LOOP/WHILE 子步骤嵌套在 `step["iterations"][*]["subSteps"]`，IF 子步骤嵌套在 `step["branches"]["then"]/["else"]`。

因此重算必须**递归遍历**所有步骤（含子步骤）：

```
// 递归遍历步骤树（顶层 + LOOP/WHILE 迭代子步骤 + IF 分支子步骤）
function traverseSteps(step, fn):
  fn(step)
  if step has "iterations":
    for iter in step["iterations"]:
      for subStep in iter["subSteps"]:
        traverseSteps(subStep, fn)
  if step has "branches":
    for branchKey in ["then", "else"]:
      for subStep in step["branches"][branchKey]:
        traverseSteps(subStep, fn)

totalCases = caseCount
totalSteps = 0
errorCount = 0
passCount  = 0   // 顶层步骤级（与原 suiteFinished 语义一致）
failCount  = 0   // 顶层步骤级

for case in segCases:
  durationMs += case["durationMs"]
  for step in case["steps"]:            // 仅顶层步骤
    if step["status"] == "PASS":
      passCount++
    elif step["status"] in ["FAIL", "TIMEOUT", "ERROR"]:
      failCount++
    traverseSteps(step, fn(s):
      totalSteps++
      if s["status"] == "ERROR":
        errorCount++
    )
```

> **语义说明**：
> - `passCount`/`failCount` 保持**顶层步骤级**统计（与原 `StepRunner::executeProgram` -> `suiteFinished` 信号语义一致），不是 case 级。同一项目的单程序报告和分段报告语义统一。
> - `totalSteps`/`errorCount` 递归遍历**所有步骤（含子步骤）**，与原 `step_count_`/`errorCount` 语义一致。
> - `durationMs` 从原「墙钟时长」改为「分段 case 的 `durationMs` 之和」，反映该程序实际执行时长。这是有意的语义改变。
> - case 状态为 `SKIPPED`/`PENDING` 时，既不计入 `passCount` 也不计入 `failCount`（与原行为一致）。

### 2. TestExecutionEngine -- 新增分段保存入口

**文件**：`src/engine/TestExecutionEngine.h`、`src/engine/TestExecutionEngine.cpp`

#### 2.1 新增 `flushMonitorData()`

```cpp
void flushMonitorData();
```

一次性 flush 监听器数据到 `ResultCollector`，**只调一次**，后续所有分段保存复用这份 `monitor_data_`。

```cpp
void TestExecutionEngine::flushMonitorData() {
  if (collector_ && monitor_manager_) {
    collector_->setMonitorData(monitor_manager_->flushSamples());
  }
}
```

> **不能在 `saveReportSegment` 里调 `flushSamples`**：`flushSamples()` 返回数据的同时清空 `history_buffer_`，第二次调用返回空数组。必须在分段保存前一次性 flush。

#### 2.2 新增 `saveReportSegment()`

```cpp
void saveReportSegment(const QString& etlogPath,
                       const QString& suiteName,
                       int startCase,
                       int caseCount);
```

**不 flush**，直接委托 `ResultCollector::saveSegmentToFile`（依赖外部已调 `flushMonitorData`）。

#### 2.3 `saveReport()` 保持不变

单程序路径仍用原 `saveReport()`（内部自己 flush），不影响 test-executor 等工具。

### 3. ExecutionPanelController -- 合并 + 分段保存

**文件**：`src/app/ExecutionPanelController.h`、`src/app/ExecutionPanelController.cpp`

#### 3.1 新增成员

```cpp
struct ProgramSegment {
  QString name;         // 程序名（报告文件名用）
  int startCaseIndex;   // 合并 ProgramData 中的起始 case 索引
  int caseCount;        // 该程序的 case 数量
};
QList<ProgramSegment> run_segments_;
```

#### 3.2 新增 `mergePrograms()` 方法

```cpp
etest::engine::ProgramData mergePrograms(const QStringList& paths,
                                          const QString& suiteName);
```

逻辑：

1. **首行 `run_segments_.clear()`**（防御连续调用累加）
2. 遍历路径列表，`loadTestProgram` 加载每个程序
3. **跳过 `cases` 为空的程序**（不为其创建 `ProgramSegment`，避免空报告）
4. `loadTestProgram` 失败时 LOG_WARN 跳过，继续合并其余程序
5. `convertProgram` 转换后拼接 `cases` 到合并 `ProgramData`
6. 记录每个程序的 `ProgramSegment`（名称、起始索引、数量）
7. `suiteName` 用传入参数（`runAll` 传 `"全部程序"`，`run` 多选传 `"选中程序"`）

#### 3.3 改 `runAll()`

```cpp
void runAll() {
  // 前提检查（不变）
  // refreshList + allPaths（不变）
  // checkUnsavedAndPrompt（不变）

  // 合并所有程序
  etest::engine::ProgramData merged = mergePrograms(all_paths, QStringLiteral("全部程序"));
  if (merged.cases.isEmpty()) {
    QMessageBox::warning(..., "无可用测试程序");
    return;
  }

  createEngine();
  if (!engine_) return;

  syncProjectTopologies();

  current_program_name_ = QStringLiteral("全部程序");
  engine_->setProgram(merged);

  // 重置统计
  pass_count_ = 0;
  fail_count_ = 0;

  engine_->start();
  // 切页面、编辑器只读等（同 run()）
}
```

#### 3.4 改 `run()` 多选路径

`run()` 中 `paths.size() > 1` 的分支也走合并执行：

```cpp
void run() {
  // 1-3. 不变（popup 获取选中、前提检查、未保存提示）

  // 4. 选中 ≥2 个 -> 合并执行（不再走 runNextInQueue）
  if (paths.size() > 1) {
    etest::engine::ProgramData merged = mergePrograms(paths, QStringLiteral("选中程序"));
    if (merged.cases.isEmpty()) {
      QMessageBox::warning(..., "选中的程序中没有可用测试用例");
      return;
    }
    createEngine();
    if (!engine_) return;
    syncProjectTopologies();
    current_program_name_ = QStringLiteral("选中程序");
    engine_->setProgram(merged);
    pass_count_ = 0;
    fail_count_ = 0;
    engine_->start();
    // 切页面、编辑器只读等
    return;
  }

  // 5. 单程序直接执行（不变）
  // ...
}
```

#### 3.5 改 `engineFinished` lambda（在 `connectEngineSignals` 中）

```cpp
connect(engine_, &TestExecutionEngine::engineFinished, this, [this]() {
  // 恢复编辑器可编辑
  if (editor_mgr_) {
    for (auto* ed : editor_mgr_->allEditors()) {
      ed->setReadOnly(false);
    }
  }

  if (run_segments_.isEmpty()) {
    // 单程序运行：原逻辑（saveReport 内部自己 flush）
    if (current_program_name_.isEmpty()) return;
    saveSingleReport(current_program_name_);
  } else {
    // 合并运行：先一次性 flush monitor 数据，再按程序分段保存
    engine_->flushMonitorData();
    QString timestamp = QDateTime::currentDateTime().toString("yyyyMMdd_HHmmss");
    for (const auto& seg : run_segments_) {
      saveSegmentReport(seg, timestamp);
    }
    run_segments_.clear();
  }
});
```

> `saveSingleReport()` 是对现有内联保存逻辑（构造路径 + `engine_->saveReport(path)`）的抽取，避免重复代码。

#### 3.6 新增 `saveSegmentReport()` 辅助方法

```cpp
void saveSegmentReport(const ProgramSegment& seg, const QString& timestamp);
```

逻辑：

1. 构造路径：`reports/程序名_时间戳.etlog`
2. 调用 `engine_->saveReportSegment(path, seg.name, seg.startCaseIndex, seg.caseCount)`

#### 3.7 `stop()` 替换 `run_queue_` 清理

将 `stop()` 中的 `run_queue_.clear()` **替换**为 `run_segments_.clear()`（`run_queue_` 已删除）：

```cpp
void stop() {
  run_segments_.clear();  // 替换原 run_queue_.clear()
  // ... 原 stop 逻辑 ...
}
```

> `stop()` 清空 `run_segments_` 后，`engineFinished` lambda 走单程序分支，`current_program_name_` 为 "全部程序"/"选中程序"，保存一个合并的不完整报告（与原行为一致：单程序停止也保存不完整报告）。

#### 3.8 删除 `runNextInQueue()`

不再需要队列递归、`engineFinished` lambda#2 推进逻辑、`destroyEngine + createEngine` 循环、`run_queue_` 成员。

## 设计决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| case 名前缀 | 不加 | 报告已按程序分开，不混淆 |
| `runAll` suiteName | `"全部程序"` | 区分单程序与合并运行 |
| `run` 多选 suiteName | `"选中程序"` | 区分用户选中的子集与全部 |
| 分段 suiteName | 各自程序名 | 还原为程序名，报告头清晰 |
| monitor 数据 | `flushMonitorData` 一次性 flush，所有分段共享 | `flushSamples` 会清空缓冲区，不能重复调用；每分段报告附带完整波形上下文 |
| summary | 分段报告里重算（递归遍历 cases/steps 含子步骤） | 各程序独立统计，与原 `step_count_`/`errorCount` 语义一致 |
| passCount/failCount | 顶层步骤级（与原 `suiteFinished` 信号语义一致） | 不改为 case 级，避免单程序报告与分段报告语义不一致 |
| durationMs | 分段 case 的 durationMs 之和（原为墙钟时长） | **语义改变**：反映该程序实际执行时长，非整个套件墙钟时长 |
| 时间戳 | 所有分段报告用同一时间戳 | 同一次运行的结果，时间戳一致 |
| 空程序 | 跳过，不创建分段 | 避免空报告 |
| setup/teardown | 不涉及 | `convertProgram` 当前未转换，不影响 |
| 停止时 | `run_segments_.clear()`，走单程序保存 | 避免对未执行完的 cases 切片越界 |

## 影响分析

### 路径对比

| 路径 | 改动前 | 改动后 |
|---|---|---|
| `run()` 单程序 | `createEngine` -> `syncTopo` -> `start` | 不变 |
| `run()` 多选 | `runNextInQueue` 循环重建引擎（**同样有 BUG**） | `mergePrograms` -> `createEngine` -> `syncTopo` -> `start`（一次跑完） |
| `runAll()` | `runNextInQueue` 循环重建引擎 -> `syncTopo` 跳过 load **BUG** | `mergePrograms` -> `createEngine` -> `syncTopo` -> `start` |
| `stop()` | 清 `run_queue_` | 清 `run_segments_` + 原 `run_queue_` 清理（如有） |

### 副带收益

1. **消除原 bug**：不重建引擎，`syncProjectTopologies` 不再跳过 `loadTopology`
2. **`run()` 多选 bug 同修**：原 `run()` 选中 ≥2 个程序也走 `runNextInQueue`，有同样的引擎重建 bug
3. **性能提升**：硬件/MockUUT 只初始化一次，省去 N 次 `destroyEngine + createEngine`
4. **监听器勾选保持**：不 `clearStructure`，跨程序保持订阅状态
5. **代码简化**：删除 `runNextInQueue` 的队列递归 + `engineFinished` lambda#2 重入风险 + `run_queue_` 成员

## 测试验证

### 正常路径

1. 加载 `demo_mock` 项目，选中程序点击「运行」-> 正常执行（基线）
2. 点击「运行全部」-> 应与步骤 1 结果一致
3. 先点「运行全部」再点「运行」-> 应正常执行
4. 多程序场景：`runAll` 后每个程序各自保存一个 `.etlog`，报告内 `suiteName` 为程序名，`cases` 只含该程序的用例
5. 检查 `reports/` 目录：N 个程序应生成 N 个 `.etlog` 文件，文件名 `程序名_时间戳.etlog`
6. 用 `EtlogViewerWidget` 打开分段报告，确认 case 列表和步骤结果正确
7. 选中 ≥2 个程序点击「运行」-> 合并执行，每个程序分别保存报告

### 边界场景

8. 合并运行中点「停止」-> `run_segments_` 清空，保存一个不完整的合并报告，不越界
9. 程序列表包含空程序（0 cases）-> 跳过空程序，不生成空报告
10. `loadTestProgram` 对某个程序失败 -> LOG_WARN 跳过，继续合并其余程序
11. 连续两次 `runAll` -> `run_segments_` 被正确覆盖（`mergePrograms` 首行 clear）
12. monitor 数据：多程序合并运行后，每个分段报告的 `monitors` 段都有完整波形数据
