# 运行态编辑锁方案

## 问题陈述

测试程序运行期间，不允许编辑任何东西。当前引擎 Running 时，用户仍可通过切换 ribbon tab 回到编辑态页面，对侧边栏、编辑器、dock 等进行交互，可能干扰运行中的引擎与数据采集。

## 架构回顾

### 现有编辑态/运行态切换机制

`MainWindow` 中央使用 `QStackedWidget`（`central_stack_`）承载两页：

| 索引 | 页面 | 内容 |
|------|------|------|
| 0 | `page_editor_widget_` | 活动栏 + 侧边栏 + 编辑器区域（DockManager）+ 底部面板 |
| 1 | `exec_dashboard_page_` | 执行仪表盘 |

切换触发链路（`MainWindow.cpp:1145`）：

```
用户点击 ribbon category tab
  -> SARibbonBar::currentRibbonTabChanged
  -> central_stack_->setCurrentIndex(0 或 1)
  -> QStackedWidget::currentChanged
  -> index==1: disableEditActions()  禁用 13 个编辑 QAction
     index==0: enableEditActions()  恢复编辑 QAction（基于 hasEditors）
```

### 已有的 disableEditActions / enableEditActions

`disableEditActions()`（`MainWindow.cpp:2612`）禁用以下 action：

- 文件：`save_action_` / `save_as_action_` / `save_all_action_` / `close_file_action_` / `close_all_files_action_`
- 编辑：`edit_undo_action_` / `edit_redo_action_` / `edit_cut_action_` / `edit_copy_action_` / `edit_paste_action_` / `edit_find_action_` / `edit_replace_action_` / `edit_go_to_line_action_`
- 注释标注：视图面板操作在运行态保持可用

`enableEditActions()`（`MainWindow.cpp:2633`）根据 `editor_manager_->currentEditor()` 是否非空恢复上述 action。

### 已有的 syncControlStates

`ExecutionPanelController::syncControlStates()`（`ExecutionPanelController.cpp:278`）已处理"执行"category 的 action 状态：

| 引擎状态 | run/run_all | pause | stop | verify | clear_data |
|----------|-------------|-------|------|--------|------------|
| Idle/Finished | checkCanRun/checkCanRunAll | 禁用 | 禁用 | checkCanVerify | 启用 |
| Running | 禁用 | 启用（文本"暂停"） | 启用 | 禁用 | 禁用 |
| Paused | 禁用 | 启用（文本"继续"） | 启用 | 禁用 | 禁用 |
| Error | checkCanRun/checkCanRunAll | 禁用 | 禁用 | checkCanVerify | 启用 |

### ribbon 结构

| category | 内容 |
|----------|------|
| 编辑 | 文件 panel（新建项目/打开项目/打开文件/保存）+ 编辑 panel（undo/redo/cut/copy/paste/find/replace/go_to_line）+ 视图 panel（欢迎页/侧边栏/日志/终端/辅助侧边栏） |
| 执行 | 运行配置 panel（程序选择 popup + 通道选择 + 验证）+ 执行控制 panel（运行/运行全部/暂停/停止/清空数据）+ 统计 panel |
| 工具 | `if (false)` 包裹，实际不创建 |

### 引擎状态信号链路

```
TestExecutionEngine::engineStateChanged
  -> ExecutionPanelController 接收（.cpp:188）
     -> syncControlStates()
     -> emit ExecutionPanelController::engineStateChanged（.cpp:214）
        -> 当前 MainWindow 未接收此信号
```

## 缺口分析

| 编号 | 缺口 | 说明 |
|------|------|------|
| G1 | 触发时机不对 | `disableEditActions` 挂在 `central_stack::currentChanged`，是页面切换驱动而非引擎状态驱动。引擎 Running 时用户点 ribbon "编辑" tab 切回 page 0，`enableEditActions` 被调用，编辑 action 恢复可用 |
| G2 | `page_editor_widget_` 未禁用 | 即使 action 禁用，page 0 的侧边栏树、dock 拖拽、编辑器内容仍可交互 |
| G3 | ribbon tab 未锁定 | 运行时可随意切换到"编辑" tab |
| G4 | `disableEditActions` 漏项 | `new_project_action_` / `open_project_action_` / `open_file_action_` 未禁用 |
| G5 | "执行"category 的 popup / select_channels | `syncControlStates` 未覆盖，运行时仍可操作程序选择与通道选择 |

## 方案选项

### 讨论 1：触发时机完全由引擎状态驱动

**决策**：1B。完全由引擎状态驱动，移除 `currentChanged` 里的 `disableEditActions/enableEditActions` 调用。

**理由**：用户需求是"运行时不允许编辑"，触发条件应是引擎状态而非页面切换。现有 `currentChanged` 里的调用是"切到执行页就禁用编辑快捷键"的另一个需求，与本项目无关，移除。

**引擎状态流转**（`TestExecutionEngine.cpp`）：

| 时机 | 状态 |
|------|------|
| createEngine 后 | Idle（初始） |
| start() | Idle -> Running |
| stop() | 任意 -> Idle（emit engineFinished + engineStateChanged(Idle)） |
| pause() | Running -> Paused |
| resume() | Paused -> Running |
| invoke 失败 | Error |

注：`EngineState::Finished` 从不被设置，`syncControlStates` 里的 `case Finished` 是防御性代码。

**实现**：

信号连接位置：`initSignalsEarly`（此时 `execution_controller_` 已创建）。

`MainWindow` 接收 `ExecutionPanelController::engineStateChanged` 信号：
- Running/Paused -> `running_locked_ = true` + `disableEditActions()` + 侧边栏禁用（见讨论 5 决策 5A）
- Idle/Finished/Error -> `running_locked_ = false` + `enableEditActions()` + 侧边栏恢复（见讨论 5 决策 5A）

`running_locked_` 成员用途：`onEngineStateChanged` 中设置，`currentEditorChanged` 回调及其内部动态连接的 `selectionChanged`/`editorStateChanged` 子 lambda 中读取。这些回调（`MainWindow.cpp:712-800`）会直接设置编辑 action 的 enabled 状态（如 `edit_undo->setEnabled(editor->canUndo())`），若不加判断会覆盖 `disableEditActions` 的结果导致编辑锁失效。

处理方式需区分：
- `selectionChanged`/`editorStateChanged` 子 lambda：开头加 `if (running_locked_) return;`（仅设置 edit action，整体跳过安全）
- `currentEditorChanged` 回调：不能整体 return（需正常执行信号连接管理、status_bar 更新等），改为正常执行后在末尾追加 `if (running_locked_) disableEditActions();` 重新禁用 edit action

`currentChanged` 里的 `disableEditActions/enableEditActions` 移除；`setObjectName("RunningMode")` + QSS 刷新保留不动。

`destroyEngine()` 内部调用 `engine_->stop()`，若引擎非 Idle 会 emit `engineStateChanged(Idle)`，编辑锁随之恢复；engine_ 置空后不会额外 emit。

### 讨论 2：运行时 ribbon tab 不锁定 + 编辑页交互禁用方式

**决策**：tab 不锁定（2B）。运行时间长时可切回编辑页浏览内容。

**编辑页交互禁用方式**：方式 B -- 编辑器设 `setReadOnly(true)` 保持可滚动可选中，侧边栏/dock 等单独处理。

### 方式 B 实现现状

编辑器只读部分**已实现**，无需改动：

- `IEditor::setReadOnly(bool)` 接口已存在（`IEditor.h:32`），默认空实现
- 四个可编辑编辑器均已实现：
  - `TextEditorWidget::setReadOnly` -> `QsciScintilla::setReadOnly`
  - `TopologyEditorWidget::setReadOnly` -> `view_->setInteractive(!readOnly)`
  - `ProtocolEditorWidget::setReadOnly`
  - `TestProgramEditorWidget::setReadOnly` -> 禁用 suite_name_edit / suite_desc_edit / setup_table / teardown_table
- `ImageViewerWidget` / `EtlogViewerWidget` 本身为只读查看器，使用 `IEditor` 默认空实现，无需改动
- `ExecutionPanelController` 已在以下位置调用：
  - `run()` 单程序路径（cpp:585）：`ed->setReadOnly(true)`
  - `run()` 合并运行路径（cpp:540）：`ed->setReadOnly(true)`
  - `verify()` 路径（cpp:785）：`ed->setReadOnly(true)`
  - `stop()`（cpp:616）：`ed->setReadOnly(false)`
  - `engineFinished` lambda（cpp:255）：`ed->setReadOnly(false)`
  - `destroyEngine()`（cpp:171）：`ed->setReadOnly(false)`

### 讨论 5：侧边栏 / 活动栏 / dock 运行时交互处理

编辑器只读已搞定，剩余的是 `page_editor_widget_` 内非编辑器组件的交互处理：

| 组件 | 现状 | 选项 |
|------|------|------|
| 侧边栏（SidebarWidget）含硬件树/协议树/拓扑管理器/测试程序管理器/搜索/Git | 无 setReadOnly 接口，运行时可点击 | 5A 整体 `setEnabled(false)` 禁用所有交互 / 5B 保持可浏览（展开折叠/滚动），仅禁用触发副作用的操作（如双击打开文件） |
| 活动栏（ActivityBarWidget） | 运行时可切换侧边栏页面 | 5C 禁用 / 5D 保持可用（切换页面本身不干扰引擎） |
| DockManager（ads::CDockManager） | 运行时可拖拽/浮动/关闭 dock | 5E 禁用 dock 拖拽浮动 / 5F 保持可用（布局操作不干扰引擎数据） |
| 底部面板（BottomContainerWidget）含执行输出/终端 | 执行输出运行时应可查看 | 5G 保持可用（需查看运行日志） |

**决策**：

- 侧边栏：5A（整体 `setEnabled(false)`）
- 活动栏：5D（保持可用）
- DockManager：5F（保持可用）
- 底部面板：5G（保持可用）

注：`sidebar_->setEnabled(false)` 禁用侧边栏内部子 widget 交互，但不影响 QSplitter handle -- 用户仍可拖动 handle 调整侧边栏宽度。此行为可接受（拖动无害），不做额外处理。

### 讨论 3：`disableEditActions` 补充范围

**选项**：

| 选项 | 做法 |
|------|------|
| 3A | 补充禁用 `new_project_action_` / `open_project_action_` / `open_file_action_`。视图开关（侧边栏/日志/终端/辅助侧边栏）保持可用 |
| 3B | 在 3A 基础上，视图开关也禁用 |
| 3C | 仅补充文件操作，视图开关保持现状 |

**倾向**：3A。讨论 5 已确认底部面板（含日志/终端）保持可用、dock 保持可用，视图开关保持可用与之一致 -- 运行时用户可能需要调整界面布局以更好地查看运行状态。侧边栏虽已 `setEnabled(false)`，但 `view_sidebar_action_` 控制的是显隐而非交互，保持可用无害。

### 讨论 4："执行"category 的 popup / select_channels

**现状**：`syncControlStates` 未处理 `popup_` 与 `act_select_channels_`。

**选项**：

| 选项 | 做法 |
|------|------|
| 4A | 在 `syncControlStates` 的 Running/Paused 分支补充 `popup_->setEnabled(false)` + `act_select_channels_->setEnabled(false)`，Idle/Finished/Error 分支恢复 |
| 4B | 不在 `syncControlStates` 处理，改在 MainWindow 的引擎状态接收处统一禁用 |

**决策**：4A。`syncControlStates` 已是引擎状态驱动 action 启停的统一入口，popup 与 select_channels 属于执行控制范畴，放这里最合适。

**实现**：`syncControlStates` 各分支补充：
- `!engine_` 分支：`popup_->setEnabled(项目已打开)` + `act_select_channels_->setEnabled(项目已打开)`
- Running/Paused 分支：`popup_->setEnabled(false)` + `act_select_channels_->setEnabled(false)`
- Idle/Finished/Error 分支：`popup_->setEnabled(true)` + `act_select_channels_->setEnabled(true)`

connect(execution_controller_, &ExecutionPanelController::engineStateChanged,
        this, [this](etest::engine::EngineState state) {
          bool locked = (state == etest::engine::EngineState::Running ||
                         state == etest::engine::EngineState::Paused);
          running_locked_ = locked;
          if (locked) {
            disableEditActions();
