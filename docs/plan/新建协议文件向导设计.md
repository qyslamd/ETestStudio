# 新建协议文件向导设计

## 背景

`docs/plan/新建项目和新建文档向导设计方案.md` 规划了新建项目 + 6 类文件向导体系。
新建项目向导、新建测试程序文件向导已打样完成，打样出了通用容器 `BaseWizardDialog`
（QStackedWidget 页面栈 + `WizardStepBar` 步骤条 + 淡入上滑转场 + 页脚导航）、模板卡片
模式 `WizardTemplateCard`、以及 `inject_wizard_qss.py` 幂等 QSS 注入脚本。

本设计针对**协议文件（.eprotox）**向导：完整复刻
`docs/prototype/新建协议文件向导设计.html` 的 4 步 UI，并接入项目树
「协议」分类下的「新建协议文件」入口。

## 问题陈述

1. 当前项目树「新建协议文件」（protocol 分类，extension `eproto`）走
   `ProjectStructureWidget::createNewFile` 的通用 `else` 分支，仅创建一个**空文件**，
   无帧属性 / 字段定义能力。
2. HTML 原型是 4 步向导（模板 / 帧属性 / 字段定义 / 完成），含模板字段预置、
   帧属性表单（帧名称 / 帧 ID / 帧类型 / 字节序 / 帧描述）、字段表格（添加 / 删除 /
   行内编辑，位偏移 / 位宽 / 数据类型 / 系数 / 单位）、摘要字段 tag 展示。
3. 原型的数据模型（HTML JS 对象）与 `icd_utility` 数据模型存在差异，需要映射层
   （见「数据模型差异与决策」）。

## 视觉基准

- 原型：`docs/prototype/新建协议文件向导设计.html`（Fluent 风格，居中卡片布局）。
- Qt Widgets 无法实现 CSS `backdrop-filter` 模糊，以半透明卡片 + 阴影 + 圆角近似
  （与已打样向导一致）。
- 颜色统一走 13 主题 QSS 语义色系统，由脚本注入；禁止 `setStyleSheet` 硬编码。

### 现有图标

已存在（可直接用）：`file_eproto`（协议文件图标）、`protocol`（协议）、`pencil`（自定义模板）、
`chevron_left`/`chevron_right`、`close`、`clear`、`plus`→无、`trash`→无。

> 模板卡片「自定义空协议」用 `pencil`；header 图标用 `file_eproto` 或 `protocol`。

### 数据模型（src/icd_utility/include/icd/）

- `icd::Frame(id:int, name, description, type:FrameType, order:ByteOrder)`。
- `icd::Node(name, description, offset:字节, bit_offset:字节内位, bit_width, value_type:ValueType, tag, attrs:NodeAttrs)`。
- `NodeAttrs`：`unit` / `scale_a:optional<float>` / `scale_b` / `is_scaled` 等。
- `ValueType` 含 `byte_(uint8)` / `word(uint16)` / `shortint(int16)` / `smallint` / `longword(uint32)` /
  `integer(int32)` / `single(float)` / `double_(double)` 等，**无 int8**。`smallint` 语义同为 int16
  （`src/core/node.cpp` 按 int16_t 解码），向导只产出 `shortint`，不产出 `smallint`。
- `.eprotox` 序列化：`icd::format::serialize_xml_repository(path, repo)` 写
  `<ICDProtocol version="1.0"><Frame>...<ID>/<Name>/<Type>data|cmd|dataCfg/
  <ByteOrder>littleEndian|bigEndian/<Length>/<Nodes>`；读回用
  `deserialize_xml_repository`。与 `ProtocolEditorWidget`（`ProtocolFormat::Xml`）完全匹配。

### 编辑器能力

- `ProtocolEditorWidget::saveAs` 默认扩展名 `.eprotox`，`ProtocolFormat::Xml` →
  `deserialize_xml_repository`；`.eproto`(JSON) 保留读取（降级兼容格式）。
- `EditorManager` 已注册 `eproto` 与 `eprotox` → "protocol" 编辑器类型，`file_eproto`
  图标映射已有。

### 现有入口

项目树「协议」分类：`defaultCategories()` 中
`{protocol, 协议, protocol/, protocol, eproto, 新建协议文件}`。
右键「新建协议文件」→ `createNewFile(catId, "eproto", "新建协议文件")` → 目前落入
通用空文件分支（`ProjectStructureWidget.cpp:1080-1091`）。本向导将替换该分支，
与 `etprog`→`TestProgramWizard` 对称。

## 方案设计

### 决策记录

| # | 决策 | 理由 |
|---|---|---|
| 1 | 向导产出 **`.eprotox`（XML）** 文件，用 `serialize_xml_repository` | 与既有决策一致：`.eproto`(JSON) 已降级为兼容格式不再新建，`.eprotox` 为主格式；编辑器默认保存也是 `.eprotox`（用户确认） |
| 2 | 字段数据类型下拉**移除 int8**，仅 7 项：uint8/uint16/int16/uint32/int32/float/double | `icd::ValueType` 无 int8（uint8=byte_、int16=shortint，smallint 实为 int16 语义），生成 int8 无落点（用户确认） |
| 3 | 项目树协议分类 `newFileExt` 由 `"eproto"` 改为 `"eprotox"`，`createNewFile` 分支判断 `extension == "eprotox"` 走向导 | 与决策 #1 对齐，产出扩展名 = 分类新建扩展名，与 `etprog`→`TestProgramWizard` 模式对称；已存在的 `.eproto` 文件仍可正常显示/打开 |
| 4 | 帧 ID 以 **hex 字符串**收集（placeholder `0x100`），存储时解析为 `int`（空则默认 0）；摘要显示原输入文本 | 原型语义为 hex；`icd::Frame::id()` 是 `int`，`.eprotox` 的 `<ID>` 存数值。UI 层 hex ↔ 模型层 int 映射 |
| 5 | HTML「位偏移」为**绝对位偏移**，映射 `Node.offset = bit/8`、`Node.bit_offset = bit%8`；位宽直接映射 `bit_width` | icd 模型 offset 是字节、bit_offset 是字节内位；位布局视图按 (offset, bit_offset, bit_width) 渲染 |
| 6 | 系数 scale 文本 → `NodeAttrs`：空或 `"1.0"` → `is_scaled=false`；非 1.0 且可解析 → `is_scaled=true, scale_a=值`；非数字红闪 | 单系数对应线性缩放系数 A；避免给不缩放字段误标 is_scaled |
| 7 | 单位文本 → `NodeAttrs.unit` | 直接映射 |
| 8 | 4 个模板字段预置用 C++ 静态数组转译 HTML JS `defaultFields` | 模板为创建期骨架，无需外置资源文件 |
| 9 | 字段表格用 QTableWidget + `setCellWidget`（行内 QLineEdit/QComboBox/QToolButton），数据变更整表重建 | 行内控件 + 删除按钮需要 cell widget；数据量小 |
| 10 | 模板重选时**直接加载**模板字段（覆盖当前字段，无脏确认） | 字段为创建期短数据，无「已保存状态」；模板覆盖语义与 HTML 一致。若审查提出丢数据风险再加脏确认 |
| 11 | 字段为空时前进（Page3）弹 QMessageBox 确认「当前未定义任何字段，确定要继续吗？」 | 原型 `confirm()` 行为，Qt 下用模态 QMessageBox |
| 12 | 帧属性页门禁：帧名称非空 + 不含非法文件名字符（红闪 1200ms）；帧 ID 非空时须为合法 hex/十进制整数 | 帧名称即文件名（`.eprotox`）；ID 非必填，空默认 0x00 |
| 13 | 创建期 `onCreateValidate()` 校验所有字段行：名称空→「未命名」兜底、位偏移/位宽非法→红闪定位、系数非数字→红闪定位；任一失败阻止 accept | `create_btn_` 直连 accept() 绕过末页校验；创建期就地拦截，避免生成非法 XML |
| 14 | 帧名称重复文件兜底：`createNewFile` 内 `QFile::exists` 检查 + warning（调用方守卫） | 与 `etprog` 分支对称；帧名称=文件名，重名即文件冲突 |

### 整体架构

```
ProjectStructureWidget::createNewFile(catId, "eprotox", ...)
└── ProtocolFileWizard (BaseWizardDialog)

    ├── Page2 FrameInfoPage     —— 帧名称(校验红闪)/帧 ID(hex)/帧类型/字节序/帧描述
    ├── Page3 FieldPage         —— 字段表格 + 添加/删除字段 + 空态占位
    └── Page4 SummaryPage       —— 模板/帧名称/帧 ID/字节序/描述/包含字段 tag

```

- `validatePage()`：字段数为 0 → QMessageBox「当前未定义任何字段，确定要继续吗？」

**Page4 摘要**：intro 文案「确认协议配置，点击「创建协议」即可生成 `.eprotox` 文件。」

- 协议模板 / 帧名称 / 帧 ID / 字节序 / 描述（跨列）/ 包含字段（跨列，字段 tag）。
- 字段 tag 格式 `name (U32 | B16)`：类型缩写映射
  uint8→U8 / uint16→U16 / int16→I16 / uint32→U32 / int32→I32 / float→F32 / double→F64；

  均实时刷新摘要。

### 数据模型差异与决策

**扁平字段模型（向导内部）**：

```cpp
struct WizardField {
  QString name;
  int offset;      // 绝对位偏移（HTML 语义）
  int width;       // 位宽
  QString type;    // uint8/uint16/int16/uint32/int32/float/double（决策 #2）
  QString scale;   // 系数文本（默认 "1.0"）
  QString unit;
};
```

**→ icd::Node 映射**（决策 #5/#6/#7）：

| WizardField | icd::Node | 说明 |
|---|---|---|
| name（空→「未命名」） | `name` | 字段名称 |
| offset（绝对位） | `offset = bit/8`、`bit_offset = bit%8` | 位偏移拆分 |
| width | `bit_width` | 位宽 |
| type | `value_type`：uint8→byte_、uint16→word、int16→shortint、uint32→longword、int32→integer、float→single、double→double_ | 类型映射 |
| scale（空/"1.0"→is_scaled=false；否则→scale_a + is_scaled=true） | `attrs.scale_a` + `attrs.is_scaled` | 系数 |
| unit | `attrs.unit` | 单位 |
| - | `attrs.scale_b = std::nullopt`（不设置） | B 系数不产出 |
| - | `tag = Tag::none`、`description = ""` | 固定 |

> 已知限制：`is_scaled` / `scale_a` 当前仅在序列化层写入 `.eprotox`，核心解码路径
> （`src/icd_utility/src/core/`）尚未消费该标志（grep `is_scaled` 无匹配）。不影响本向导
> 产出数据完整性；向导按规范正确写入，供未来解码消费。

**帧属性 → icd::Frame**（决策 #4）：

| 向导 | icd::Frame |
|---|---|
| 帧名称 | `name`（也是文件名 `<name>.eprotox`） |
| 帧 ID（hex 文本→int） | `id` |
| 帧类型 | `type`（data/cmd/data_cmd） |
| 字节序 | `order`（little_endian/big_endian） |
| 帧描述 | `description` |

```cpp
if (extension == QStringLiteral("eprotox")) {
  // 协议文件走完整向导（模板/帧属性/字段定义/完成），文件名由帧名称决定
  ProtocolFileWizard wizard(this);
  if (wizard.exec() != QDialog::Accepted) return;
  auto frame = wizard.resultFrame();
  fileName = QString::fromStdString(std::string(frame.name())) + ".eprotox";
  fullPath = QDir(fullDir).absoluteFilePath(fileName);
  if (QFile::exists(fullPath)) {
    QMessageBox::warning(this, "新建失败", "文件已存在：%1");
    return;
  }
  icd::Repository repo;
  repo.add_frame(std::make_unique<icd::Frame>(std::move(frame)));
  created = icd::format::serialize_xml_repository(
                toFsPath(fullPath), repo).has_value();
  skipRename = true;
  LOG_INFO("PROJECT_UI", "向导新建协议 [name={}] [template={}]",
           ...);
}
```
