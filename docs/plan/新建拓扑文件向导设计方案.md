# 新建拓扑文件向导设计方案

## 问题陈述

用户需要一个快速创建拓扑文件（`.etopo`）的向导，复刻
`docs/prototype/新建拓扑文件向导设计.html` 的四步交互（模板 → 设备&UUT → 连线 → 摘要），
在项目「拓扑」分类下新建文件，替代当前创建空白 `.etopo` 的流程。

现状：`ProjectStructureWidget::createNewFile` 对 `etopo` 走通用分支，生成空文件，
用户需在拓扑编辑器中手工拖拽搭建。向导应产出**结构完整、可直接打开与运行**的拓扑骨架。

## 架构回顾

- `.etopo` 为 JSON，由 `etest::topology::TopologyJsonSerializer` 序列化
  `TopologyDocument`（`products`=UUT / `devices` / `connections`），
  `version=1`；设备/连线 `id` 缺省时 `addDevice`/`addConnection` 自动生成 UUID v4。
- `TopologyDocument` 模型：`TopologyProduct`（name/ports/position/size）、
  `TopologyDevice`（id/name/deviceType/pluginId/position/properties/ports/size）、
  `TopologyConnection`（id/productName/portName/deviceName/devicePort/style）。
- 引擎 `TestExecutionEngine::loadTopology` 按 `pluginId` 经 PluginManager 解析设备，
  并**禁止 mock 与真实设备混用**（`checkMockConsistency`）。
- 连线兼容性由 `TopologyDocument::canConnect` 校验：UUT 端口方向与设备端口方向兼容
  （Input↔Output、Bidirectional↔任意），且 UUT 端口 `allowedDeviceTypes` 包含设备
  `deviceType` 或设备端口 `functionType` 字符串。
- 现有 5 个 mock 设备插件（`src/plugins/mock/{can,a429,ad,da,serial}`），描述文件
  `mock_<type>_device.json` 提供 `id`（`etest.plugin.device.mock_<type>`）、
  `device_type`、`device_channels`、`device_function`、`device_direction`。
- 向导基础设施：`BaseWizardDialog`（页头/步骤条/页面栈/底部导航，`addPage`/
  `setCurrentPage`/`onCreateValidate` 虚函数），已有 NewProjectWizard /
  ProtocolFileWizard / TestProgramWizard 三个打样复用。
- 集成点：`ProjectStructureWidget::createNewFile` 已按 extension 分支
  （`etprog` → TestProgramWizard、`eprotox` → ProtocolFileWizard），加 `etopo` 分支。
- 约束：向导实现于 `etest_app`（主程序），不在 topology-editor 工具内，
  不触发「附属工具不得链接其它模块」约束。

## 方案选项及理由

### 设备模板来源
- **选项 A（选定）**：向导内置 5 类 mock 设备模板（can/a429/ad/da/serial），
  pluginId/通道数/功能类型硬编码对应现有 mock 插件。
  理由：5 类模板与原型一一对应，且生成的全 mock 拓扑天然满足引擎一致性校验，
  保证可运行；V1 零配置、零运行时依赖。
- 选项 B：运行时从 PluginManager 枚举设备插件动态生成。
  理由：灵活，但需处理 mock/真实混合拦截与空插件列表，V1 风险高，留作后续。

### 拓扑文件名
- **选项 A（选定）**：向导内加「拓扑名称」输入框（默认「新建拓扑文件」），
  生成 `<名称>.etopo`，与协议/测试程序向导一致。
- 选项 B：不加名称，沿用通用分支默认名（新建拓扑文件.etopo，重名自动 _1/_2）。
  不选：用户无法控制文件名。

### 连线创建交互
- **选项 A（选定）**：显式选择器。连接页顶部常驻一行
  `[设备▾][设备端口▾] → [UUT▾][UUT端口▾] [+添加]`，下方列表展示已有连线（可删）。
  端口下拉随设备/UUT 选择联动。
- 选项 B：忠实原型随机生成。不选：随机不可控，实际产品 UX 差。

### UUT 端口方向与兼容性
- **选项 A（选定）**：UUT 端口默认 `Bidirectional` + `functionType=CUSTOM`；
  建立连线时自动把设备 `deviceType` 并入该 UUT 端口的 `allowedDeviceTypes`，
  保证 `canConnect` 通过，模型自洽。
- 选项 B：UUT 端口默认携带全部 5 类设备类型。不选：语义过宽，后续编辑器内
  改端口属性时信息失真。

### 自动布局
- **选项 A（选定）**：设备列于左、UUT 列于右，垂直排列、行距固定、不重叠。
  无画布场景下保证生成文件在编辑器打开时结构可读。
- 选项 B：全部堆叠于原点。不选：编辑器打开即重叠，需手工拖动。

## 决策记录

1. 复用 `BaseWizardDialog`，4 页：模板 / 设备&UUT / 连线 / 摘要。
2. 设备模板内置 5 类 mock（can/a429/ad/da/serial），硬编码映射到
   `etest.plugin.device.mock_<type>`；设备显示名沿用原型（PXI-CAN卡等）。
3. 第 1 页顶部加「拓扑名称」输入框（默认「新建拓扑文件」），非法文件名
   字符（`\ / : * ? " < > |`）校验失败。
4. 设备实例名 `<显示名>_<序号>`（如 `PXI-CAN卡_1`）；UUT 名 `UUT_<序号>`。
5. 设备端口：由模板通道数生成 `ch0..chN-1`；可加端口（自动名，避免与 ch* 冲突）。
   UUT 端口：初始 `p0`，可增删。
6. 名称唯一性：设备名、UUT 名、设备端口名、UUT 端口名各自唯一
   （连线按名称引用，重复会破坏引用）。
7. 连线显式选择器：设备+端口 → UUT+端口；校验方向兼容 + 非重复；建线时
   自动把设备 `deviceType` 并入 UUT 端口 `allowedDeviceTypes`（实现为
   `reconcileUutPortAllowedTypes`：依当前连线集合重算，删线后同步移除）。
   `canConnect` 双子句：子句 1 匹配 `deviceType` 字符串，子句 2 匹配
   `functionTypeToString(端口.functionType)`。注意 `FunctionType` 枚举无 CAN，
   CAN 设备端口 `functionType=CUSTOM`，故子句 2 永为 false，兼容性完全依赖
   子句 1 的 deviceType 匹配——决策 7 的自动并入恰好覆盖。
   **已知限制**：未连线的 UUT 端口 `allowedDeviceTypes` 为空，在编辑器内
   拖线会被 `canConnect` 拒绝；需在编辑器属性面板补类型后方可连线（V1 接受，
   后续可在端口 UI 提供类型多选）。
8. 校验：第 2 页 → 第 3 页需 ≥1 设备 + ≥1 UUT；第 3 页 → 第 4 页连线为空时
   确认放行；创建时 `onCreateValidate` 校验拓扑名称合法。
9. 模板预置（忠实原型）：空拓扑（空）；单设备+UUT（1 个 CAN 设备 + 1 个
   UUT + 1 条连线）；多设备混合（can/ad/serial 3 设备 + 2 UUT + 3 条连线）。
10. 自动布局：设备左列（x≈-1100）、UUT 右列（x≈-500），按索引垂直排列，
    行距 160。
11. 产出 `.etopo`：`TopologyDocument` → `TopologyJsonSerializer::serialize` →
    `QJsonDocument::toJson(Indented)` → 写文件。
12. 集成：`ProjectStructureWidget::createNewFile` 增加 `etopo` 分支，文件名
    `拓扑名称 + ".etopo"`，重名拦截（与 eprotox 分支一致）。

## 详细设计

### 文件与类

| 文件 | 说明 |
|------|------|
| `src/app/dialogs/TopologyFileWizard.h/.cpp` | 向导本体 + 4 个嵌套页类 |
| `src/app/ProjectStructureWidget.cpp` | `createNewFile` 加 `etopo` 分支 |
| `src/app/CMakeLists.txt` | 注册 TopologyFileWizard.h/.cpp |

`TopologyFileWizard : BaseWizardDialog`：
- `QString topologyName() const`
- `TopologyDocument* resultDocument()`（内部持有，调用方 serialize 前拷贝语义
  需注意 `TopologyDocument` 非拷贝——由向导内部构建，调用方读取）

### 页面

1. **TemplatePage（模板）**：顶部「拓扑名称」QLineEdit；下方 3 张模板卡片
   （复用 `WizardTemplateCard`，objectName `templateCard`）。切模板 = 清空并预置
   对应设备/UUT/连线。
2. **DeviceUutPage（设备&UUT）**：左右两栏。左栏设备池：`添加设备`（下拉菜单
   列出 5 类 mock 模板）→ 添加实例；每行显示 `名称 + 端口数`，含 `+端口`/`删除`。
   右栏 UUT 池：`添加 UUT` → `UUT_<n>`（1 个 p0 端口）；行内含 `+端口`/`删除`。
   删除设备/UUT 时级联删除关联连线。空态提示。
3. **ConnectionPage（连线）**：顶部新增连线行（4 个下拉 + 添加按钮）；下方已有
   连线列表（`设备·端口 → UUT·端口`，含删除）。添加时校验兼容性并自动补
   UUT 端口 `allowedDeviceTypes`。
4. **SummaryPage（摘要）**：网格展示 模板/设备数/UUT 数/连线数/拓扑描述
   （对齐原型），创建按钮文案「创建拓扑」。

### 校验规则

- 拓扑名称：非空、无非法文件名字符（第 1 页实时校验 + 创建前复验）。
- 名称唯一：设备/UUT/端口增删时检查，冲突红闪定位。
- 第 2 → 3 步：≥1 设备 + ≥1 UUT；不足则禁止前进。
- 第 3 → 4 步：0 连线确认放行。
- 创建前 `onCreateValidate`：复验名称 + 名称唯一性。

### 序列化产出

```
createNewFile("topology", "etopo", "新建拓扑文件")
  └─ TopologyFileWizard.exec() == Accepted
       ├─ fileName = topologyName() + ".etopo"
       ├─ QFile::exists 拦截
       ├─ QJsonObject root = TopologyJsonSerializer::serialize(*doc)
       ├─ QFile::write(QJsonDocument(root).toJson(QJsonDocument::Indented))
       └─ skipRename = true
```

## 验证

1. `scripts/build_ninja.bat -t debug -m ETestStudio` 编译通过。
2. 手动（GUI 需人工确认）：
   - 项目「拓扑」分类新建 → 向导 4 步可走通
   - 3 个模板预置正确；设备/UUT 增删、端口增删、连线增删联动正确
   - 名称冲突、缺设备/UUT 的拦截生效
   - 生成的 `.etopo` 在拓扑编辑器打开：设备/UUT 位置不重叠、连线可见
   - 生成的拓扑可被引擎加载（mock 全一致）
