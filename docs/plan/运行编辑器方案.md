# 运行编辑器（Run Editor）方案

## 一、问题陈述

项目各编辑器均产出独立文件，形成"编辑器 + 运行器"成对架构：

| 编辑器（编辑态） | 产出文件 | 运行器 |
|---|---|---|
| 拓扑编辑器 | `.etopo` | 拓扑展示 / 独立拓扑编辑器 |
| 协议编辑器 | `.eproto`/`.eprotox` | 协议解析 / 独立协议编辑器 |
| 测试程序编辑器 | `.etprog` | 引擎执行 / 独立测试程序编辑器 |
| **运行编辑器（缺失）** | **`.erun`（待定）** | ExecutionDashboard（运行态）/ test-executor（独立） |

**缺口**：运行页面（执行仪表盘）的可编辑配置——选择测试程序、监听器（connectionId/类型/名称）、布局（位置/大小）、运行参数——目前散落在运行态（`MonitorConfigDialog` 对话框 + `ExecutionDashboard` 运行时），**没有独立编辑器**。运行态也因此被塞进了编辑职责（布局保存等），与"运行态只展示"的职责边界冲突。

**同时**，可视化区（`VisualizationArea`）当前 `relayout()` 自动网格均分，用户无法自由摆放/调整 visualizer 卡片。

**改动动机**：
- **架构一致**：运行编辑器产出独立 `.erun`，与拓扑/协议/测试程序编辑器平级。
- **职责分离**：运行编辑器负责编辑（编辑态），ExecutionDashboard / 独立程序只读消费，运行态不承担编辑。
- **用户体验**：可视化区（运行编辑器主视图）像画布一样自由摆放、调整 visualizer（拖拽移动 + 边缘改大小），增删不重置布局。
- **复用成熟实现**：拓扑编辑器已有完整的 QGraphicsView 交互（移动、8 方向 resize 手柄、排列/分布），直接复用。

**目标**：新增**运行编辑器**（编辑态一页），以可视化区为主视图，产出 `.erun` 独立文件；`ExecutionDashboard`（运行态）与独立运行程序读 `.erun` 消费。可视化区支持**拖拽移动 + 边缘/角部改大小 + 排列/分布工具栏**。

> **进度同步**：阶段 A 已完成运行编辑器骨架——`RunConfigEditor`（IEditor 派生）+ `.erun` 序列化/反序列化，可打开/保存 `.erun`。阶段 B 已完成：可视化区手动布局（`VisualizerProxy` 移动/8 向 resize/两态、`VisualizationArea` 编辑态手动布局 + 排列/分布 + 缩放平移）、`RunConfigEditor` QMainWindow + dock 体系（`addToolBar` 原生工具栏、左侧「测试程序」QDockWidget、快照式撤销/重做、主题图标）、`.erun` 格式（`programs` 多选数组 + 归一化）、D2 测试程序选择（`ProgramChecklistWidget` 多选 dock）。阶段 B 剩余：`.erun` 监听器迁移评估（D1）、`runParams` 键定义、`MonitorConfigDialog` 运行态交互迁移评估。`ExecutionDashboard` 保持运行态只读展示（D3），QMainWindow 化留后续阶段。关键决策见 3.4/四。

## 二、架构回顾：拓扑编辑器可复用逻辑

拓扑编辑器是项目内现成的 QGraphicsView 交互实现（`src/topology/`），两块逻辑可直接参考：

### 2.1 `TopologyBlockItem`（`TopologyBlockItem.cpp`）—— item 级交互，核心可复用

- **可移动**：`setFlag(ItemIsMovable)` + `ItemSendsGeometryChanges`，`itemChange(ItemPositionHasChanged)` 通知场景刷新关联。
- **可选中**：`setFlag(ItemIsSelectable)`，`paint` 中按 `State_Selected` 高亮（fill 变亮 + 描边加粗）。
- **8 方向 Resize 手柄**（选中时显示，`resizeHandlesEnabled()` 配置开关）：
  - `resizeHandleRect(ResizeHandle)`：8 个手柄的局部矩形（TopLeft/TopMid/TopRight/RightMid/BottomRight/BottomMid/BottomLeft/LeftMid）。
  - `handleAt(pos)`：命中测试（遍历 8 个手柄矩形）。
  - `updateCursorForHandle`：按手柄方向切光标（SizeFDiag/SizeBDiag/SizeVer/SizeHor）。
  - `mousePress/Move/Release` 状态机：按下手柄 → `active_handle_` 记录 + 暂存旧尺寸/位置 + **临时关 `ItemIsMovable`**；移动 → `doResize(delta)`；释放 → 恢复 `ItemIsMovable` + 回调 `onResizeFinished`。
  - `doResize`：按手柄方向更新 `block_width_`/`block_height_`，带 `minW`/`minH` 下限；四角手柄同步修正 `pos()`（保持对边固定）。
- **hover 反馈**：`hoverMoveEvent` 内命中手柄切光标，否则 `SizeAllCursor`。

### 2.2 `TopologyView`（`TopologyView.cpp`）—— 视图级交互，参考

- `RubberBandDrag` 框选；`mousePress/Move/Release` 中键平移（`panning_`）；`wheelEvent`（Ctrl+滚轮缩放）；`zoomFit`（`fitInView`）。

### 2.3 关键差异（复用必须适配的点）

| 维度 | 拓扑 `TopologyBlockItem` | 可视化区 `VisualizationArea` |
|---|---|---|
| item 类型 | 自绘 `QGraphicsItem`（`paint` 重绘） | `QGraphicsProxyWidget`（包裹 QWidget visualizer） |
| resize 对象 | `block_width_`/`block_height_`（item 局部尺寸） | proxy 的 widget 尺寸（`QWidget::resize`/`setGeometry`） |
| 子内容 | 端口子项（`child_ports_`） | visualizer 的 QWidget 布局 |
| 撤销 | `onResizeFinished` 入 `QUndoStack` | 布局属于配置，无需 undo |

因此 **resize 手柄的状态机逻辑（命中/光标/拖动/最小尺寸）可以整体移植**，但改的落点是 proxy 几何而非 item 自绘尺寸。

## 三、方案设计

### 3.1 主视图：VisualizerProxy 与可视化区手动布局（核心）

**VisualizerProxy —— `QGraphicsProxyWidget` 子类**，内嵌拓扑的 resize 手柄逻辑：

- **移动**：`setFlag(ItemIsMovable)` + `ItemSendsGeometryChanges` + `ItemIsSelectable`。
- **手柄**：`paint` 选中态绘制 8 个手柄；移植 `handleAt`/`updateCursorForHandle`/鼠标事件状态机，`doResize` 改为改 `widget()->resize` + 四角同步 `setPos`。
- **选中**：选中态高亮（卡片描边），点击选中、点空白取消。
- **boundingRect 边距（审查🟡1）**：重写 `boundingRect()` 返回 `QGraphicsProxyWidget::boundingRect().adjusted(-6,-6,6,6)`，否则手柄外扩半区伪影 + 可抓取区减半。
- **拖拽兜底（审查🟡2）**：proxy 转发鼠标事件给内嵌 widget，波形缩放等子控件可能消费事件。实现期逐一确认 visualizer 子类鼠标行为，不满足的加标题栏拖拽区兜底。
- **最小尺寸（审查🔵8/🔵9）**：`doResize` 用 `widget()->setMinimumSize(minW, minH)`，具体值参考各 visualizer 的 `minimumSizeHint()`，阶段 B 实现期定（见开放问题 1）。

**VisualizationArea 改造**：
- 去掉自动 `relayout()`；新卡片落默认位置。
- **relayout 解耦（审查🟡3）**：手动模式与 `relayout()` 完全解耦，`resizeEvent` 不重排，仅"自动排列"动作可调用。
- **视图交互**：滚轮缩放 + 中键平移（参考 TopologyView）。
- **画布尺寸（审查🟡6）**：设固定 `sceneRect`（如 4000×3000），滚动条 `ScrollBarAsNeeded`。
- **右键菜单**保留（关闭可视化）+ "自动排列"动作。

### 3.2 辅助布局工具栏（参考拓扑）

`QToolButton + QMenu` 两组（`InstantPopup`）：
- **排列**：左/水平居中/右/顶端/垂直居中/底端对齐（复刻 `doAlign`）
- **分布**：水平/垂直（复刻 `doDistribute`）
- **自动排列**：恢复旧 `relayout()`

算法移植 `doAlign`/`doDistribute` 几何逻辑，收集选中 `VisualizerProxy*` → `sceneBoundingRect()` 联合 → `moveBy`；去掉 undo（布局存配置）。**门控与保存时机（审查🔵7）**：移植"选中 ≥2 才启用"门控，动作结束统一 `saveLayout()`。

工具栏宿主：运行编辑器窗口 `QMainWindow` 的 `addToolBar()`。

### 3.3 运行编辑器窗口：QMainWindow + QDockWidget

运行编辑器（含未来的 ExecutionDashboard / 独立程序）作为 **QMainWindow**：

- **`addToolBar()`** 原生工具栏（排列/分布、保存等挂这里）。
- **`QDockWidget`** 面板（监听器配置、布局属性、运行参数等）可停靠、可拖拽重排。
- **停靠策略**：QDockWidget **禁用浮动**（`setFloatable(false)`），避免浮动窗口脱离宿主（QStackedWidget 页面内嵌时，浮动窗口切页不跟随隐藏）。支持拖拽重排停靠，不支持脱离浮动。
- **布局改造**（针对现 `ExecutionDashboard` 的 `QVBoxLayout + QSplitter`）：`setCentralWidget(可视化区容器)` + `addToolBar` + 面板 `addDockWidget`。
- **消费方与样式迁移（审查🟡4）**：改造需一并纳入 `MainWindow` 注入链路、`ExecutionPanelController` 的 tab 切换调用、13 主题 QSS 的 `#Exec*Splitter/#ExecBottomTabs` 选择器迁移。

### 3.4 `.erun` 独立格式（关键决策，谨慎推进）

> **定位（审查🔴2）**：`.erun` 是**项目内**的运行配置文件，**不是自包含的独立运行文件**。它记录运行页面的一切可编辑配置（选择测试程序、监听器、布局、运行参数）。**独立运行程序加载的是整个项目**（`.etproj` + 拓扑 + 协议 + 用例 + `.erun`），从项目上下文解析 `.erun` 中的 `connectionId`（拓扑连接 UUID）与相对路径。因此 `.erun` 内路径均相对项目根，**无需 `projectRef` 字段**（项目本身提供上下文）。

运行编辑器产出独立 `.erun` 文件，包含**运行页面一切可编辑配置**：

```json
{
    "version": "1.0",
    "programs": [                                        // 测试程序多选（相对项目根路径），与监听/布局正交
        "cases/命令演示.etprog",
        "cases/综合Mock测试.etprog"
    ],
    "monitors": [                                       // 监听器（connectionId/类型/名称/展示方式）
        { "connectionId": "conn-mock-ad", "displayMode": "waveform", "name": "..." }
    ],
    "layout": [                                         // 布局（位置/大小）
        { "connectionId": "conn-mock-ad", "x": 20, "y": 30, "w": 320, "h": 240 }
    ],                                                  // 坐标取 scene 坐标（proxy->pos()），与视图缩放无关（审查🟡3）
    "runParams": {}                                     // 运行参数（预留）
}
```

**格式不变量（审查🔵3）**：`layout` 仅含有效 connectionId，与 `monitors` 一一对应；`RunConfig::fromJson` 做归一化（丢弃无对应 monitor 的 layout 项、同 id 去重、`programs` 去重丢空串）。

**runParams（审查🔵4）**：预留，候选键如循环次数/超时/执行方式；本版本留空 `{}`，阶段 B 再定。

**关键决策（方向性，需单独评估，不武断落地）**：
- **D1 监听器存储迁移**：现在监听器存 `.etproj` `monitors`。若 `.erun` 承担运行配置，监听器是否从 `.etproj` 迁到 `.erun`？——**倾向迁移**（架构一致，运行配置独立，与拓扑/协议/测试程序文件平级），但需评估 `MonitorManager::loadMonitors` 加载链、现有 `.etproj` 向后兼容、`ExecutionPanelController` 订阅链，属较大改动，列入阶段 B。
- **D2 测试程序选择（已完成）**：测试程序在**运行编辑器**中**多选**，`.erun` 存 `programs` 数组（相对项目根路径，如 `cases/xxx.etprog`），与监听/布局正交。选择 UI 为独立「测试程序」QDockWidget（`ProgramChecklistWidget`：QListView + checkable item + 顶部"全选"），勾选变化即存快照可撤销。运行页在项目打开时加载对应 `.erun`，运行/执行从项目上下文解析。
- **D3 运行态是否可编辑（倾向结论，审查🟡1）**：运行态（ExecutionDashboard）**只读展示**——page1 在运行前按 `.erun` 重建可视化区；编辑只在运行编辑器（page0 独立实例），两者**不共享可视化区实例**，避免编辑污染运行展示。运行中如需临时调整布局，属视图临时态，不写回 `.erun`。

### 3.5 三个消费方

| 消费方 | 形态 | 职责 |
|---|---|---|
| **运行编辑器**（编辑态 page0） | 可视化区主视图 + QDockWidget 面板 | 编辑监听器/布局/测试程序，保存 `.erun` |
| **ExecutionDashboard**（运行态 page1） | 复用可视化区（只读） | 读 `.erun`，展示监听器 + 布局，执行测试 |
| **独立运行程序**（test-executor 演进） | 独立窗口 | 读 `.erun` 直接跑，用户无需 IDE |

可视化区（VisualizationArea + VisualizerProxy）作为**共享组件**，编辑/展示两用。

## 四、决策记录

| # | 决策 | 理由 |
|---|---|---|
| 1 | 用 `VisualizerProxy : QGraphicsProxyWidget` 而非自绘 item | 现有 visualizer 全是 QWidget，proxy 包裹零改造成本 |
| 2 | resize 手柄逻辑从 `TopologyBlockItem` 移植，落点改为 `widget()->resize` | 状态机可复用，最小差异适配 |
| 3 | 去掉自动 relayout，改为手动摆放 | 用户可自由布局；保留右键"自动排列"兜底 |
| 4 | 运行配置**格式**用独立 `.erun` 文件 | 架构一致：每个编辑器产出独立文件；监听器是否从 `.etproj` 迁移见 D1 未定项 |
| 5 | 视图支持滚轮缩放 + 中键平移（参考 TopologyView） | 大画布可浏览 |
| 6 | 可视化区加辅助布局工具栏（排列/分布），复用拓扑 doAlign/doDistribute | 手动布局需要对齐/分布辅助 |
| 7 | 运行编辑器/ExecutionDashboard 用 QMainWindow（宿主内嵌），面板用 QDockWidget 且禁用浮动 | 原生工具栏 + 可停靠面板，利于扩展；禁浮动避免脱离宿主 |
| 8 | 运行编辑器与运行态/独立程序职责分离：编辑器编辑、消费方只读 | 运行态不承担编辑，职责干净 |

**未定决策（谨慎推进，见 3.4/五）**：D1 监听器迁移到 `.erun`（需评估加载链与兼容性）；D2 测试程序选择交互；D3 运行态临时布局语义。

## 五、开放问题

1. **最小尺寸**：visualizer 卡片最小宽高（参考各 visualizer sizeHint）？
2. **选中与右键冲突**：proxy mousePress 处理顺序（手柄 vs 默认）？
3. **布局迁移**：现自动布局无保存状态，切手动后首次打开位置如何定？
4. **工具栏图标**：复用拓扑 `topo_*` 还是新图标？
5. **运行态临时布局（D3）**：运行中用户能否拖 visualizer？若允许，是"视图临时态（切走还原）"还是"写回 `.erun`"？——需明确，避免运行态又背编辑职责。
6. **`.erun` 与 `.etproj` 的关系**：`.erun` 是否引用/内嵌拓扑、协议、测试程序（相对路径），还是纯配置？——影响文件组织与独立程序加载。

**阶段 C 共享化的对象边界**：
- **共享**：可视化区（VisualizationArea + VisualizerProxy + visualizers）——主程序运行态（ExecutionDashboard）与独立运行程序**共同消费的核心**。趁依赖干净（当前无 app 特定依赖）独立成共享模块，是成本最低的时机，避免后续积累 app 依赖后难搬。
- **不共享**：RunConfigEditor 编辑器壳（app 层套在共享可视化区上的编辑器）——独立运行程序只读 `.erun` 运行，不需要编辑能力（"运行=定稿"职责哲学），编辑器留 `src/app/editors/` 与 MockConfigEditor 并列。
- **判断标准**：是否被多个目标消费。可视化区被 2+ 消费方使用，故共享；编辑器仅 IDE 使用，故留 app。
