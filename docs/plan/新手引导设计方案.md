# 新手引导设计方案

## 1. 问题陈述

新用户初次使用 ETest Studio 时，缺少对核心功能（新建项目 / 拓扑 / 协议 / 测试程序 /
执行）的主动引导。需要一套**分步高亮的引导**，让新用户跟着气泡了解各功能如何操作。

仓库已有可复用的引导演示机制（`examples/guidance-demo`：引导首页 + GuidanceFlow 分步
高亮 UI + 窗口移动），整体迁移到主程序，在 ribbon「开始」页加入口。

## 2. 目标交互流程

```
入口（开始页「新手引导」）
  → 全屏遮罩引导首页（5 主题卡片）
    → 点击主题 → 自动打开示例/切页 → 分步高亮 + 气泡导航
      → 完成 / 跳过 / 点遮罩 → 退出
```

## 3. 详细设计

### 3.1 入口（D1）

- ribbon「开始」页（第一 tab）加「新手引导」入口，与「快速开始」并列。
- **定位理由**：帮助页是"事后查询"入口，新用户不会主动点；「开始」页是新用户第一眼
  看到的 tab，可达性最高，与「快速开始」同属"引导"语义。

### 3.2 引导首页（D2）

- **MainWindow 全窗口半透明遮罩** + 居中卡片区（5 张主题卡）。覆盖范围为主窗口
  （含 ribbon）；QADS 浮动 dock 是独立顶层窗口，不在本期覆盖范围。
- 卡片：图标 + 名称 + 一句描述；hover 高亮，点击进入对应 `GuidanceFlow`。
- 布局：5 张卡，宽屏一行或 3+2 两行（实现期按窗口宽度自适应）。
- 关闭：点遮罩空白或右上角 ×。

### 3.3 分步引导（D3/D6/D7/D8）

- 遮罩覆盖 **MainWindow 全窗口**（含 ribbon），当前步骤目标 **accent 边框高亮** +
  其余区域压暗（镂空聚焦）。
- **气泡**（完整导航）：目标旁（优先右侧/下方）：
  - 标题 + 描述
  - 「第 N 步 / 共 M 步」
  - 非首步「上一步」；非末步「下一步」；末步「完成」；右上角「跳过」
- **交互锁定（D11）**：引导期间目标 UI 元素不响应鼠标（遮罩拦截），用户只能操作气泡
  按钮；主窗口快捷键禁用，避免用户干扰演示。

### 3.4 主题与步骤序列（范围收敛，D16）

**本期先做 2 条主题**（机制先行、主题渐进）：功能/UI 尚在迭代，引导过度依赖具体控件
会在 UI 改动后失效，故收敛范围，UI 稳定后再扩。

| 主题 | 步骤 |
|---|---|
| 创建测试工程 | ① 高亮「开始」页「新建项目」按钮 → ② 说明将打开新建项目向导（选模板 / 名称 / 位置，向导已存在，引导不必细） |
| 创建拓扑 | ① 高亮「新建文件」入口（说明新建文件里可选拓扑，静态高亮） → ② 直接 `openFile` 示例 `.etopo` 打开拓扑编辑器，高亮画布（拖拽设备 / 连线） → ③ 高亮工具栏 |

**关键约束**：引导步骤**不实际触发模态向导**（`QuickStartWizard` / `NewFileGuideWizard`
均 `exec()`，模态框会盖住作为 MainWindow 子窗口的引导遮罩）。「新建项目」「新建文件」
仅作静态高亮目标 + 说明气泡；打开编辑器统一走 `editor_manager_->openFile`（非模态）。

引导首页保留 5 主题槽位，本期仅启用以上 2 条；其余 3 条（协议 / 测试程序 / 执行）
显示"敬请期待"（置灰不可点），后续 UI 稳定后追加，无需改首页结构。

### 3.5 示例文件与自动打开（D3/D4）

- 本期**只内置 `.etopo` 最小示例**（拓扑主题用，放资源）；`.eproto` / `.etprog`
  延后到对应主题启用时再加，避免为未来主题埋无用资源。
- 拓扑主题步骤 ②：直接 `editor_manager_->openFile(示例.etopo)`（非模态），打开拓扑
  编辑器后高亮画布 / 工具栏。
- 后续主题（协议 / 测试程序 / 执行）沿用自动打开示例 / `navigateTo(1)` 机制。

### 3.6 高亮时序（D12）

- 编辑器是 `openFile` 后才创建 dock，enter 回调后需在**编辑器加载完成**（或 QTimer
  单次延时）后再映射 target 高亮，避免 `highlightRect_` 计算错误。

### 3.7 引导结束（D5）

- 完成最后一步自动退出；任一步「跳过」直接退出；点遮罩空白退出。三种退出路径并存。

### 3.8 UI 风格规范（D15）

guidance 整体沿用现有 Fluent 设计语言（与 WelcomeV2 / SettingsDialog 一致），**不沿用
guidance-demo 的硬编码浅色**（绿 #4CAF50 / 固定白泡黑遮罩）。所有颜色经 QSS
（`default.qss` / `vscode.qss` 对称）+ `ThemeManager` token，明暗主题自动适配。

**色板（两套主题对称）**

| 组件 | default（浅色） | vscode（深色） |
|---|---|---|
| 遮罩背景 | rgba(0,0,0,0.50) | rgba(0,0,0,0.55) |
| 气泡 / 卡片底 | #FFFFFF | #2D2D2D |
| 卡片边框 | #E0E0E0 | #3C3C3C |
| 主文字 | #333333 | #CCCCCC |
| 次要文字 | #8A8A8A | #9D9D9D |
| accent（高亮边框 / 主按钮） | #0078D4 | #007ACC |
| hover（卡片 / 按钮） | #F0F0F0 | #383838 |
| 选中（accent-soft） | rgba(0,103,192,0.10) | rgba(0,122,204,0.25) |

**样式通道（自绘层 vs QSS 层）**
- **QPainter 自绘层**：遮罩、气泡底 + 三角形箭头、高亮框由 paintEvent/drawBubble
  自绘，**QSS 无法作用其上**。颜色在代码中读 `ThemeManager` token
  （`accentColor` / `hoverBackground` / `textColor` 等），双主题自动适配、无硬编码。
- **QSS 层**（`default.qss` / `vscode.qss` 对称）：覆盖可样式化的子控件——气泡内
  `#bubble_title` / `#bubble_text` / `#bubble_skip` / `#bubble_prev` / `#bubble_next`
  （沿用 demo objectName），首页主题卡 `#guidanceCard`（白/深底 + 边框 + 圆角 8px +
  hover / 选中）。气泡/高亮的圆角、阴影、箭头形态由自绘决定（复用 demo 逻辑），不靠
  QSS。
- 图标：经 `AppIconProvider` 加载 SVG（明暗自适应），无 emoji。

**文字 / 圆角 / 间距**
- 字号：标题 13-14px（600）；描述 / 步数 11-12px。
- 圆角：卡片 / 气泡 8px。
- 间距：气泡距目标 8px；内部 padding 12-16px；按钮间距 8px。

## 4. 迁移与实现要点

### 4.1 迁移方式（app 一部分，非独立静态库，D13）

guidance 作为 **app 的一部分**：源文件直接编入 ETestStudio，不建独立静态库。
理由：enter 回调需访问 MainWindow 的 `openFile`/`navigateTo`/编辑器定位，与 app
紧耦合；独立库需接口抽象，收益低。目录位置与 `welcome/`、`editors/` 等 app 内部
模块一致。

### 4.2 迁移后目录结构（D14）

```
src/app/guidance/
  guidance_config.h/.cpp          # GuidanceStep/Flow/Config（纯类，入 etest::app 命名空间 + Q_DECLARE_METATYPE 同步）
  guidance_controller.h/.cpp      # 流程控制
  guidance_homepage.h/.cpp/.ui    # 引导首页（全屏遮罩 + 主题卡）
  guidance_presentation.h/.cpp    # 演示层（高亮 + 气泡 + 遮罩，QSS 化）
  guidance_common.h/.cpp          # createGraphicsShadow 子集（原 utility_qt 收窄）
```

**复用** `src/app/utils/window_mover`（不迁 demo 版，D9）。

### 4.3 迁移规范与接入

- 类入 `etest::app`（`Q_DECLARE_METATYPE` 同步）、头保护符 `#pragma once`、
  `setStyleSheet` 全改：自绘层（遮罩/气泡底/箭头/高亮框）颜色读 `ThemeManager` token，
  QSS 只覆盖可样式化子控件（气泡 label/按钮、首页卡片），注册 `default.qss` +
  `vscode.qss`；删坏资源（emoji 笑脸）与死代码。
- **迁移新增实现项**（demo 未实现，需补）：① 点遮罩空白退出——presentation 新增
  `mousePressEvent` 处理；② 快捷键禁用——MainWindow 加 `qApp` 事件过滤器拦截
  `QEvent::ShortcutOverride`。
- `src/app/guidance/GuidanceConfig.cpp`：配置 5 条主题与各自 Flow（enter 回调经
  MainWindow 公开方法 `openFile`/`navigateTo`/编辑器定位）。
- `src/app/MainWindow.cpp`：开始页加「新手引导」入口，trigger 打开引导首页；提供
  Guidance 所需公开方法；MainWindow 持有 Guidance。
- `src/app/resources/icons/svg/`：如缺「新手引导」入口图标则新增 `guide_light/dark.svg`。
- `src/app/CMakeLists.txt`：注册 guidance 源文件 + `.ui`。
- 示例文件 `.etopo/.eproto/.etprog` 加入资源 qrc。
- **`examples/guidance-demo` 迁移完成后删除**（D7）：迁移即完整搬运 + 改造，主程序已
  有完整机制；保留两份源码会 drift，demo 无独立用途。

## 5. 决策记录

| 编号 | 决策 | 理由 |
|---|---|---|
| D1 | 入口放 ribbon「开始」页（非帮助页） | 新用户第一眼看到，可达性最高；与「快速开始」同属引导语义 |
| D2 | 引导首页为全屏遮罩 + 居中主题卡片 | 沉浸式引导，明确告知"引导模式" |
| D3 | 主题进入自动打开示例文件 | 用户跟随气泡即可，引导性强 |
| D4 | 内置最小示例 .etopo/.eproto/.etprog | 无项目也能引导，不受用户文件影响 |
| D5 | 完成/跳过/点遮罩均可退出 | 多种退出路径，防误触卡死 |
| D6 | 气泡完整导航（标题/描述/步数/上一步/下一步/完成/跳过） | 清晰的引导进度 |
| D7 | 目标 accent 边框高亮 + 其余压暗 | 镂空聚焦，明确当前操作对象 |
| D8 | 遮罩覆盖 MainWindow 全窗口（含 ribbon） | ribbon 目标（新建项目/运行）可正确映射高亮 |
| D9 | 迁移剔除 window_mover（复用 utils/window_mover），QSS 化 + 主题适配 | 避免重复实现，符合项目规范 |
| D10 | 主题覆盖 5 大功能（新建项目/拓扑/协议/测试程序/执行） | 覆盖核心操作闭环 |
| D11 | 引导期间目标不响应鼠标、禁用快捷键 | 避免用户干扰演示 |
| D12 | 编辑器加载完成后再高亮 | 避免 target 未 show 导致高亮错位 |
| D13 | 迁移后作为 app 的一部分（非独立静态库） | 与 MainWindow 紧耦合，独立库需接口抽象、收益低 |
| D14 | 迁移后目录为 `src/app/guidance/`（5 组源文件） | 与 welcome/editors 等 app 内部模块一致 |
| D15 | guidance UI 沿用 Fluent 语言：自绘层读 ThemeManager token、QSS 只覆盖子控件，不沿用 demo 硬编码浅色 | 适配 default/vscode 明暗主题；自绘层 QSS 无法作用，须代码取 token |
| D16 | 引导范围收敛：本期先 2 条主题（创建测试工程 2 步、创建拓扑 2-3 步），首页保留 5 槽位，其余"敬请期待" | 功能/UI 尚在迭代，引导过度依赖控件会在改动后失效；机制先行，UI 稳定后扩 |

## 6. 验收标准

1. ribbon「开始」页有「新手引导」入口，点击打开全屏遮罩引导首页，列 5 个主题。
2. 首页列 5 主题槽位，本期启用「创建测试工程」「创建拓扑」2 条，其余置灰
   "敬请期待"；选择启用主题后分步高亮目标（accent 边框 + 压暗），气泡含
   标题/描述/步数/上一步/下一步/完成/跳过。
3. 完成/跳过/点遮罩均可退出引导。
4. 编辑器类主题在编辑器加载完成后再高亮，无错位。
5. 明暗主题下首页、气泡、遮罩正常（QSS + ThemeManager，无硬编码色）。
6. 引导期间主窗口交互锁定（目标不响应、快捷键禁用）。
7. Windows 与 WSL Linux 编译通过。
