# 监听器项目级改造方案（解耦拓扑）

## 1. 问题陈述

监听器（monitor）当前是拓扑文档的一部分，与拓扑文件强耦合，表现为三个痛点：

| 环节 | 现状 | 代价 |
| ---- | ---- | ---- |
| 数据 | `TopologyMonitor{name, connectionId, displayMode}` 住在 `TopologyDocument::monitors_`，随 `.etopo` 序列化 | 观察配置固化进硬件结构文件 |
| 编辑 | 拓扑编辑器属性面板选连接、选展示方式，改完必须保存 `.etopo`，执行页靠 mtime 重载生效 | 编辑位置太靠前：改观察需求要回拓扑编辑器，不能边看边调 |
| 执行 | 执行页只能"勾选已有监听器"，不能新增/改展示方式 | 执行页是只读消费方 |

本质是分层错误：拓扑回答"有什么信号"（设备/连接/端口 = 信号源结构），监听器回答"观察哪个信号、怎么展示"（运行期/项目级观察配置）。

`.etproj` 目前只有 `{version, name, create_time, settings}`，完全闲置，可承载监听器。

## 2. 架构回顾

- `TopologyMonitor{name, connectionId(UUID), displayMode}` 引用 `TopologyConnection.id`（UUID），引擎加载时经 connectionId 解析出 `deviceId + devicePort` 建查表。
- `MonitorManager`（engine 层）：`loadFromTopology` 构建 `lookup_table_`（key=(deviceId,portName)，值 `MonitorTapInfo{monitorIndex, deviceId, devicePort, displayMode}`）、`tree_cache_`、`buffer_`（key=monitorIndex int）。
- 执行链路：`onHardwareOpFinished(deviceId, portName, ...)` → 查表 → 写 `buffer_` → 30fps 定时器批量推送 `subscribers_` → 可视化组件 `onSampleCaptured`。
- `monitorIndex`（int 数组下标）被当作 key 用在全链路：`subscribers_` / `buffer_` / `lookup_table_` / `VisualizationArea` / `SignalTreePanel` / `flushSamples` 报告分组。
- 执行页 UI：ribbon「通道选择」→ `SignalTreePanel`（扁平 checkbox 列表，只能勾选显示/隐藏）。
- `.etproj`：`src/core/project/ProjectInfo`，`toJson/fromJson` 读写 `{version, name, create_time, settings}`。
- CLI 工具 `test-executor` / `test-executor-cli` 也调用 `TestExecutionEngine::loadTopology` → `MonitorManager::loadFromTopology`，无项目上下文。
- 模块约束：`etest_core` 是底层，不能被 `etest_topology` / `etest_app` 反向依赖；core 只做通用 JSON 透传。

## 3. 决策记录

### 决策 1：存储载体 —— `.etproj` 内嵌 `monitors` 数组

选项：A `.etproj` 内嵌数组 / B 独立文件 `monitors.json` / C 塞进 `settings_` QVariantMap。

选定 A。`.etproj` 极小，加一个数组即全部改动；与项目同生命周期、单文件原子保存、Git 版本管理天然覆盖。分层上 `ProjectInfo` 把 monitors 当不透明 JSON 透传（`QJsonArray` get/set），不引入 topology 类型依赖。

### 决策 2：身份标识 —— 全链路改用 `QUuid`

选项：A int 会话句柄 + 持久 UUID / B 全链路 QUuid / C 禁止删除。

选定 B。监听器以 `connectionId`(UUID) 为身份与运行时 key（一连接一监听器，决策 17），`subscribers_`/`buffer_`/`VisualizationArea`/报告全部以 `connectionId` 为 key；`SignalTreePanel` 整体废弃（双栏重构替代，不迁移）；`lookup_table_` 的 key 保持 `(deviceId, portName)`（硬件按设备端口查表），仅其条目 `monitorIndex` 改 `connectionId`。杜绝数组下标漂移（执行页增删后其他监听器错位）。代价：波及 engine + app + 全部 visualizer + 报告序列化，属较大改动面，接受。

### 决策 3：迁移策略 —— 硬切，不迁移存量拓扑监听器

选项：A 自动迁移一次 / B 双轨兼容 / C 硬切。

选定 C。学习型项目，兼容成本不值；拓扑中的 `monitors` 段彻底移除（不再写、不再读），`TopologyDocument::monitors_` 及相关 UI 清理删除。

### 决策 4：执行页 UI —— 升级「通道选择」对话框为监听器管理器

选项：A 升级通道选择对话框 / B 侧边常驻面板 / C 空态引导 + 右键菜单。

选定 A。重构为双栏监听器配置对话框（左连接列表 + 右 visualizer 平铺，决策 15/16）。侧边常驻面板留作后续迭代。

### 决策 5：写回时机 —— 增删改即写回 `.etproj`

选项：A 改动即写回 / B 跟随项目保存 / C 关闭项目时写。

选定 A。`.etproj` 极小，写回成本可忽略；监听器是执行页高频操作对象，自动保存最省心、无丢失风险。

### 决策 6：失效处理 —— 保留 + 列表标记无效

选项：A 保留 + 标记无效 / B 自动删除失效项 / C 保留但静默。

选定 A。拓扑删连接/改端口后，`.etproj` 中引用失效的监听器保留，列表灰色 + 警示图标，不订阅不显示；**仅可删除**（连接已没，重指信号源 ≈ 新建，直接配新连接即可，见决策 17 一连接一监听器）。上次 gauge 不显示的教训是"配置失效但没人知道"，必须把失效状态暴露出来。

### 决策 7：单拓扑 —— 既定决策，沿用

执行页仍只加载 `topology/topology.etopo` 单文件，`.etproj` 监听器无需携带拓扑归属。

### 决策 8：信号源 —— 选连接

创建监听器时从拓扑连接列表选择（展示 `device.port` + functionType），存储 `connectionId`(UUID)。复用现有解析链（connectionId → deviceId+portName）；UUID 稳定，设备/端口改名经连接同步不失效；失效检测干净（连接删了 → 标无效）。

### 决策 9：映射 —— 一监听器一信号一可视化（1:1）

保持现状，不做一监听器多信号。多信号叠图（如波形多迹线叠加）是"可视化面板组合"层次的需求，留后续迭代。

### 决策 10：创建行为 —— 创建即所见

在右栏点选类型后自动勾选并立即创建可视化组件（未运行则显示空态），同时写回 `.etproj`。

### 决策 11：拓扑编辑器 —— 彻底移除

拓扑编辑器移除全部监听器痕迹（连接徽标 / outline 分类 / 粘贴 / 撤销命令），完整清单见 4.8。topology 模块不反向读 `.etproj`。

### 决策 12：CLI 工具 —— 一并硬切

`test-executor` / `test-executor-cli` 删除监听采样与监听报告能力（`.etlog` 不再输出 `monitors[]` 段），`MonitorManager::loadFromTopology` / `appendFromTopology` 连带删除。避免"拓扑为 CLI 保留监听数据写入"与硬切自相矛盾。

### 决策 13：拓扑重载 —— 自动重订阅

拓扑 mtime 变更重载后，自动重订阅仍有效的已勾选监听器（QUuid 稳定，可视化 key 对上重载后的监听器）；失效的标无效并移除对应可视化。避免改拓扑保存后执行页显示全断、需重勾。

### 决策 14：标题 —— 两级（主标题自定义 + 二级标题连接描述）

监听器带 `name`（主标题，用户自定义，默认取连接描述）；二级标题 = 连接描述，运行时由 `connectionId` 解析、不落盘。5 个 visualizer 组件顶部标题栏支持两行（主 + 副）。

### 决策 15：对话框交互 —— 双栏管理器

`ChannelSelectionDialog` 重构为双栏：左栏全部拓扑连接列表（已配置的绿色 + 加粗、checkbox = 执行页显示/隐藏、底部「失效监听器」分组灰显可删除）；右栏 `QScrollArea + QGridLayout` 平铺 5 种 visualizer 真实空态实例（创建一次复用）。交互：点类型 = 配置/切换（创建即所见），再点已选类型 = 取消配置（删除监听器）；选中连接已配类型描边高亮。取代原「添加/编辑/删除按钮 + 新建弹窗」方案。主标题编辑 = 双击已配置通道重命名。

### 决策 16：对话框命名 —— `MonitorConfigDialog`

`ChannelSelectionDialog` 重命名为 `MonitorConfigDialog`（文件 `src/app/dialogs/MonitorConfigDialog.h/.cpp` + CMake + `ExecutionPanelController` 引用同步），窗口标题「通道选择」→「监听器配置」。与 engine `MonitorManager` 词根一致、后缀区分。

### 决策 17：连接约束 —— 一连接一监听器

一个连接至多一个监听器（`connectionId` 唯一）。理由：与双栏交互（点类型=赋/切换、再点=删）完全一致，数据模型最简。想看同信号多视图可另配同源其他连接。

### 决策 18：对话框模态 —— 非模态

`MonitorConfigDialog` 用 `show()` 非模态打开，与执行页并存，配置后立即看到可视化区变化（真正"创建即所见"）。对话框随项目关闭 / 执行页切换关闭，不常驻。

## 4. 实现方案

### 4.1 数据模型

`.etproj` 增加 `monitors` 数组，每项：

```json
{
  "connectionId": "8e1d…（拓扑连接 UUID，即监听器 key）",
  "name": "油压监测",
  "displayMode": "gauge"
}
```

- `displayMode` 取值范围：`waveform / led / meter / frame / gauge`，创建时显式选择（默认 waveform），**不支持 auto**（避免上次"选了仪表出不来"的隐性失效）。
- `name` 为主标题（用户自定义，默认取连接描述，决策 14）；二级标题 = 连接描述，运行时由 `connectionId` 解析、不落盘。
- `signalType` 不落盘：运行时由 connection 解析出的设备端口 `functionType` 提供，仅用于可视化标题/兜底。

### 4.2 `ProjectInfo`（core）扩展

`ProjectInfo` 增加 `QJsonArray monitors()` / `setMonitors(QJsonArray)`，`toJson` 写 `obj["monitors"]`，`fromJson` 读。不校验结构、不依赖 topology 类型（不透明 JSON 透传），保持 `etest_core` 无反向依赖。

写回通道：`ProjectManager::currentProject()` 返回 const 指针，不能 `setMonitors`。新增显式入口 `ProjectManager::setMonitors(const QJsonArray& monitors)` —— 更新当前 `ProjectInfo` 并立即 `saveProject()` 落盘，供 4.5 增删改后调用。

### 4.3 `MonitorManager`（engine）改造

- `MonitorTapInfo`：`int monitorIndex` → `QUuid connectionId`（监听器 key = 连接 UUID，决策 17）。
- `MonitorSample`：`int monitorIndex` → `QUuid connectionId`。
- `subscribers_` / `buffer_` 的 key 由 int 改为 `connectionId`(QUuid)；`lookup_table_` 的 key 保持 `(deviceId, portName)`（`onHardwareOpFinished` 按设备端口查表），仅条目 `monitorIndex` → `connectionId`。
- `subscribe(QUuid, cb)` / `unsubscribe(QUuid)` / `displayMode(QUuid)` / `onFlushTimer` / `flushSamples` 同步改。
- 新增 `loadMonitors(const QJsonArray& monitors, const QJsonObject& topologyDoc)`：
  0. 开头 `clearStructure()` + `clearRuntime()`（清 `lookup_table_`/`tree_cache_`/`subscribers_`/`buffer_`/`history_buffer_`/`invalid_ids_`），保证多次调用幂等（决策 13 重载依赖）；
  1. 遍历 monitors，解析 `connectionId`；
  2. 在 `topologyDoc.connections` 中查找该连接 → 得 `deviceName + devicePort`；
  3. 在 `topologyDoc.devices` 中按 name 查设备 → 取 `device.id`（UUID）、`device.deviceType`；再按 port name 在 `devices[].ports[]` 取 `functionType`（供右栏展示与可视化标题，决策 8）；
  4. 构建 `lookup_table_`（key=(deviceId, devicePort)）与 `tree_cache_`；
  5. `connectionId` 在拓扑中不存在 → 该监听器标记无效（`invalid_ids_` 集合），**仍进 `tree_cache_`（灰显、不可勾选、`invalid=true`），不进 `lookup_table_`**，不订阅不显示。
- `MonitorTreeEntry` 增 `QString displayMode` + `bool invalid`（key 即 `connectionId`，无需独立 monitorId；双栏左栏连接↔监听器映射直接用 connectionId，审查 🟡3）。
- **删除 `loadFromTopology` / `appendFromTopology`**（决策 12 CLI 硬切后无消费方，存量单测同步迁移）。`loadMonitors` 直接复用其解析链（connectionId → deviceName+devicePort → device.id/deviceType，审查 B4 确认可行性）。

### 4.4 `TestExecutionEngine`（engine）

`loadTopology` 移除 `monitor_manager_->loadFromTopology(root)` 调用（只加载设备/Mock）。监听器加载改由 `ExecutionPanelController` 在拓扑加载成功后触发（见 4.5）。`topology_doc_` 保留并新增 `const QJsonObject& topologyDoc() const` getter，供 `loadMonitors` 解析连接、对话框右栏读端口 functionType。`clearTopologyState()` 中提及 monitors 的注释同步更新。

### 4.5 监听器管理器对话框 + `ExecutionPanelController`（app）改造

现状：`src/app/dialogs/ChannelSelectionDialog` 已是独立类（持有 `SignalTreePanel`，转发 `setMonitorTree`/`uncheckMonitor`/`clearTree`，勾选经 `checkStateChanged(int, bool)` 对外）；编排在 `ExecutionPanelController::onChannelCheckStateChanged`（创建/移除可视化 + subscribe/unsubscribe）。改造在此结构上重命名并重构为双栏管理器（决策 15/16）。

**对话框布局（重构 `MonitorConfigDialog`，原 `ChannelSelectionDialog`）**
- 左栏 `QListView`：顶部搜索框（按连接描述模糊过滤，沿用原 SignalTreePanel 的搜索交互）；列表为全部拓扑连接（连接描述 `device.port ↔ UUT.port`），**checkbox = 执行页显示/隐藏，仅已配置的通道显示 checkbox**（未配置连接无 checkbox，配置后出现并默认勾选=创建即所见，取消配置后消失）；已配置监听器的通道绿色 + 加粗；底部固定「失效监听器」分组（灰显主标题 + 「连接已删除」，选中可删除，决策 10）。
- 右栏 `QScrollArea + QGridLayout`：5 种 visualizer 真实实例（空态、无数据），对话框创建一次复用；点某实例 = 给当前选中连接赋/切换该类型（决策 10 创建即所见），再点已选类型 = 取消配置（删除监听器）；当前连接已配类型以 QSS property 描边高亮。
- 主标题编辑：双击已配置通道重命名主标题（决策 14 两级标题）；二级标题 = 连接描述，运行时由 `connectionId` 解析。
- 非模态（决策 18）：`show()` 打开，与执行页并存，配置后立即看到可视化区变化；对话框随项目关闭 / 执行页切换关闭，不常驻。
- 执行页可视化区右键「关闭可视化」= 取消勾选（保留 `.etproj` 配置，`visualizerClosed(QUuid)` 同步左栏 checkbox），不删除监听器。
- 对外交互信号（编排留 controller），key 统一为 `connectionId`：`channelSelected(QString connectionId)` / `visualizerChosen(QString connectionId, QString displayMode)` / `checkToggled(QUuid connectionId, bool)` / `renameRequested(QUuid connectionId, QString name)` / `deleteRequested(QUuid connectionId)`。

**`ExecutionPanelController` 槽**
- `onChannelSelected`：右栏高亮该连接已配类型（无则不高亮）。
- `onVisualizerChosen(connectionId, displayMode)`：该连接已有监听器 → 改 displayMode 并同步重建可视化；无 → 用该 `connectionId` 新建监听器（key = connectionId，无需另生成 UUID）、调 `MonitorManager` 建查表、写回 `.etproj`、自动勾选并创建可视化。批量 `loadMonitors` 之外需新增单条增量接口 `MonitorManager::addMonitor(entry, deviceId, devicePort, functionType)`（含对应的查表 / `tree_cache_` 增量）。
- `onCheckToggled`：订阅/取消订阅 + 建/撤可视化（沿用现有 `onChannelCheckStateChanged` 逻辑，QUuid 化）；删除 `mode.isEmpty() → "auto"` 兜底（创建时显式选展示方式）；波形取色 `kColors[monitorIndex % 8]` 改 UUID hash 或自增分配。
- `onRenameRequested`：改主标题、写回、同步可视化标题。
- `onDeleteRequested`：移除查表 + 订阅、移除可视化、从 `.etproj` 删除。
- 无拓扑/无连接时右栏禁用，提示先加载拓扑。
- `syncProjectTopologies()` 拓扑加载成功后：取 `ProjectManager::currentProject()->monitors()` 数组，连同引擎 `topologyDoc()` 调 `monitor_manager_->loadMonitors(...)`，再 `refreshMonitorTree()`。
- 拓扑 mtime 重载路径（决策 13）：顺序 `clearMonitorState → loadTopology → loadMonitors → 依 VisualizationArea::activeChannels()(QUuid) 对仍有效的已勾选监听器自动重订阅 → 刷新左栏`；失效的标无效并移除可视化。已勾选来源唯一 = `activeChannels()`（勾选态不落盘）。**`clearMonitorState` 仅清引擎侧订阅/缓冲，不清 `VisualizationArea`**（勾选态即可视化区持有），否则重载后 `activeChannels()` 恒空、自动重订阅静默失效。
- 每次增删改后立即 `ProjectManager::setMonitors(...)` 写回（决策 5）。写回失败仅日志告警、不阻塞 UI。

### 4.6 失效监听器呈现（决策 6 + 决策 10）

`MonitorManager` 对 `connectionId` 在拓扑中不存在的监听器标记无效：不进 `lookup_table_`、不订阅。`MonitorTreeEntry` 增 `QString displayMode` + `bool invalid`（key 即 `connectionId`），支撑左栏连接↔监听器映射与失效分组。对话框左栏底部「失效监听器」分组灰显（主标题 + 「连接已删除」），选中仅可删除（决策 6/17）。

### 4.7 可视化组件（app）改造

全部 `SignalVisualizer` 子类 `displayedSignals()` 返回 `QList<QUuid>`（值为 `connectionId`）；`onSampleCaptured` 记录 `sample.connectionId`；`WaveformWidget::addTrace`、`clearData` 同步；Gauge/DigitalMeter/StateLED/ValueLabel 的 `int monitor_index_` → `QUuid connection_id_`。`VisualizationArea` 的 `addVisualizer/removeVisualizer/visualizer/activeChannels/visualizerClosed` key 全部 int → `connectionId`(QUuid)。

标题改造（决策 14）：5 个 visualizer 组件顶部标题栏支持两行——主标题（monitor.name，可编辑）+ 二级标题（连接描述）。各组件增加 `setTitle(const QString&)` / `setSubtitle(const QString&)` 接口（当前标题仅构造传入，无 setter），供 `onRenameRequested` 同步；4.5 右栏预览实例用空态标题（如「波形」「LED」）。

左栏连接列表：废弃原 `SignalTreePanel`（监听器勾选列表，含死代码 `updateNodeValue`），由新的连接列表控件替代（QListView + 分组）。`MonitorConfigDialog`（原 `ChannelSelectionDialog`）重构为双栏（见 4.5），其旧 `setMonitorTree`/`uncheckMonitor`/`checkStateChanged` int 接口随重构废弃。

`ExecutionPanelController.cpp:1041` 的 `kColors[monitorIndex % 8]` 依赖 int 取色，改 UUID 后改为按 UUID hash 取色或自增分配。

### 4.8 拓扑/相关模块监听器残留清理（硬切全删）

删除 `TopologyMonitor` 结构体前先移除全部消费者，完整清单：

- `src/topology/TopologyDocument.h/.cpp`：删 `monitors_`、monitor 增删改查、`monitorAdded/Removed/Changed` 信号。
- `src/topology/TopologyJsonSerializer.cpp`：不再读写 `monitors` 段；**从反序列化 `arrayKeys` 硬校验必需键中移除 `"monitors"`**（否则新拓扑无法重新打开）。
- `src/topology/PropertyPanelWidget.cpp`：删监听器编辑 UI（displayMode 下拉等）。

## 5. 边界与不做

- 不做侧边常驻监听器面板（决策 4，留后续迭代）。
- 不做显示模式 auto 推断（创建时显式选择）。
- 不做监听器跨会话勾选状态恢复（checkbox 状态会话内有效，不落盘）。
- 不做监听器分组/排序 UI。
- 不迁移存量 `.etopo` 监听器（决策 3）。
- `ProjectInfo` 不解析 monitors 结构（不透明 JSON 透传，保持 core 纯净）。
- CLI 不再输出监听报告（决策 12）。
- 一连接一监听器（connectionId 唯一，决策 17）。
- 监听器编辑支持改主标题 / 展示方式；失效监听器仅可删除（决策 6）。
