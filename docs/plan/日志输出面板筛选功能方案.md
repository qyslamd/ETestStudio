# 日志输出面板筛选功能方案

## 背景与目标

page0 底部「输出」面板（`LogOutputPanel`）当前为纯追加式日志显示：spdlog 实时流经
`QtConsoleSink::logMessage` 信号 → `appendLog` → `QTextEdit::append(html)`，仅着色整行，
无任何过滤、查找、滚动锁定能力。日志量大时无法快速定位问题。

参考 VS Code 输出面板、IDEA Run Console、Chrome DevTools Console 的共性能力，为
`LogOutputPanel` 增加筛选与滚动锁定，提升排障效率。

## 现状

### 数据流

```
spdlog 工作线程
  └─ QtConsoleSink::sink_it_ ── push ──▶ LogHistoryBuffer (环形 5000)
                                          │
                                          │ drain() 一次性回放（drained_ 幂等）
                                          ▼
  QtConsoleSink::logMessage 信号 ──────▶ MainWindow.cpp:955 connect
                                          │
                                          ▼
                                    LogOutputPanel::appendLog
                                          │
                                          ▼
                                    QTextEdit::append(html)
```

关键点：

- `LogHistoryBuffer` 仅负责「启动期到面板构造之间」的历史回放，`drain()` 调一次后
  `drained_=true`，之后 `push` 进来的实时日志**不再**通过 `drained` 信号下发。
- 实时日志走 `QtConsoleSink::logMessage` 信号，`appendLog` 收到即渲染，**不缓存源数据**。
- 现有 `appendLog` 直接操作 `QTextEdit` 文档，无法按筛选条件重渲。

### 现有代码位置

| 文件 | 说明 |
|---|---|
| `src/app/widgets/LogOutputPanel.h/.cpp` | 面板本体，`QTextEdit` + `appendLog`（内联 block 裁剪） |
| `src/core/logger/LogHistoryBuffer.h/.cpp` | 环形缓冲，`LogEntry{int level; QString text;}` |
| `src/core/logger/Logger.cpp` | `qtHistoryBuffer()` / `QtConsoleSink` 创建 |

### 死代码

`LogOutputPanel::levelName()` 定义后无调用方（`appendLog` 仅着色整行，level 前缀由
spdlog formatter 自带）。本方案落地时删除。

## 设计

### 范围

仅改造 page0 `LogOutputPanel`。page1 `ExecutionOutputPanel`（运行结果，PASS/FAIL 语义）
本方案不动，后续若需要可复用 `LogFilterBar` 组件。

### 能力清单

| 能力 | 说明 |
|---|---|
| 文本包含过滤 | 输入框关键字匹配，300ms 防抖 |
| 正则模式 | 过滤框旁正则开关，开启后按 `QRegularExpression` 匹配 |
| 大小写敏感 | 正则/普通模式均支持大小写开关 |
| 级别多选过滤 | DEBUG/INFO/WARN/ERROR/FATAL 5 个 checkable 按钮，默认全选 |
| 命中高亮 | 命中片段黄底黑字（`#FFD700`/`#000`） |
| 滚动锁定 | 锁定后新日志不自动滚到底，便于阅读历史 |
| 清空 | 一键清空当前显示 |

### 架构：自建条目缓存 + 按筛选重渲

`QTextBlock` 无 `setVisible` API，无法直接隐藏某些行。采用「缓存源数据 + 按筛选重渲」
方案：

- `LogOutputPanel` 内部新增 `QList<etest::core::logger::LogEntry> entries_` 作为唯一数据源。
- `appendLog` 改为：先 `entries_.append(...)`，再按当前筛选条件决定是否渲染命中项。
- `onHistoricalLogs` 改为：塞进 `entries_` 后批量渲染命中项。
- `entries_` 自带 5000 环形裁剪（与 `LogHistoryBuffer` 容量对齐）。现有 `appendLog`
  内联了对 `QTextEdit` 文档做 block 裁剪的逻辑（`LogOutputPanel.cpp:49-57`），改造后该
  职责移至 `entries_` 环形裁剪，内联裁剪代码随 `appendLog` 重写而移除。
  > 注：`trimToMaxLines()` 是 `ExecutionOutputPanel` 的方法，不在 `LogOutputPanel`，
  > 勿混淆。
- 筛选条件变化：`text_edit_->clear()` + 遍历 `entries_` 重渲命中项，输入框 300ms 防抖。

> 由于 `LogHistoryBuffer` 是一次性 drain 设计，实时日志只来一次即丢，`entries_` 缓存是
> 必须的，否则切换筛选条件无法重渲。

### 筛选模型

纯数据结构，与 UI 解耦：

```cpp
struct LogFilter {
  QString text;                 // 过滤文本（普通模式为字面量，正则模式为正则表达式）
  bool useRegex = false;        // true=正则匹配，false=字面量包含
  bool caseSensitive = false;   // 大小写敏感
  QSet<int> enabledLevels;      // 启用的级别集合（spdlog::level::level_enum 强转 int）

  bool matches(int level, const QString& text) const;
};
```

级别选择语义：**不允许取消最后一个勾选项**（点击最后一个已勾选的级别按钮时不响应
uncheck），参考浏览器 DevTools。这样避免「全不选却显示全部」的反直觉行为，UI 状态与
显示结果始终一致。`enabledLevels` 恒非空，`matches` 的级别判断恒为「level ∈ 集合」。

#### LogOutputPanel 改造

布局变化：

```
QVBoxLayout
├─ LogFilterBar    （新增，顶部）
└─ QTextEdit       （原有）
```

成员变化：

```cpp
// 新增
QList<etest::core::logger::LogEntry> entries_;   // 唯一数据源
LogFilter current_filter_;                        // 当前筛选条件
LogFilterBar* filter_bar_ = nullptr;
QTimer* debounce_timer_ = nullptr;                // 过滤输入防抖
bool scroll_locked_ = false;
static constexpr int kMaxEntries = 5000;          // 与 LogHistoryBuffer 对齐

// 删除
// QString levelName(int) const;  （死代码）
// appendLog 内联的 block 裁剪逻辑（随 appendLog 重写移除，职责转给 entries_ 环形裁剪）
```

方法变化：

| 方法 | 改造 |
|---|---|
| `appendLog(int, QString)` | push 进 `entries_`（超限裁剪）→ 命中筛选才 `renderEntry` → 非锁定才滚底 |
| `onHistoricalLogs` | 塞 `entries_` 后 `applyFilter` 全量重渲 |
| `clearLog` | `entries_.clear()` + `text_edit_->clear()` |
| `applyFilter`（新增） | 记录 `was_at_bottom` -> `clear()` + 遍历 `entries_` 调 `renderEntryNoScroll` -> 仅 `was_at_bottom && !scroll_locked_` 才滚底 |
| `renderEntry`（新增） | 单条渲染：着色整行 + 命中片段高亮 span，末尾按 `scroll_locked_` 决定滚底（实时单条用） |
| `renderEntryNoScroll`（新增） | 同 `renderEntry` 但不滚底（`applyFilter` 批量重渲用，避免 5000 次冗余滚动） |
| `requestFilterApply`（新增） | 防抖入口，`debounce_timer_` 300ms 后调 `applyFilter` |

信号连接（`initSignals`）：

- `filter_bar_::filterChanged` → 更新 `current_filter_` + `requestFilterApply`
- `filter_bar_::scrollLockChanged` → `scroll_locked_ = locked`
- `filter_bar_::clearRequested` → `clearLog`

### 高亮实现

命中片段用 `<span style="background:#FFD700;color:#000">` 包裹。渲染流程：

1. 整行文本先 `toHtmlEscaped()` 防注入。
2. 根据模式定位命中区间：
   - 普通模式：`indexOf` 循环（受 `caseSensitive` 控制 `Qt::CaseSensitivity`）。
   - 正则模式：`QRegularExpression::globalMatch` 遍历（pattern 受 `caseSensitive` 控制
     `CaseInsensitiveOption`）。
3. 按命中区间分段拼接 HTML：未命中段用级别色 `<span>`，命中段外加高亮 `<span>`。
4. `text_edit_->append(html)`。

正则非法时（`QRegularExpression::isValid()` 为 false）退化为「不过滤文本，仅级别过滤」，
并给两重视觉提示：
1. 过滤框红色边框（QSS `#LogFilterBox[invalid="true"]` 属性选择器控制）。
2. 过滤框 `setToolTip` 设为 `QRegularExpression::errorString()`，hover 即可看到具体错误
   原因（如「unexpected end of pattern」）。

正则合法或非正则模式时清除 `invalid` 属性与 tooltip。

### 滚动锁定

`scroll_locked_` bool，由 `LogFilterBar::scrollLockChanged` 驱动。滚动策略分两种场景：

**实时单条 append（`appendLog` -> `renderEntry`）**：

```cpp
// renderEntry 末尾
if (!scroll_locked_) {
  QScrollBar* bar = text_edit_->verticalScrollBar();
  bar->setValue(bar->maximum());
}
```

**全量重渲（`applyFilter`）**：重渲前记录用户是否已在底部，重渲期间禁用 per-entry 滚动
（避免 5000 次冗余 `setValue`），循环结束后仅在「用户原本在底部」时滚底，否则保留原
滚动位置：

```cpp
void applyFilter() {
  QScrollBar* bar = text_edit_->verticalScrollBar();
  bool was_at_bottom = bar->value() >= bar->maximum() - 2;  // 容差 2px

  text_edit_->clear();
  for (const auto& entry : entries_) {
    if (current_filter_.matches(entry.level, entry.text)) {
      renderEntryNoScroll(entry);  // 不触发滚底
    }
  }

  // 仅当用户原本在底部时才跟随滚底；否则保留原位置（相对顶部偏移尽量不变）
  if (!scroll_locked_ && was_at_bottom) {
    bar->setValue(bar->maximum());
  }
}
```

> 关键：全量重渲不能无条件拉到底--用户正阅读历史时改筛选条件，视图被一把拉到底是
> 体验问题。`was_at_bottom` 判断保证「原本跟着新日志走的人才继续跟，看历史的人不被
> 打断」。

锁定时新日志照常进 `entries_` 和文档（若命中筛选），只是不顶走视图。用户手动滚动不受
影响。

### 性能

- 实时每条：`entries_` append + 单条 `renderEntry`，O(1)，无问题。
- 全量重渲：5000 行 clear + append，实测约几十 ms；叠加 300ms 防抖，可接受。
- 高频日志场景若出现卡顿，后续可加 100ms 批量合并（多条日志攒一批再渲染），MVP 不做。

## 落地步骤

便于逐步审查与验证，按以下顺序分阶段实施：

1. **LogFilterBar 组件**（纯 UI + 信号）- 5 个级别按钮、过滤框、4 个开关按钮，
   `initUi`/`initSignals` 分离。级别按钮点击时拦截「取消最后一个勾选」（P2 语义）。
   QSS 仅写最小可运行样式（控件可见、布局正确），主题打磨留到步骤 5。
2. **LogOutputPanel 加 `entries_` 缓存 + `applyFilter` 重渲**- 先不加高亮，跑通级别多选
   与文本包含过滤。此阶段 `renderEntry` 末尾**总是滚底**（等价现状），`applyFilter` 内
   暂时也总是滚底（滚动优化留到步骤 4）。
3. **加高亮 + 正则 + 大小写**- `renderEntry` 实现命中片段 span，正则非法退化 + 红框 +
   tooltip（P4）。
4. **加滚动锁定 + 重渲滚动优化**- 接入 `scroll_locked_` 与 `filter_bar_::scrollLockChanged`；
   `applyFilter` 改为 `was_at_bottom` 判断 + `renderEntryNoScroll` 拆分（P1）；`renderEntry`
   末尾改为按 `scroll_locked_` 决定滚底。
5. **QSS 样式完善**- `#LogFilterBar` 及子控件在 vscode/default 两套主题下的规则打磨，
   级别按钮按级别着色（`#LevelDebugBtn` 等）。
6. **编译验证**- 全量构建 `ETestStudio`，运行后切到 page0 输出面板验证：
   - 各级别按钮单独/组合过滤生效，最后一个不可取消
   - 文本过滤（普通 + 正则 + 大小写）生效，命中片段高亮
   - 正则非法时红框 + tooltip 显示错误
   - 滚动锁定开关后新日志不顶走视图
   - 改筛选条件时，若用户原本在底部则跟随滚底，否则保留原位置
   - 清空按钮清空显示与缓存
   - 历史日志回放（启动期日志）在面板构造后仍可见
