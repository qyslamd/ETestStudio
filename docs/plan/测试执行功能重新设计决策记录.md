### 决策 4：ExecutionDebugWidget 的职责

**状态**：✅ 已确认

**定位**：**调试器页面**，不是程序选择器，也不是运行管理器。

**当前内容**：
- **顶部概览区**：运行前提状态（分组摘要，默认折叠，展开显示 6 项逐条状态）
- **进度树**：用例/步骤层级执行进度，空闲时保留上次结果，下次运行自动清空
- 不包含底部统计/状态栏

**未来扩展**：
- Lua 调试器集成：变量监视、调用堆栈、断点管理

**它不包含**：
- 测试程序选择列表（那是 `TestProgramManagerWidget` 的事）
- 执行控制按钮（那是 Ribbon 的事）
- 文本日志（那是 `ExecutionOutputPanel` 的事）
- 统计/状态栏（那是 MainWindow statusBar 的事）

### 决策 5：运行程序的入口方式

**状态**：✅ 已确认

**结论**：两个按钮分工明确，覆盖三种使用场景。

```
「运行」按钮:
  有编辑器打开 → 运行当前编辑器中的程序（调试/快速迭代场景）
  无编辑器打开 → 运行 TestProgramManagerWidget 中选中的程序

「运行全部」按钮:
  扫描项目 cases/*.etprog → 逐个执行（不管选中了什么）
```

**入口选择逻辑**（`onRunClicked`）：
```
1. 检查 ExecutionDebugWidget 概览区前提状态 → 有错误则阻断
2. 编辑器有打开 → 从编辑器取程序数据
3. 编辑器没打开 → 从 TestProgramManagerWidget 取选中程序数据
4. 都拿不到 → 提示用户打开或选择测试程序
5. 先切侧边栏到 ExecutionDebugWidget（视觉反馈优先）
6. 再执行 createEngine/setProgram/start
```

**TestProgramManagerWidget 需补充的能力**（最小接口，单选）：
```cpp
// TestProgramManagerWidget 新增
public:
  QString selectedProgramPath() const;  // 返回当前选中项的完整路径，无选中返回空

signals:
  void programSelectionChanged(const QString& filePath);  // 选中项变化时发出
```

**`programSelectionChanged` 消费者**：MainWindow 接收该信号，将选中的程序名称转发到 ExecutionDebugWidget 概览区显示（如"当前程序: 程序A.etprog"）。不进 statusBar。

### 决策 6：Ribbon 执行控制按钮

**状态**：✅ 已确认

| 按钮 | 类型 | 作用 |
|------|------|------|
| 验证 | Large | 运行前检查，刷新 ExecutionDebugWidget 概览区状态 + ProblemsPanel |
| 运行 | Large | 有编辑器 → 跑编辑器中的程序 / 无编辑器 → 跑 TestProgramManagerWidget 选中的程序 |
| 运行全部 | Large | 遍历项目 cases/*.etprog 串行逐个执行，失败跳过继续 |
| 暂停 | Small | 暂停/恢复执行（图标切换：暂停 ↔ 继续） |
| 停止 | Small | 终止执行 |

**已移除**：「运行用例」按钮已删除，`MainWindow::onRunCaseClicked()` 方法体一并清理。

**同步控制**：`syncControlStates()` 根据引擎状态启用/禁用对应按钮。`act_run_all_` 与 `act_run_` 同步（Idle/Finished/Error 时可点，Running/Paused 时禁用）。

**暂停图标切换**：需要新增 `resume_dark.svg` / `resume_light.svg` 图标资源，风格与现有 `pause_dark/light.svg` 一致的 Material play_arrow 图标（`M8 5v14l11-7z`），并注册到 `resource.qrc`。

### 决策 7：运行前提检查

**状态**：✅ 已确认

#### 前提清单（6 项）

1. **项目已打开** — 打开了测试项目
2. **ICD 协议已定义** — 项目定义了 ICD 协议文件
3. **拓扑已定义** — 项目包含拓扑文件
4. **拓扑已绑定信号** — 拓扑中的设备和端口绑定了 ICD 信号
5. **测试程序已编写** — 存在 `.etprog` 文件且包含至少一个用例
6. **硬件已连接或 Mock 已配置** — 设备可用

#### 展示位置

ExecutionDebugWidget 顶部概览区，分组摘要风格：
```
🟢 运行前提: 5/6 满足  [展开▼]
  ✅ 项目已打开
  ✅ ICD 已加载
  ⚠️ 拓扑信号未绑定
  ...（展开后逐条显示）
```

#### 检查时机

自动 + 手动结合：
- **自动**：事件驱动。`ExecutionDebugWidget` 自行监听 `ProjectManager`、`SignalRegistry` 等状态对象信号，状态变化时自动触发检查刷新概览区
- **手动**：Ribbon「验证」按钮强制触发。`ExecutionDebugWidget` 对外暴露 `refreshPreconditions()` 公开槽，MainWindow 在 `onVerifyClicked()` 中调用以强制刷新

**阻断接口**：
```cpp
// ExecutionDebugWidget 新增
public:
  bool canRun() const;  // 返回 true = 无阻断性错误，false = 存在阻断性错误
```
`refreshPreconditions()` 更新内部缓存状态，`canRun()` 读取缓存。`onRunClicked()` 开头直接检查。

#### 阻断策略

硬阻断：错误级别阻断运行（运行按钮禁用 + tooltip），警告级别仅提示不妨碍。

阻断逻辑在 `onRunClicked()` 开头统一校验（选项 B）。

**「运行全部」检查策略**：统一检查一次。执行前检查 6 项前提，通过后串行执行所有程序。加载每个程序时单独判断其有效性（无用例则跳过），不阻断整体流程。

## 整体分层架构

```
Ribbon「运行」              → 控制面（验证 → 运行/运行全部 → 暂停/停止）
侧边栏「执行调试」Widget    → 调试面（运行前提 + 进度树 + 未来 Lua 调试）
底部「输出」ExecutionOutput → 执行详情面（彩色日志，专用于执行）
底部「日志」LogOutput      → 全局日志面（spdlog 着色）
底部「问题」Problems       → 错误列表面
MainWindow statusBar        → 轻量汇总面（引擎状态 + ✅❌⏱ 统计）
```

## 对独立工具的影响

**结论：无影响。**

`tools/test-executor` 和 `tools/test-executor-cli` 是独立可执行程序，不链接 `etest_app`：

| 工具 | 链接依赖 | 是否受影响 |
|------|----------|-----------|
| `test-executor` | etest_engine, etest_core, etest_core_ui, etest_ui | ❌ 不链接 app 层 |
| `test-executor-cli` | etest_engine, etest_core, icd_utility | ❌ 不链接 app 层 |

- `test-executor` 有自己独立的 `MainWindow`（非 `etest::app::MainWindow`），不包含 ExecutionMonitorPanel 等 UI 组件
- `test-executor-cli` 是纯 CLI（`QCoreApplication`），无任何 GUI 控件
- 本次改动未修改引擎层公共 API，引擎数据结构不变
