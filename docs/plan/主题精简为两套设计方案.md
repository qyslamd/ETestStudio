# 主题精简为两套设计方案

## 问题陈述

当前有 13 个主题，每个主题 = 1 个 JSON（调色板）+ 3 个 QSS（main / ribbon / ads），
共 13 JSON + 约 40 QSS 全部注册进 resource.qrc。每次新增 QSS 功能（向导、控件样式）
都要经 inject 脚本/手动同步写入 13 个文件，维护负担重。本设计精简为两套：
`default`（亮）+ `vscode`（暗），删除其余 11 个强调色主题。

## 架构回顾

- 主题数据：`src/app/resources/themes/<id>.json`（`themeId`/`displayName`/`isDark`/
  `ribbonBaseTheme`/`colors`/`editorColors`），全部注册进 `src/app/resource.qrc`。
- 主题渲染：`ThemeManager`（`src/core_ui/`）从资源目录扫描 `*.json` 注册 `palettes_`，
  `availableThemes()` 返回列表；`default` 有兜底保证存在。
- 每个主题的 QSS：`<id>.qss`（主样式）+ `ribbon_<id>.qss`（ribbon 叠加）+
  `ads_<id>.qss`（QADS dock 样式）。`default`（ribbonBaseTheme=2，亮）、
  `vscode`（ribbonBaseTheme=5，暗）各 4 件齐全。
- 自动生成：`gen_themes.py` 以 `vscode.qss` 为暗底生成 5 个亮色主题
  （avocado_green/mocha_brown/hermes_orange/bright_yellow/cyan）；另有 `--widgets`
  注入 QSpinBox/QComboBox 等通用控件样式。
- 注入脚本：`inject_wizard_qss.py` 扫描 themes 目录 `*.json`，把向导 QSS 块写入
  每个主题的 `.qss`。
- 主题切换：`MainWindow` 经 `ThemeManager::themeChanged` 应用；保存的主题 ID 存配置。

## 方案选项及理由

### 保留范围
- **选项 A（选定）**：只留 `default`（亮）+ `vscode`（暗），删除其余 11 个主题的
  JSON + QSS。理由：明暗两套覆盖绝大多数场景；每次 QSS 功能改动从 13 文件降到 2 文件。
- 选项 B 保留一个喜欢强调色主题（共 3 套）：不选（用户确认 2 套够用）。

### 已删主题回退
- **选项 A（选定）**：保存的主题 ID 在 `palettes_` 中不存在时**一律回退 `default`**。
- 选项 B 按明暗回退：不选（用户确认一律 default）。

### 执行顺序
- **选项 A（选定）**：主题精简作为独立任务，先于 Welcome 重设计（Welcome 步骤 6
  QSS 只动 2 个文件）。

## 决策记录

1. 保留 `default`（亮）+ `vscode`（暗），删除 11 个主题：
   avocado_green、bright_yellow、chinese_red、cyan、gold、hermes_orange、indigo、
   klein_blue、lime、mocha_brown、rose_pink。
2. 删除文件（11 × 4 = 44）：`resources/themes/<id>.json`、
   `resources/styles/<id>.qss`、`resources/styles/ribbon_<id>.qss`、
   `resources/styles/ads_<id>.qss`（ads 缺失的主题只删存在的）。
3. `resource.qrc`：摘除上述 44 个条目，仅保留 default/vscode 的 JSON 与
   main/ribbon/ads QSS + 共享 `startup.qss`。
4. `ThemeManager` 回退（审查 🟡1/🟡2）：**必须在 `loadQss()` 与 `current_theme_`
   赋值之前**完成回退检查，且两处都要——构造函数读取配置的 themeId 时、
   `setTheme()` 收到无效 ID 时。统一模式：
   ```cpp
   auto theme = cfg.get<QString>(CONFIG_APPEARANCE_THEME, CONFIG_APPEARANCE_DEFAULT_THEME);
   if (!palettes_.contains(theme)) theme = QStringLiteral("default");
   loadQss(theme);
   current_theme_ = theme;
   ```
   否则 `current_theme_` 残留无效 ID，`MainWindow::onThemeChanged()` 会尝试加载
   已删的 `ads_<id>.qss`。主题切换 UI 的 `availableThemes()` 自然只返回 2 个。
5. `gen_themes.py`（审查 🔵3）：删除「生成 5 个亮色主题」的 themes 列表与生成主循环
   （否则下次运行重新生成已删文件）；`inject_widget_styles()`（QSpinBox/QComboBox 等）
   保留，仅作用于 default/vscode。`--widgets` 开关是否保留在实现时定（两种路径等价
   时删其一）。
   模板文件（审查 🔵4）：`ads_template.qss` 仅被主题生成循环使用、不在 resource.qrc，
   可删或留作参考；`spinbox_template.qss`、`combobox_template.qss` 仍被
   `inject_widget_styles()` 使用，**必须保留**。
6. `inject_wizard_qss.py`：扫描 `*.json` 自动只剩 2 个主题，无需改逻辑；已注入的
   向导块随 default/vscode 保留。
7. 主题切换 UI/菜单：只显示 2 个主题（`availableThemes()` 驱动，自动生效）。
8. 本次精简不碰 Welcome 重设计；后续 Welcome 步骤 6 QSS 只写 default/vscode。

## 详细设计

### 文件与类

| 文件 | 说明 |
|------|------|
| 删除 `src/app/resources/themes/<11 id>.json` | 调色板 |
| 删除 `src/app/resources/styles/<id>.qss` + `ribbon_<id>.qss` + `ads_<id>.qss`（11 主题） | QSS |
| 修改 `src/app/resource.qrc` | 摘除 44 条目 |
| 修改 `src/core_ui/ThemeManager.cpp` | 回退逻辑（不存在 → default） |
| 修改 `src/app/resources/scripts/gen_themes.py` | 移除 5 亮色主题生成（保留 --widgets） |

### 回退实现点（ThemeManager）

两处：构造函数读取配置的 themeId 时、`setTheme()` 收到无效 ID 时，统一在
`loadQss()`/`current_theme_` 赋值前做：
```
if (!palettes_.contains(theme)) theme = QStringLiteral("default");
```
`registerBuiltinPalettes()` 已有 default 兜底，天然安全。`onConfigChanged` 监听
`CONFIG_APPEARANCE_THEME` 改配置时走 `setTheme()`，同样先回退。
