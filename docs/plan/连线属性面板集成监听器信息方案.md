# 连线属性面板集成监听器信息方案

## 问题陈述

在当前代码中，监听器的属性入口存在两条路径：

1. **点击 badge** → `emitMonitorBadgeClicked` → `monitorBadgeClicked` 信号 → `onMonitorBadgeClicked` → `showMonitorProperties`（独立 Monitor 页面）
2. **选中连线** → `showPropertiesFor(ConnectionItem)` → `PageConnection`（连线属性页面）

两条路径相互独立，用户需要来回切换标签页才能同时查看连线和监听器信息。此外，为 badge 点击引入的信号中继（`emitMonitorBadgeClicked`、`badge_click_handled_` 时序标记、`monitorBadgeClicked` 信号、`onMonitorBadgeClicked` slot）增加了架构复杂性。

## 现状架构

```
badge 点击 → emitMonitorBadgeClicked(connIdx, monIdx)
  → badge_click_handled_ = true
  → TopologyScene::monitorBadgeClicked 信号
    → TopologyEditorWidget::onMonitorBadgeClicked
      → scene_->clearSelection()
      → connItem->setSelected(true)     // 选中连线
      → view_->centerOn(connItem)
      → property_panel_->showMonitorProperties(monIdx)  // 独立页面

连线选中 → showPropertiesFor(ConnectionItem)
  → PageConnection（连线信息，无监听器相关内容）
```

## 推荐方案：连线属性面板集成监听器

### 核心思路

**选中连线时，如果该连线有监听器，在 PageConnection 底部嵌入监听器信息区域。** 不再需要独立的 Monitor 入口路径。

`ConnectionItem` 中已有的 `monitor_index_` 字段直接用于定位对应的监听器——`showPropertiesFor` 的 ConnectionItem 分支中通过 `connItem->monitor_index_` 获取关联的监听器索引，无需额外参数传递。

### 新架构

```
选中连线 / 点击 badge → showPropertiesFor(ConnectionItem)
  → 读取 connItem->monitor_index_（已有字段）
  → PageConnection
    → 连线信息（连线源/目标/端口/样式）
    → --- 分割线 ---
    → 监听器信息（如果 monitor_index_ >= 0）
      → 监听器名称（只读或可编辑）
      → 显示模式下拉
      → 删除监听器按钮
```

### 调用者迁移

| 调用者 | 位置 | 当前行为 | 新行为 |
|--------|------|----------|--------|
| 右键添加监听器后 | `TopologyEditorWidget.cpp:600-603` | `showMonitorProperties(cmd->monitorIndex())` | 仅选中连线（`connItem->setSelected(true)`），`showPropertiesFor` 自动触发 |
| 大纲树点击监听器 | `TopologyEditorWidget.cpp:1394` | `showMonitorProperties(mainIndex)` | 查找对应连线，`connItem->setSelected(true)`，`centerOn` |
| badge 点击 | `topology_items.cpp:800` | `sc->emitMonitorBadgeClicked(...)` → slot → `showMonitorProperties` | 移除整个拦截分支，事件穿透到基类 → 选中连线 |
| `onMonitorBadgeClicked` slot | 已移除 | 不再需要 | — |

### 移除的代码

| 组件 | 说明 |
|------|------|
| `ConnectionItem::mousePressEvent` 中 badge 区域拦截 | 移除整个 `if (has_monitor_) { ... }` 分支，事件穿透到 `QGraphicsPathItem::mousePressEvent` |
| `TopologyScene::emitMonitorBadgeClicked()` | 不再需要 |
| `TopologyScene::monitorBadgeClicked` 信号 | 不再需要 |
| `TopologyScene::badge_click_handled_` 标记 | 不再需要 |
| `TopologyScene::mousePressEvent` 中的 `badge_click_handled_` 检测 | 不再需要 |
| `TopologyEditorWidget::onMonitorBadgeClicked` slot 和声明 | 不再需要 |
| `TopologyEditorWidget::connect(monitorBadgeClicked, ...)` | 不再需要 |
| `PropertyPanelWidget::showMonitorProperties()` 方法 | 不再需要 |
| `PropertyPanelWidget` 中的 `PageMonitor` 页面 | `buildMonitorPage()` 整体移除，对应控件迁移到 PageConnection |
| `editing_monitor_index_` 及相关 slots | 迁移到 PageConnection 上下文，通过 ConnectionItem 的 `monitor_index_` 获取 |

### 保留的代码

| 组件 | 保留理由 |
|------|----------|
| `ConnectionItem::paint` 中的 badge 绘制 | 保留 badge 可视化标记 |
| `ConnectionItem::setMonitorState` | 保留 badge 显示状态（设置 `has_monitor_` 和 `monitor_index_`） |
| `ConnectionItem` 中 hover 效果增强 | 新增：`hoverMoveEvent` 检测 badge 区域，`paint` 绘制高亮效果 |
| `TopologyMonitor` 数据模型 | 监听器数据仍然需要 |
| `AddMonitorCommand` / `RemoveMonitorCommand` | 创建/删除监听器仍然需要 |
| `updateMonitorBadges()` | 更新连线 badge 状态不变 |
| `TopologyOutlineWidget::addMonitorItem` | 大纲树显示监听器节点不变 |

### 做法

#### PropertyPanelWidget 改动

`buildConnectionPage()` 中新增监听器嵌入式区域：

```
PageConnection 布局：
  ┌─────────────────────────┐
  │ 连线源: xxx / port      │
  │ 连线目标: xxx (type)    │
  │ 设备端口: ch0           │
  │ 连线样式: [下拉]         │
  ├─────────────────────────┤  ← 分割线
  │ 监听器                  │  ← 仅当 has_monitor 时 visible
  │   名称: Monitor-01      │
  │   显示模式: [下拉]       │
  │   [删除监听器]           │
  └─────────────────────────┘
```

具体：
1. `buildConnectionPage()` 中预先创建监听器控件组（`QWidget` container + name/displayMode/deleteBtn），默认 `setVisible(false)`
2. `showPropertiesFor()` 的 connection 分支中：
   - 设置 `editing_monitor_index_` 为 `connItem->monitor_index_`（如果有监听器）
   - 填充监听器数据，`setVisible(true)` 监听器区域
   - 无监听器时 `setVisible(false)` 并置 `editing_monitor_index_ = -1`
3. `onMonitorDelete()` 和 `onMonitorDisplayModeChanged()` 保留，改用 `editing_monitor_index_` 定位
4. 删除监听器后：刷新 PageConnection，隐藏监听器区域（`setVisible(false)`）

#### ConnectionItem 改动

移除 `mousePressEvent` 中整个 `if (has_monitor_)` 拦截分支，让事件正常传递到 `QGraphicsPathItem::mousePressEvent`。badge 区域的点击会触发连线选中 → `itemSelected` → `showPropertiesFor(ConnectionItem)`，自动显示连线+监听器信息。

#### 大纲树导航改动

`onOutlineNavigate` case 5：
1. 查找监听器对应的连线
2. `connItem->setSelected(true)` + `centerOn`
3. 不再调用 `showMonitorProperties`，由选中连线时 property panel 自动处理

#### 右键添加监听器后

`addMonitorRequested` lambda：
1. 仅选中对应连线（`connItem->setSelected(true)` + `centerOn`）
2. 不再调用 `showMonitorProperties`
3. 属性面板随选中自动切换

### 多监听器问题

当前 `ConnectionItem::monitor_index_` 是单个 `int`，一条连线只关联一个监听器。`updateMonitorBadges` 也只取第一个匹配。这与现有设计一致——右键添加监听器时，每添加一个就在目标连线上创建一个独立 Monitor（已确认的监听器模型）。如需支持一条连线多个监听器，需后续单独设计。

### 选择方案理由

| 方案 | 优点 | 缺点 |
|------|------|------|
| **推荐：集成到 PageConnection** | 无需独立页面、无需信号中继、简化架构 | PageConnection 布局略复杂 |
| 保留独立 PageMonitor | 已实现、改动小 | 两条路径割裂，用户需切换页面 |
| Composite 页面（选 Connection 时同时显示 PageMonitor） | 看起来一体化 | 内部状态管理复杂 |

### 影响评估

- **架构简化**：移除 1 个信号、1 个 slot、2 个方法、1 个状态标记、`mousePressEvent` 中一个分支、`buildMonitorPage` 整个页面
- **用户体验**：选中连线即可看到完整的连线和监听器信息，无需切换页面
- **交互路径缩短**：点击 badge 后直接选中连线，property panel 自动显示监听器信息
- **hover 效果**：可在 `ConnectionItem` 内独立增强，不影响架构
