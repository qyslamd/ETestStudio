# 开发技能树

本文档列出参与本项目开发所需的技能点和推荐学习路径。新人按此清单逐项学习即可上手开发。

---

## 一、基础必备

### C++ 17

项目使用 C++17 标准。需要掌握：

- 类与继承、虚函数、RAII（资源获取即初始化）
- 模板基础（了解即可）
- `auto`、范围 for、`nullptr`、智能指针（`unique_ptr`、`shared_ptr`）
- lambda 表达式（大量用于 Qt 信号连接）
- `std::string` / 容器（vector、map）
- `std::variant` / `std::optional`（icd_utility 模块中使用）
- 异常处理（`try`/`catch`，MSVC 开启 `/EHa` 可捕获 Windows SEH）

学习资源：

- [C++ Primer 第 5 版](https://book.douban.com/subject/25708312/) — 经典入门教材
- [learncpp.com](https://www.learncpp.com/) — 免费在线教程

### CMake

项目使用 CMake 3.19+ + Ninja 构建。需要掌握：

- 看懂 `CMakeLists.txt`：`add_executable`、`add_library`、`target_link_libraries`、`add_subdirectory`
- `CMakePresets.json` 的用法（项目已配好 4 套预设，选择 ninja-debug 即可）
- `find_package` 查找依赖库
- `configure_file` 模板替换（用于生成 run 脚本和版本信息）
- 会执行 `scripts/build_ninja.bat`

学习资源：

- [CMake 官方教程](https://cmake.org/cmake/help/latest/guide/tutorial/index.html) — Step 1-3 即可
- [Modern CMake 简介](https://cliutils.gitlab.io/modern-cmake/)

### Git

版本控制，已配置 `pull.rebase = true`。

需要掌握：

- `clone` / `add` / `commit` / `push` / `pull`
- `rebase` — 项目合并策略，禁止用 `merge`（避免多余 merge commit）
- `log` / `status` / `diff`
- 解决冲突

学习资源：

- [Pro Git 中文版](https://git-scm.com/book/zh/v2) — 前三章即可

## 二、Qt 框架

### Qt 5.14.2 Core / Gui / Widgets

项目的基础 UI 框架。**必须熟练掌握**。

| 知识点 | 项目中用在哪 |
|---|---|
| 信号与槽（Signals & Slots） | 最核心机制，几乎每个类都在用 |
| QWidget 布局（QVBoxLayout、QHBoxLayout、QSplitter） | 所有面板和对话框 |
| QSS 样式表 | 主题切换，所有样式写在 `.qss` 文件中 |
| QTreeView + QFileSystemModel + QSortFilterProxyModel | 文件浏览器面板 |
| QGraphicsView / QGraphicsScene / QGraphicsItem | 拓扑编辑器和 ICD 位图编辑器 |
| QJsonDocument / QJsonObject / QJsonValue | 项目文件、配置文件、拓扑数据、ICD 协议数据 |
| QUndoStack / QUndoCommand | 拓扑编辑器的撤销/重做 |
| QStyledItemDelegate | 拓扑编辑器的属性表格（ComboBox 委托） |
| QClipboard | 复制粘贴功能 |
| QTimer | 定时备份、设备状态轮询 |
| QProcess | 运行外部程序 |
| QSettings（通过 ConfigManager 封装） | 所有配置读写 |

学习资源：

- [Qt 5.14 官方文档](https://doc.qt.io/qt-5.14/)
- 《C++ GUI Qt 4 编程》第 2 版 — 基础概念通用

### Qt 高级模块

| 模块 | 用途 | 需要掌握程度 |
|---|---|---|
| Qt5::Network（QLocalServer、QLocalSocket） | 单实例检测（SingleInstance） | 了解即可 |
| Qt5::Xml | ICD XML 导入 | 了解 |
| Qt5::Svg | SVG 图标渲染 | 了解即可 |
| Qt5::PrintSupport | 打印支持 | 了解即可 |
| Qt5::Test | 单元测试框架 | 了解 `QTest` 基本用法 |

### Qt 插件系统（QPluginLoader）

项目的硬件设备驱动使用 Qt 插件机制加载。

需要了解：

- `Q_DECLARE_INTERFACE` / `Q_PLUGIN_METADATA` 宏
- `QPluginLoader` 加载和卸载插件
- 项目中 IDevicePlugin 接口体系

## 三、项目特有组件

### Qt-Advanced-Docking-System (QADS v3.8.3)

高级停靠窗口系统，项目用它管理编辑器和面板布局（类似 VS Code 的布局）。

需要了解：

- CDockManager / CDockWidget 基本用法
- 编辑器标签页通过 QADS 管理
- 已开启中间点击关闭标签页、拖拽分离等特性

### SARibbon (v2.5.7)

Office 风格 Ribbon 工具栏，项目主窗口的顶部菜单。

需要了解：

- SARibbonBar / SARibbonCategory / SARibbonPanel 层次结构
- 展开/收起模式
- 主题跟随 ThemeManager 自动切换（暗色/亮色）

### QScintilla (v2.11.3)

高级代码编辑器组件。

需要了解：

- QsciScintilla 基本使用
- QsciLexer 语法高亮机制
- 项目已配置多种语言的 lexer（C++、Python、Lua、JSON、XML、YAML、Markdown 等）

### spdlog (v1.17.0)

日志库，通过 Logger 封装使用。

需要了解：

- `LOG_INFO` / `LOG_WARN` / `LOG_ERROR` / `LOG_DEBUG` 宏
- 日志文件位于运行目录下的 `logs/`
- 支持按模块区分日志（"EXPLORER"、"EDITOR"、"\PROJECT" 等）

### Google Test (v1.17.0) + Google Mock

单元测试。

需要了解：

- `TEST()` / `TEST_F()` 宏
- `EXPECT_EQ` / `ASSERT_TRUE` 等断言
- `MOCK_METHOD` 模拟接口（用于插件接口测试）
- 运行测试：`ctest` 或在 VSCode 中点击运行

### Lua 5.4 + sol2 (v3.3.0)

嵌入式脚本引擎，测试用例脚本使用 Lua 编写。sol2 是 C++17 的 Lua 绑定库。

需要了解：

- Lua 基本语法
- sol2 的 `sol::state`、`sol::function` 调用方式
- 项目使用 CMake 自编译 Lua 源码

### pugixml (v1.15)

轻量级 XML 解析库，用于 ICD 协议导入。

需要了解：

- `pugi::xml_document` 加载和解析
- XPath 查询 `pugi::xml_node::select_nodes()`

### nlohmann/json

现代 C++ JSON 库（header-only），用于 icd_utility 模块。

需要了解：

- `nlohmann::json` 的读写、序列化/反序列化
- 项目中 QJsonDocument 和 nlohmann/json 两套 JSON 库并存

### QXlsx (v1.5.0)

Excel 文件读写。

需要了解：

- `Document::write()` / `Document::read()` 基本用法

### libharu (v2.4.6)

PDF 生成。

需要了解：

- `HPDF_NewPage` / `HPDF_Page_ShowText` 等 C API

## 四、设计模式（项目中实际使用）

| 模式 | 项目中的例子 |
|---|---|
| 单例（Singleton） | ConfigManager、ThemeManager、PluginManager、ProjectManager、AppIconProvider |
| 观察者（Observer） | Qt 信号与槽机制，几乎所有类 |
| 工厂（Factory） | EditorFactoryRegistry — 按文件类型创建编辑器 |
| 命令模式（Command） | Topology UndoCommands — 每个操作一个 QUndoCommand 子类 |
| 策略（Strategy） | CrashHandler — 不同平台不同实现 |
| 接口/抽象基类 | IEditor、IPlugin、IDevicePlugin |
| PImpl（指针实现） | ConfigManager、PluginManager、ProjectManager 用 `unique_ptr<Impl>` 隐藏实现 |

不需要刻意学习，在代码中遇到时能识别即可。

## 五、开发工具

### VSCode 开发

推荐 IDE，项目已配好 `.vscode` 配置。

需要安装扩展：

- **CMake Tools** — CMake 集成，选 ninja-debug 预设即可构建
- **C/C++** — IntelliSense、调试
- **clang-format** — 代码格式化（项目使用 Google 风格）
- **Qt VS Tools** — Qt Natvis 调试可视化

### Windows 调试

- **附加到进程**：Ninja 构建不生成 `.sln`，需要在 VS 或 VSCode 中附加到运行中的 `etest_demo.exe` 进程进行断点调试
- **崩溃 dump 分析**：项目使用 `MiniDumpWriteDump`（dbghelp.dll）生成 `.dmp` 文件，配合 `.pdb` 符号文件分析崩溃调用栈
- 详见 `docs/04-参考/RelWithDebInfo构建与崩溃调试指南.md`

### 代码规范

- 使用 `format_code.bat` 自动格式化（clang-format）
- 遵循 Google C++ Style Guide
- Qt 类将 UI 初始化和信号连接分离到 `initUi()` 和 `initSignals()` 函数

## 六、Windows 特有知识

项目深度依赖 Windows 平台特性：

| 特性 | 用途 |
|---|---|
| SEH（Structured Exception Handling） | 崩溃捕获，`__try`/`__except` 捕获访问越界等硬件异常 |
| dbghelp.dll（MiniDumpWriteDump、StackWalk64） | 崩溃 dump 生成和调用栈回溯 |
| ConPTY（CreatePseudoConsole） | 终端面板的 Windows 伪终端实现 |
| .rc 资源文件 | 嵌入版本信息到 EXE |
| 环境变量 QT5_DEFAULT_SDK_PATH | Qt SDK 路径，CMake 通过此变量查找 Qt5 |

## 七、领域知识

项目面向航空/工业总线测试，需要了解以下概念（在需要接触对应模块时学习即可）：

| 领域 | 涉及的模块 | 说明 |
|---|---|---|
| ICD（Interface Control Document） | src/protocal/、src/icd_utility/ | 接口控制文档，定义信号在数据帧中的位级布局（起始位、位宽、值类型） |
| ARINC 429 | 设备插件 | 航空电子数据总线（Label、SDI、数据字段） |
| MIL-STD-1553 | 设备插件 | 军用航空总线 |
| CAN / FlexRay | 设备插件 | 汽车/工业总线 |
| AD/DA 转换 | 设备插件 | 模数/数模转换 |
| 硬件拓扑建模 | src/topology/ | UUT（被测单元）、Device、Port、Connection、Monitor/Tap |
