# 拆解 EPH435的硬件资源和ICD建立联系的过程

## app.config 配置文件

1. 在<appSettings>分组中，建立了UUT（被测设备）和激励设备在物理上连线的关系。即信号通路
   ```xml
    <add key="ISI-01#A429_IN1" value="6272T_00" />
    <add key="ISI-01#A429_IN2" value="6272T_01" />
    <add key="ISI-01#A429_IN3" value="6272T_02" />
    <add key="ISI-01#A429_IN4" value="6272T_03" />
    <add key="ISI-01#A429_OUT" value="6272T_00" />
    <add key="ISI-02#A429_IN1" value="6272T_08" />
    <add key="ISI-02#A429_IN2" value="6272T_09" />
    <add key="ISI-02#A429_IN3" value="6272T_10" />
    <add key="ISI-02#A429_IN4" value="6272T_11" />
    <add key="ISI-02#A429_OUT" value="6272T_08" />
   ```
   ISI-01(被测设备01)的A429_IN1(被测设备的数据传输通道1)这个数据传输通道对应的是 6272T_00，6272T 是一个硬件资源，后边的 _ 是分隔符，后边的 00 是通道号。

   A429_OUT 和 A429_IN1 都映射到 6272T_00——说明同一张卡同时处理该产品的收/发，或者说 OUT 和 IN1 共用硬件通道 0。

2. 在<appSettings>分组中，配置了 写入信号表和读取信号表的配置文件的路径
   ```xml
    <add key="WtSignalKeyValuePath" value="\ConfigFiles\信号KeyValue工装发送.csv" />
	<add key="RdSignalKeyValuePath" value="\ConfigFiles\信号KeyValue工装接收.csv" />
   ```
   对于这两个csv来说，它的作用是：友好信号名 ↔ ICD XML节点名 的翻译层
   `A429_IN4(317) LABEL,Magnetic_Track_Angle_LABEL,磁航迹角_LABEL,航迹角_LABEL`其实代表的意思：
   第一个是XML文件中配置的信号名称：A429_IN4(317) LABEL
   后边的都是它的不同的名字，别名。即 :
   - Magnetic_Track_Angle_LABEL = A429_IN4(317) LABEL
   - 磁航迹角_LABEL = A429_IN4(317) LABEL
   - 航迹角_LABEL = A429_IN4(317) LABEL
   
   都是在说同一个东西！


3. 在<device.list>分组中，配置了硬件资源及其通道号在操作系统中的资源位置，通常用于连接设备
   ```xml
   <add key="6272T_00" value="6272T_00::EPH6272T::PXI6::2" />
	<add key="6272T_01" value="6272T_01::EPH6272T::PXI6::2" />
	<add key="6272T_02" value="6272T_02::EPH6272T::PXI6::2" />
	<add key="6272T_03" value="6272T_03::EPH6272T::PXI6::2" />
    <add key="1033" value="1033::EPM6200::PXI3::4::0" />
	<add key="1173" value="1173::EPM6200::PXI3::4::1" />
   ```
   特殊的：
   ```txt
   # PXI板卡
    6272T_00 = 6272T_00::EPH6272T::PXI6::2
                {资源名}::{型号}::{总线}::{槽号}
    # 串口设备
    ComADTS300H_COM2 = ComADTS300H_COM2::ComADTS300H_COM2::115200::8::1::0
                        {name}::{波特率}::{数据位}::{停止位}::{校验}
    # 网络设备
    LanTLIPC342_0 = LanTLIPC342_0::LanTLIPC342_0::192.168.1.60::80::admin::12345678a
                        {资源名}::{IP}::{port}::{user}::{pwd}
    # 子卡
    <add key="1033" value="1033::EPM5200::PXI4::14::1" />
                        {资源名}::{总线}::{总线}::{槽号}::{子卡号}
   ```

## IcdConfig.xml 这个配置文件
IcdConfig.xml 告诉 IcdManager 要加载哪些ICD XML文件、每个文件是什么类型、关联哪个硬件。
IcdConfig.xml 是连接 ICD 语义层（Label/信号定义）和物理层（硬件资源/通道）的桥梁。它不是ICD协议本身，而是ICD协议文件的索引目录。

- 字段	含义	本次文件中的值
- Name: 帧的唯一运行时标识名	A429_00_ISI_01_发送_Label110_6272T_00
- ID:	数字编号	0~160+
- Type:	帧类型	1=接收, 2=发送, 4=配置
- Description:	描述	同Name
- Enable:	启用	1
- WordType:	保留	0
- ByteOrder:	字节序	0=小端, 1=大端
- Path:	ICD XML文件名	A429_00_ISI_01_发送_Label110_6272T_00.xml

Name命名规则拆解:
A429_00_ISI_01_发送_Label110_6272T_00
│      │   │    │     │       │
│      │   │    │     │       └─ 硬件资源=6272T卡通道00
│      │   │    │     └─ ARINC 429 Label编号（八进制110）
│      │   │    └─ 方向：发送（激励→UUT）
│      │   └─ 被测产品：ISI-01
│      └─ A429通道号（对应6272T_00的通道0）
└─ 总线类型

ARINC 429 每个 Label 独立成一个 ICD XML 文件。

## 信号到物理通道的建立过程

appSettings中配置 `ISI-01#A429_IN1 = 6272T_00`，表示：
```markdown
被测设备 `ISI-01` 的 `A429_IN1` 通道 映射到了 `6272T_00` 这个资源上的
```

appSettings中配置 `6272T_00 = 6272T_00::EPH6272T::PXI6::2`，表示：
```markdown
资源 `6272T_00` 是 由后边的 `::` 分割的字符串来描述的，具体是：`{资源名}::{型号名称}::{PXI总线号}::{槽号}`
```

工装发送csv文件中，定义的`A429_IN1(110) GNSS_Latitude,GNSS_Latitude,纬度,,,`，表示：
```markdown
- Magnetic_Track_Angle_LABEL = A429_IN4(317) LABEL
- 磁航迹角_LABEL = A429_IN4(317) LABEL
- 航迹角_LABEL = A429_IN4(317) LABEL
```
