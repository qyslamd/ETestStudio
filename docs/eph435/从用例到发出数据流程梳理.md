**IcdFrame 构造函数内**（`IcdFrame.cs:35`）：

```csharp
public IcdFrame(string name, IcdByteOrder byteOrder, IcdFrameType frameType, ICDData schema) {
    this.Name = name;                      // "A429_00_ISI_01_发送_Label110_6272T_00"
    this.FrameType = frameType;            // iftCmd (Type=2)

    _length = CalLength(schema.Data.Item); // 根据最大Offset+BitWidth算帧长度
    _dataCache = new byte[_length];        // 分配数据缓冲区

    foreach (var item in schema.Data.Item) {
        // 递归创建 IcdNode 树
        node = CreatNode(this, frameType, baseOffset, item, byteOrder);
        _childNodes.Add(node);
        MapToList(node);                    // 展平到 _allChildNodes

        // 根据 Tag 标记特殊字段
        switch ((IcdTag)item.Tag) {
            case IcdTag.Head:   _headNode = node; break;
            case IcdTag.Sum:    _sumNode = node; break;
            case IcdTag.Count:  _countNode = node; break;
        }
    }
}
```

#### 8.2 IcdIntValue / IcdUIntValue 的 UnConvert（物理→原始）

// IsScaled = 1, 走缩放分支

string tempStr = _value.ToString();        // "90"
double tempDouble = double.Parse(tempStr); // 90.0
double tempValue = tempDouble - _schema.ScaleB;  // 90.0 - 0 = 90.0
tempValue /= _schema.ScaleA;                      // 90.0 / 0.000171661376953125 = 524288

// BitWidth = 21, 需要位掩码

**计算结果**: raw = 524288（21bit 无符号整数），对应物理值 90°

验证：524288 × 0.000171661376953125 ≈ 90.0°

#### 8.3 BitSet64.UnExtract（写入 dataCache）

**函数**: `BitSet64.UnExtract(byte* pData)`（`BitSet64.cs` line 88）

```csharp
public unsafe void UnExtract(byte* pData) {
    // 节点的 _schema.Offset = 1, StartBit = 0
    // 所以 pData 指向 dataCache[1]（即 DWORD 的字节1，bit8）
    // BitWidth = 21 < 32

    uint* pTempData32 = (uint*)pData;     // 从字节1开始按uint读取
    UInt32 mark = (UInt32)(0x1 << 21) - 1; // 0x1FFFFF（21位掩码）

    *pTempData32 = (*pTempData32 & ~(mark << 0)) | ((UInt32)524288 << 0);
    // 将 value 写入 dataCache[1..3] 的 bit0..20（即 DWORD 的 bit8..28）
}
```

**dataCache 状态变化**（32-bit DWORD）：

| Byte | Bit Position | 字段 | 之前 | 之后 |
|------|-------------|------|------|------|
| 0 | 0-7 | LABEL=72(0x48) | 0x00 | 0x48 |
| 1 | 0-7 | GNSS_Latitude[7:0] | 0x00 | 0x00 |
| 2 | 0-7 | GNSS_Latitude[15:8] | 0x00 | 0x08 |
| 3 | 0-4 | GNSS_Latitude[20:16] | 0x00 | 0x00 |
| 3 | 5-6 | SSM | 0x00 | 0x00 |
| 3 | 7 | PARITY | 0x00 | 0x00 |

DWORD 16进制: `0x00080048`（小端）

实际 ARINC 429 word 布局（bit1=LSB）：
```
Bit  1- 8: LABEL  = 110(octal)
Bit  9-29: Data   = 524288 = 纬度编码
Bit 30-31: SSM    = 00(Normal)
Bit 32:   Parity  = ?
```

### 第10步：DoWrite → 硬件寄存器写入

**函数**: `Eph6272TChannelSession.DoWrite(IcdNode node, string name)`（位于 IO.Imp 中）

```csharp
protected override void DoWrite(IcdNode node, string name) {
    // 1. 从 node 获取所属 frame
    IcdFrame frame = node.GetOwner() as IcdFrame;

    // 2. 触发 Encode → 处理校验/计数
    byte[] txData = new byte[frame.Length];
    frame.Encode(txData);   // 将 dataCache 复制到 txData

    // 3. 获取硬件通道号（从 IcdConfig.xml 帧名中提取 "00"）
    //    或从 node.LinkTo 获取 "\6272T_00\ch0"
    int channel = 0;

    // 4. PXI 寄存器写入
    //    PXI6::2 对应设备路径，通过 PXI/PCIe 驱动接口
    //    BAR0 + 通道偏移 + 数据寄存器
    WritePxiRegister(PXI_SLOT_2, CHANNEL_OFFSET(ch0), DATA_REG, txData);

    // 5. 硬件 FPGA 自动：
    //    - 解析 LABEL（bits 1-8 = 110 octal）
    //    - 按 LABEL 调度表周期发送
    //    - NRZ 编码，差分电平输出
    //    - 通道 00 物理引脚输出
}
```

**LinkTo 字段**：ICD XML 中节点有 `<LinkTo>\6272T_00\ch0</LinkTo>`，标记该信号所属的硬件通道。

## 六、设计总结

1. **分层清晰、映射解耦**：友好名→ICD节点名（CSV）、产品通道→设备资源（appSettings）、ICD语义定义（ICD XML）、硬件地址（device.list），各层独立维护。

2. **ICD定义与硬件部署分离**：同一套 Label110 的 ICD 定义，通过更换 IcdConfig.xml（便携版 vs 机柜版）可以部署到不同硬件平台（5272 便携卡 vs 6272T 机柜卡）。

3. **帧名编码了完整路径**：`A429_00_ISI_01_发送_Label110_6272T_00` 这个帧名本身编码了总线类型、通道号、产品、方向、Label、硬件资源，实现了一种"自描述"的命名体系。

4. **运行时拼装 vs 存储完整**：CSV 存的是不含产品前缀的通用名，运行时按 `{产品}#{ICD节点名}` 拼装；但 ICD XML 中直接存完整名 `ISI-01#A429_IN1(110) GNSS_Latitude`。两种策略并存。

5. **ICD编码是数据流核心**：`UnConvert`（物理→原始缩放）和 `BitSet64.UnExtract`（位域写入）是整个链路的"语义编码"步骤，将业务层的 90° 编码为硬件理解的 524288 二进制值。
