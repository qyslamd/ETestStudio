# 阶段1.1：开发环境与基础工程搭建迭代

## 一、核心目标

完成开发环境统一规范、现有工程结构优化、所有第三方依赖源码集成与CMake编译配置，输出可在VS2017/2019/QtCreator/VSCode一键编译运行的最小Qt程序，所有依赖链接正常，为后续功能开发扫清环境障碍。

## 二、预期周期：1~2个工作日

## 三、开发环境统一规范

| 平台 | 标准配置 | 兼容配置 |
|------|----------|----------|
| Windows | Qt 5.12.12 + VS2017 64位套件 | VS2019 64位套件 |
| Linux | 暂不考虑，后续迭代适配 | - |

* 输出交付物：《Windows开发环境配置手册》，包含Qt、VS安装配置步骤、环境变量统一配置规范

## 四、详细任务拆分

| 序号 | 任务内容 | 输出物 |
|------|----------|--------|
| 1 | 现有工程结构优化 | 规范工程目录结构，删除冗余文件，目录结构如下文所示 |
| 2 | 第三方依赖源码集成 | 收集所有符合Qt5.12.12兼容性的依赖源码，放入`3rdparty/`目录，删除不必要的示例、测试、文档文件，减小工程体积 |
| 3 | CMake编译配置编写 | ① 优化现有基础Qt项目CMake配置，兼容VS/QtCreator/VSCode编译 ② 逐个添加每个3rdparty依赖的静态库编译规则 ③ 配置统一输出目录，编译产物自动输出到`bin/`目录 |
| 4 | 依赖链接验证 | 开发最小验证窗口程序，代码中引入所有依赖的头文件，调用简单API验证链接正常，运行无崩溃、无依赖缺失错误 |
| 5 | 多IDE编译验证 | 分别在VS2017、VS2019、QtCreator、VSCode中执行CMake生成、编译、运行流程，确保所有环境编译正常，无链接错误 |

## 五、工程目录结构规范

```txt
etest_qt/
├── CMakeLists.txt          # 顶层CMake配置
├── src/                    # 源代码目录
│   ├── app/                # 主程序入口
│   └── CMakeLists.txt
├── 3rdparty/               # 第三方依赖源码
│   ├── qads/               # Qt Advanced Docking System
│   ├── qscintilla/         # QScintilla文本编辑器
│   ├── spdlog/             # 日志库
│   ├── gtest/              # 单元测试框架
│   ├── lua/                # Lua脚本引擎
│   ├── qtxlsx/             # Qt Excel读写库
│   ├── libharu/            # libharu PDF生成库
│   └── CMakeLists.txt      # 第三方依赖统一编译配置
├── resources/              # 资源文件（图标、样式等）
├── test/                   # 单元测试代码
├── docs/                   # 文档
└── bin/                    # 编译输出目录（自动生成）
```
