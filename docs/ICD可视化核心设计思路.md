# ICD 可视化核心设计思路

> 本文基于对 EphAutoTest (eph435) 项目 ICD 工作流全信息的分析，推演 ICD 协议可视化编辑器的设计目标和功能边界。本文是设计文档，非实施方案。

---

## 一、核心约束：ICD 数据结构特征

ICD 的定义围绕**位级编码**展开，这是所有设计决策的出发点：

```
帧 (Frame)
├── 帧名: "A429_00_ISI_01_发送_Label110_6272T_00"
├── ID: 90
├── 类型: 1=接收Data / 2=发送Cmd / 4=配置Config
├── 字节序: 0=小端 / 1=大端
├── 帧长度: 由所有节点的 Max(Offset + BitWidth/8) 决定
│
└── 信号节点树 (Item / Childs 嵌套)
    ├── Node A (Offset=0, StartBit=0, BitWidth=32)
    │   ├── Child A1 (Offset=0, StartBit=0, BitWidth=8)
    │   ├── Child A2 (Offset=0, StartBit=8, BitWidth=8)
    │   └── Child A3 (Offset=0, StartBit=16, BitWidth=16)
    ├── Node B (Offset=4, StartBit=0, BitWidth=16)
    └── Node C ...
```

关键设计点：
- **信号可嵌套**（Childs 递归），编辑器必须支持树形展示和操作
- **位宽可跨字节**（StartBit=0, BitWidth=21 跨3字节），位布局视图必须支持跨字节色块
- **帧名按固定规则编码**，编辑器可提供自动生成工具
- **信号位域不可重叠**，编辑器必须提供重叠检测

## 二、目标用户与使用场景

### 场景 A — 测试工程师配置新信号

> UUT 新增一个参数需要激励，工程师在指定 Label 的发送帧里添加信号，配置 Offset/StartBit/BitWidth/ScaleA/B 等属性。

### 场景 B — 验证 ICD 定义

> A429 板卡回读数据解析错误，工程师打开接收帧，逐个检查每个信号的定义是否与 ICD 文档一致。

### 场景 C — 排查四层映射一致性

> CSV 中"纬度"映射到 `A429_IN1(110) GNSS_Latitude`，但 ICD XML 中此信号的 Offset/BitWidth/ScaleA 是否有误？编辑器应能关联展示各层映射关系。

## 三、编辑器整体布局

```
┌──────────────────────────────────────────────────────────┐
│  帧属性栏: ID:90 | 类型:发送 | 字节序:小端 | Label:110  │  ← 可编辑
├──────────┬─────────────────────────┬────────────────────┤
│          │                         │                    │
│  信号树   │    位布局可视化           │   属性编辑器       │
│  (左30%)  │    (中40%)              │   (右30%)         │
│          │                         │                    │
│  ┌──────┐│  Byte0 Byte1 Byte2...   │  Name: GNSS_Lat   │
│  │+ 发送 ││  ┌──┬──┬──┬──┬──┬──┐   │  Offset: 1        │
│  │ ├─LAB ││  │##│##│##│##│  │  │   │  StartBit: 0      │
│  │ ├─SSM ││  └──┴──┴──┴──┴──┴──┘   │  BitWidth: 21     │
│  │ ├─Data││   ↑GNSS_Latitude(21bit) │  Type: uint       │
│  │ └─Parit││                        │  ScaleA:0.00017166│
│  │        ││  不同信号用不同颜色      │  ScaleB:0         │
│  │        ││  色块精准覆盖位域        │  Tag: none        │
│  │        ││  悬停显示信号名+位范围   │  Unit: °          │
│  │        ││                        │  IsScaled: ✅     │
└──────────┴─────────────────────────┴────────────────────┘
```

三种视图通过信号联动：
- 信号树选中节点 → 位视图中对应色块高亮 + 属性面板刷新
- 位视图点击色块 → 信号树自动展开并选中 + 属性面板刷新
- 属性面板修改值 → 信号树节点名/图标更新 + 位视图色块位置更新

## 四、核心视觉元素：位布局网格

这是"可视化"的核心价值所在 — 它直接对应 BitSet64 的位域操作，是连接"工程师的协议理解"和"底层二进制编码"的桥梁。

### 显示模式

| 模式 | 行组织 | 适用场景 |
|------|--------|---------|
| A429 字模式 | 每行 4 字节 (32bit A429 word) | ARINC 429 总线 |
| 字节模式 | 每行 1 字节 (8bit) | 串口/自定义协议 |
| 自由模式 | 按实际帧长度自动选择 | 通用编辑 |

### 交互能力

- **色块覆盖**: 每个信号使用唯一色块覆盖其位域（从 StartBit 到 StartBit+BitWidth-1）
- **悬停提示**: 鼠标悬停在色块上时显示"信号名 (Offset:X, Bit:Y~Z)"
- **点击选中**: 点击色块 → 三个视图联动定位
- **标尺**: 顶部 bit 偏移标号、左侧字节偏移标号
- **重叠检测**: 两个信号位域重叠时红色闪烁警示
- **越界检测**: 信号超出帧长度时用警告色标识
- **缩放**: 支持缩放到位级精度（能看到每个 bit 格）

## 五、帧浏览器（侧边栏面板）

帧浏览器按四层配置体系的逻辑组织过滤：

### 过滤维度

| 维度 | 来源 | 控件 |
|------|------|------|
| 帧类型 | IcdConfig.FileInfo.Type | 下拉: 全部/发送(Cmd)/接收(Data)/配置(Config) |
| 总线类型 | 帧名第一段 | 下拉: A429/串口/电源/压力/离散量/1553/摄像头 |
| 产品 | appSettings ProductList | 下拉: ISI-01/ISI-02 |
| Label | 帧名中的 LabelXXX | 输入框 |
| 关键字 | 帧名全文 | 搜索框 |

### 列表展示

帧列表以表格展示主要信息：帧名、ID、类型、总线、Label、产品

## 六、信号树操作

信号是递归嵌套的（Childs），树操作能力：

| 操作 | 说明 |
|------|------|
| 添加子节点 | 在选中节点下新建子信号 |
| 添加同级节点 | 在选中节点之后新建同级信号 |
| 删除节点 | 确认后删除，包含所有子节点 |
| 上移/下移 | 调整同层级内的顺序（影响编解码顺序） |
| 拖拽排序 | 通过拖拽改变层级结构 |
| 展开/折叠 | 树形结构的标准操作 |
| 搜索节点 | 在树内搜索信号名 |

每个树节点显示：`[类型图标] 信号名 — Tag标签 — Offset:StartBit[BitWidth]`

## 七、属性编辑器

每个信号节点可编辑的属性完全由 Item 定义驱动：

| 属性 | 控件类型 | 说明 |
|------|---------|------|
| Name | 文本编辑 | 信号名（自动管理产品前缀） |
| Offset | 整数 spinbox | 字节偏移 |
| StartBit | 0-7 spinbox | 位偏移（在 Offset 字节内） |
| BitWidth | 1-64 spinbox | 位宽 |
| Type | 下拉选择 | byte/int/uint/float/double/string/bytes/dword |
| Tag | 下拉选择 | none/Head/Length/Count/Sum/XOR... |
| IsScaled | checkbox | 是否启用缩放 |
| ScaleA | 浮点数输入 | 缩放系数 A |
| ScaleB | 浮点数输入 | 缩放系数 B |
| Unit | 文本编辑 | 单位 |
| SystemName | 文本/下拉 | 系统名 |
| GroupName | 文本编辑 | 组名 |
| Description | 文本编辑 | 描述 |
| Min | 浮点数输入 | 最小值 |
| Max | 浮点数输入 | 最大值 |
| ValueTextList | 文本编辑 | 预设值列表（如 LABEL 号） |
| LinkTo | 下拉选择 | 关联硬件通道 |

## 八、智能校验与约束

### 帧完整性校验

- 检查 A429 帧是否缺少标准字段（Parity/SSM/Label/SDI/Data）
- 检查 Tag=Head/Length/Count/Sum/XOR 是否唯一
- 检查校验和节点的覆盖范围是否合理

### 位域重叠检测

- 遍历帧内所有同级信号，检查是否有任意两个信号的位域重叠
- 重叠信号在位布局网格中以红色闪烁标识
- 状态栏输出重叠详情："信号A(Off=0, Bit=0~7) 与 信号B(Off=0, Bit=4~11) 重叠"

### 缩放预览

- 属性编辑 ScaleA/ScaleB 时实时显示物理值与原始值的映射关系
- 例如：ScaleA=0.00017166, ScaleB=0 → "原始值 524288 = 物理值 90.0°"

### 帧长度约束

- ARINC 429 标签帧固定为 4 字节（32bit），禁止改动帧长度
- 其他总线类型在添加信号时自动扩帧

## 九、关联功能

### CSV 映射预览

编辑器应能够加载 CSV 映射文件，在选中信号时显示：
- "当前信号被 CSV 友好名引用：纬度、GNSS_Latitude"
- 修改信号名时提示："以下 CSV 映射可能已失效：纬度、GNSS_Latitude"

### 帧名自动生成

新建帧时提供表单：总线类型 + 通道 + 产品 + 方向 + Label + 硬件资源 → 自动拼装标准帧名

```
A429_00_ISI_01_发送_Label110_6272T_00
│      │   │    │     │       │
总线  通道 产品  方向  Label  硬件资源
```

### 设备资源选择器

编辑 LinkTo 属性时，下拉选项从 device.list 配置中加载：6272T_00~03、ComADTS300H_COM2、LanTLIPC342_0 等。

### 多 IcdConfig 切换

支持同时打开多个 IcdConfig（机柜/便携系统/自环回），方便对比不同部署方案的 ICD 定义差异。

### 节点名前缀自动管理

编辑时自动剥离/拼接产品前缀 `ISI-01#`，用户在属性编辑器中看到干净的信号名 `A429_IN1(110) GNSS_Latitude`，保存时自动补全。

## 十一、设计原则总结

1. **位级精度是一切的核心** — 编辑器的存在价值源于 ICD 定义是位级的，脱离了可视化位布局就没有区别于文本编辑器的意义。

2. **三视图联动是基本交互范式** — 树（结构）/ 位图（空间）/ 属性（详情）三者永远保持同步。

3. **校验必须内建于编辑流程** — 位域重叠、帧完整性、Tag 唯一性这些检查不需要用户主动触发，编辑过程中自动实时检测并提示。

4. **编辑器是四层配置体系的入口而非孤岛** — 设计时必须考虑对 CSV 映射层的影响、对 device.list 的依赖、对多 IcdConfig 版本的支持。

5. **帧名编码规则是元数据而非格式** — 编辑器不应要求用户手动拼接帧名，而是提供结构化表单自动生成。
