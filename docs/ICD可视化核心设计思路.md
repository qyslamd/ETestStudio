# ICD 可视化核心设计思路

> 本文基于对 EphAutoTest (eph435) 项目 ICD 工作流全信息的分析，结合 `docs/icd_schema/` 目录下 21 个实际 XML 文件的结构逆向，推演 ICD 协议可视化编辑器的设计目标和功能边界。本文是设计文档，非实施方案。

---

## 一、核心约束：ICD 数据结构特征

ICD 的定义围绕**位级编码**展开，这是所有设计决策的出发点。

### 1.1 文件组织：单帧 XML

每个 XML 文件对应**一个帧**，文件结构如下：

```
ICDData (XML根)
├── <Name/>              (帧名，通常为空)
└── <Data>
    └── <Item>           (根信号节点)
        ├── <Offset>0</Offset>
        ├── <StartBit>0</StartBit>
        ├── <BitWidth>32</BitWidth>
        ├── <Type>dword</Type>
        ├── <Name>ISI-01#A429_IN1(050) 发送数据</Name>
        ├── <Description>发送的32位数据</Description>
        ├── <GroupName>ISI-01#A429_IN1(050)</GroupName>
        ├── <IsScaled>0</IsScaled>
        ├── <SystemName>ARINC429总线通讯模块</SystemName>
        ├── <Tag>0</Tag>
        ├── <ValueTextList>40</ValueTextList>
        ├── <LinkTo>5272_00\ch0</LinkTo>
        ├── <ScaleA>0.01</ScaleA>        (可选，仅部分帧有)
        ├── <Unit>A</Unit>               (可选，仅部分帧有)
        └── <Childs>                     (可选，嵌套子节点)
            └── <Item>...</Item>
```

### 1.2 Item 完整字段清单

从 21 个 XML 文件中提取的所有字段：

| 字段 | 必有 | 类型 | 说明 |
|------|------|------|------|
| `Offset` | ✅ | 整数 | 字节偏移（从0开始） |
| `StartBit` | ✅ | 整数 (0-7) | 起始位（在 Offset 字节内） |
| `BitWidth` | ✅ | 正整数 | 位宽（1-2080） |
| `Type` | ✅ | 枚举 | 值类型（见 1.3） |
| `Name` | ✅ | 字符串 | 信号名（含产品前缀） |
| `Description` | ✅ | 字符串 | 信号描述 |
| `IsScaled` | ✅ | 0/1 | 是否启用缩放 |
| `GroupName` | 部分 | 字符串 | 组名（信号名前缀） |
| `SystemName` | 部分 | 字符串 | 系统/模块名 |
| `Tag` | 部分 | 整数 | 标签（见 1.4） |
| `ValueTextList` | 部分 | 字符串 | 枚举值文本列表 |
| `LinkTo` | 部分 | 字符串 | 硬件通道链接 |
| `Unit` | 少数 | 字符串 | 物理单位 |
| `ScaleA` | 极少 | 浮点数 | 缩放系数 A |
| `ScaleB` | ❌ 不存在 | — | 预留字段，XML 中未使用 |
| `Min` | ❌ 不存在 | — | 预留字段，XML 中未使用 |
| `Max` | ❌ 不存在 | — | 预留字段，XML 中未使用 |

### 1.3 Type 枚举映射

实际 XML 中出现的 6 种类型：

| XML Type 值 | 含义 | 对应 icd::ValueType | 典型 BitWidth |
|------------|------|-------------------|--------------|
| `byte` | 无符号 8 位整数 | byte_ | 8 |
| `word` | 无符号 16 位整数 | word | 16 |
| `dword` | 无符号 32 位整数 | longword | 32 |
| `float` | 32 位浮点数 | single | 32 |
| `double` | 64 位浮点数 | double_ | 64 |
| `string` | 字符串 | string_ | 8 的倍数（如 2080） |

> 注意：XML 中**不使用** `int16`、`int32`、`uint64`、`bytes`、`boolean` 等类型。设计时应以实际 6 种为准。

### 1.4 Tag 数值映射

XML 中 Tag 为整数，非枚举名：

| Tag 值 | 含义 | 典型场景 |
|--------|------|---------|
| `0` | none（无标签） | 大多数信号 |
| `1` | head（帧头） | 串口帧头 0xAA55 |
| `40` | sum/xor（校验） | A429 LABEL 字段、CRC |
| `41` | signal_in_value | 带缩放的信号值 |
| `60` | big_endian_value | 大端数据字段 |

### 1.5 帧级元数据：不在 XML 中

以下帧属性在 XML 文件内**不存在**，需要从文件名推断或外部配置：

| 属性 | XML 中是否存在 | 来源 |
|------|---------------|------|
| 帧 ID | ❌ | 文件名编码或 IcdConfig 配置 |
| 帧类型 (Cmd/Data/Config) | ❌ | 文件名中的"发送/接收/配置" |
| 字节序 (ByteOrder) | ❌ | 默认小端，或文件名/配置推断 |
| 帧长度 | ❌ | 由 max(Offset + BitWidth/8) 计算 |

### 1.6 关键设计点

- **信号可嵌套**（Childs 递归），编辑器必须支持树形展示和操作
- **位宽可跨字节**（如 Offset=0, StartBit=0, BitWidth=21 跨 3 字节），位布局视图必须支持跨字节色块
- **文件名按固定规则编码**，编辑器需提供文件名解析和生成工具（见第六章）
- **信号位域不可重叠**，编辑器必须提供重叠检测
- **string 类型 BitWidth 可达 2080**（如摄像头路径字段），位布局视图需处理大跨度信号

## 二、目标用户与使用场景

### 场景 A — 测试工程师配置新信号

> UUT 新增一个参数需要激励，工程师在指定 Label 的发送帧里添加信号，配置 Offset/StartBit/BitWidth/ScaleA 等属性。

### 场景 B — 验证 ICD 定义

> A429 板卡回读数据解析错误，工程师打开接收帧，逐个检查每个信号的定义是否与 ICD 文档一致。

### 场景 C — 排查四层映射一致性

> CSV 中"纬度"映射到 `A429_IN1(110) GNSS_Latitude`，但 ICD XML 中此信号的 Offset/BitWidth/ScaleA 是否有误？编辑器应能关联展示各层映射关系。

## 三、编辑器整体布局

```
┌──────────────────────────────────────────────────────────────┐
│  帧属性栏: 文件名: A429_00_ISI_01_发送_Label050_5272_00.xml │
│           总线:A429 | 通道:00 | 产品:ISI-01 | 方向:发送      │
│           Label:050 | 硬件:5272_00                          │
├──────────┬─────────────────────────┬────────────────────────┤
│          │                         │                        │
│  信号树   │    位布局可视化           │   属性编辑器           │
│  (左30%)  │    (中40%)              │   (右30%)             │
│          │                         │                        │
│  ┌──────┐│  Byte0 Byte1 Byte2...   │  Name: GNSS_Latitude  │
│  │+ 发送 ││  ┌──┬──┬──┬──┬──┬──┐   │  Offset: 1            │
│  │ ├─LAB ││  │##│##│##│##│  │  │   │  StartBit: 0          │
│  │ ├─SSM ││  └──┴──┴──┴──┴──┴──┘   │  BitWidth: 21         │
│  │ ├─Data││   ↑GNSS_Latitude(21bit) │  Type: dword          │
│  │ └─Parit││                        │  ScaleA: 0.00017166   │
│  │        ││  不同信号用不同颜色      │  Tag: 0 (none)        │
│  │        ││  色块精准覆盖位域        │  Unit: °              │
│  │        ││  悬停显示信号名+位范围   │  IsScaled: ✓          │
│  │        ││                        │  LinkTo: 5272_00\ch0  │
└──────────┴─────────────────────────┴────────────────────────┘
```

三种视图通过信号联动：
- 信号树选中节点 → 位视图中对应色块高亮 + 属性面板刷新
- 位视图点击色块 → 信号树自动展开并选中 + 属性面板刷新
- 属性面板修改值 → 信号树节点名/图标更新 + 位视图色块位置更新

## 四、核心视觉元素：位布局网格

这是"可视化"的核心价值所在 — 它直接对应 BitSet64 的位域操作，是连接"工程师的协议理解"和"底层二进制编码"的桥梁。

### 显示模式

| 模式 | 行组织 | 适用场景 |
|------|--------|---------|
| A429 字模式 | 每行 4 字节 (32bit A429 word) | ARINC 429 总线 |
| 字节模式 | 每行 1 字节 (8bit) | 串口/自定义协议 |
| 自由模式 | 按实际帧长度自动选择 | 通用编辑 |

### 特殊类型处理

| Type | BitWidth | 位布局处理 |
|------|----------|-----------|
| byte | 8 | 占 1 格 |
| word | 16 | 占 2 格，可能跨行 |
| dword | 32 | 占 4 格，正好一行（A429 模式） |
| float | 32 | 同 dword，标记为浮点色 |
| double | 64 | 占 8 格，跨 2 行 |
| string | 8 的倍数（如 2080） | 占多行，显示为单一长色块 |

### 交互能力

- **色块覆盖**: 每个信号使用唯一色块覆盖其位域（从 Offset*8+StartBit 到 Offset*8+StartBit+BitWidth-1）
- **悬停提示**: 鼠标悬停在色块上时显示"信号名 (Offset:X, Bit:Y~Z)"
- **点击选中**: 点击色块 → 三个视图联动定位
- **标尺**: 顶部 bit 偏移标号、左侧字节偏移标号
- **重叠检测**: 两个信号位域重叠时红色闪烁警示
- **越界检测**: 信号超出帧长度时用警告色标识
- **缩放**: 支持缩放到位级精度（能看到每个 bit 格）
- **大跨度信号**: string 类型 BitWidth=2080 时，色块横跨多行，需支持滚动查看

## 五、帧浏览器（侧边栏面板）

帧浏览器按文件名编码的逻辑维度组织过滤：

### 过滤维度

| 维度 | 来源 | 控件 |
|------|------|------|
| 帧类型 | 文件名中的方向词 | 下拉: 全部/发送(Cmd)/接收(Data)/配置(Config) |
| 总线类型 | 文件名第一段 | 下拉: A429/串口/电源/压力/离散量/1553/摄像头 |
| 产品 | 文件名中的产品段 | 下拉: ISI-01/ISI-02 |
| Label | 文件名中的 LabelXXX | 输入框 |
| 关键字 | 文件名全文 | 搜索框 |

### 列表展示

帧列表以表格展示主要信息：文件名、总线、通道、产品、方向、Label、硬件资源

## 六、文件命名编码规则

这是编辑器的核心元数据来源。每个 XML 文件名按固定规则编码帧级属性：

### 文件名格式

```
A429_00_ISI_01_发送_Label050_5272_00.xml
│      │   │    │     │       │
总线  通道 产品  方向  Label  硬件资源
```

### 各段解析规则

| 段 | 位置 | 说明 | 示例 |
|----|------|------|------|
| 总线类型 | 第 1 段 | 总线/设备类型 | `A429`, `串口`, `压力给定`, `大华电源`, `摄像头`, `1033`, `5121A`, `5V导光板电源`, `示波器` |
| 通道号 | 第 2 段 | 通道编号 | `00`, `08`, `03` |
| 产品 | 第 3 段 | 产品/板卡名 | `ISI_01`, `ISI_02` |
| 方向 | 第 4 段 | 数据流向 | `发送`=Cmd, `接收`=Data, `配置`=Config |
| Label | 第 5 段 | A429 Label 号（可选） | `Label050`, `Label156` |
| 硬件资源 | 第 6 段 | 硬件设备+通道 | `5272_00`, `6272T_08`, `ComADTS300H_COM2` |

### 方向 → 帧类型映射

| 文件名方向词 | 帧类型 | 含义 |
|------------|--------|------|
| `发送` | Cmd | 测试系统发送给 UUT 的激励 |
| `接收` | Data | UUT 返回给测试系统的数据 |
| `配置` | Config | 板卡/设备配置参数 |

### 无 Label 的帧

串口、电源、压力等非 A429 帧不含 Label 段，文件名格式为：

```
5121A_自检_发送.xml
压力给定_发送静压总压_ComADTS300H_COM2.xml
大华电源_接收电源状态_ComPower_COM3.xml
```

这类帧的总线类型从文件名第一段解析，通道/硬件资源从最后一段解析。

## 七、信号树操作

信号是递归嵌套的（Childs），树操作能力：

| 操作 | 说明 |
|------|------|
| 添加子节点 | 在选中节点下新建子信号 |
| 添加同级节点 | 在选中节点之后新建同级信号 |
| 删除节点 | 确认后删除，包含所有子节点 |
| 上移/下移 | 调整同层级内的顺序（影响编解码顺序） |
| 拖拽排序 | 通过拖拽改变层级结构 |
| 展开/折叠 | 树形结构的标准操作 |
| 搜索节点 | 在树内搜索信号名 |

每个树节点显示：`[类型图标] 信号名 — Tag标签 — Offset:StartBit[BitWidth]`

## 八、属性编辑器

每个信号节点可编辑的属性由 Item 定义驱动：

### 必有属性

| 属性 | 控件类型 | 说明 |
|------|---------|------|
| Name | 文本编辑 | 信号名（自动管理产品前缀） |
| Offset | 整数 spinbox | 字节偏移 |
| StartBit | 0-7 spinbox | 位偏移（在 Offset 字节内） |
| BitWidth | 1-2080 spinbox | 位宽 |
| Type | 下拉选择 | byte/word/dword/float/double/string |
| Description | 文本编辑 | 描述 |
| IsScaled | checkbox | 是否启用缩放 |

### 可选属性（部分帧有）

| 属性 | 控件类型 | 说明 |
|------|---------|------|
| GroupName | 文本编辑 | 组名（信号名前缀，非语义分组） |
| SystemName | 文本/下拉 | 系统/模块名 |
| Tag | 下拉选择 | 数值标签: 0=none, 1=head, 40=sum/xor, 41=signal_in_value, 60=big_endian_value |
| ValueTextList | 文本编辑 | 枚举值文本列表（如 `SBAS=0,GLONASS=1`） |
| LinkTo | 下拉选择 | 关联硬件通道（格式: `\DeviceName\chN`） |
| Unit | 文本编辑 | 物理单位 |
| ScaleA | 浮点数输入 | 缩放系数 A |

### 预留属性（UI 保留，XML 无数据）

| 属性 | 控件类型 | 说明 |
|------|---------|------|
| ScaleB | 浮点数输入 | 缩放系数 B（预留，默认 0） |
| Min | 浮点数输入 | 最小值（预留） |
| Max | 浮点数输入 | 最大值（预留） |

### GroupName 语义说明

XML 中的 GroupName 实际是**信号名前缀**（如 `ISI-01#A429_IN1(050)`），不是语义分组。位布局视图的颜色分组不应依赖 GroupName，而应基于 Tag 值或自定义规则。

## 九、智能校验与约束

### 帧完整性校验

- 检查 A429 帧是否缺少标准字段（Parity/SSM/Label/SDI/Data）
- 检查 Tag 值唯一性（如 Tag=40 的校验字段是否唯一）
- 检查校验和节点的覆盖范围是否合理

### Tag 值校验规则

| Tag 值 | 含义 | 校验规则 |
|--------|------|---------|
| 1 (head) | 帧头 | 每帧最多 1 个 |
| 40 (sum/xor) | 校验 | 每帧至少 1 个 |
| 41 (signal_in_value) | 信号值 | 无限制 |
| 60 (big_endian_value) | 大端值 | 无限制 |

### 位域重叠检测

- 遍历帧内所有同级信号，检查是否有任意两个信号的位域重叠
- 重叠信号在位布局网格中以红色闪烁标识
- 状态栏输出重叠详情："信号A(Off=0, Bit=0~7) 与 信号B(Off=0, Bit=4~11) 重叠"

### 缩放预览

- 属性编辑 ScaleA 时实时显示物理值与原始值的映射关系
- 例如：ScaleA=0.01, Unit=A → "原始值 100 = 物理值 1.0A"

### 帧长度约束

- ARINC 429 标签帧固定为 4 字节（32bit），禁止改动帧长度
- 其他总线类型在添加信号时自动扩帧
- string 类型 BitWidth=2080 时帧长度较大（如 260 字节），位布局视图需支持滚动

## 十、关联功能

### 文件名生成器

新建帧时提供表单：总线类型 + 通道 + 产品 + 方向 + Label + 硬件资源 → 自动拼装标准文件名。

```
输入: 总线=A429, 通道=00, 产品=ISI-01, 方向=发送, Label=050, 硬件=5272_00
输出: A429_00_ISI_01_发送_Label050_5272_00.xml
```

### 设备资源选择器

编辑 LinkTo 属性时，下拉选项从已知硬件设备中加载：
- `5272_00` ~ `5272_03`（A429 板卡）
- `6272T_00` ~ `6272T_08`（A429 板卡）
- `ComADTS300H_COM2`（压力设备）
- `ComPower_COM1` ~ `ComPower_COM3`（电源）
- `LanTLIPC342_0`（摄像头）
- `UsbDP07504_0`（示波器）
- `ComCHH50W_COM1`（导光板电源）
- `5276H_00` ~ `5276H_01`（串口）
- `5121A`（离散量）
- `1033`（AD 采集）

### CSV 映射预览

编辑器应能够加载 CSV 映射文件，在选中信号时显示：
- "当前信号被 CSV 友好名引用：纬度、GNSS_Latitude"
- 修改信号名时提示："以下 CSV 映射可能已失效：纬度、GNSS_Latitude"

### 多帧文件管理

支持同时打开多个 XML 帧文件，方便对比不同帧的定义差异。

### 节点名前缀自动管理

编辑时自动剥离/拼接产品前缀 `ISI-01#`，用户在属性编辑器中看到干净的信号名 `A429_IN1(110) GNSS_Latitude`，保存时自动补全。

| 用户辅助 | 节点名前缀自动管理（产品前缀剥离/拼接） |
| 用户辅助 | 节点属性修改后后续节点偏移量自动调整提醒 |

## 十二、设计原则总结

1. **位级精度是一切的核心** — 编辑器的存在价值源于 ICD 定义是位级的，脱离了可视化位布局就没有区别于文本编辑器的意义。

2. **三视图联动是基本交互范式** — 树（结构）/ 位图（空间）/ 属性（详情）三者永远保持同步。

3. **校验必须内建于编辑流程** — 位域重叠、帧完整性、Tag 唯一性这些检查不需要用户主动触发，编辑过程中自动实时检测并提示。

4. **文件名即元数据** — 帧的 ID、类型、字节序等属性不在 XML 内，而是编码在文件名中。编辑器必须能正确解析和生成文件名。

5. **以实际 XML Schema 为准** — 类型系统只用 byte/word/dword/float/double/string 6 种，Tag 用数值映射，不引入 XML 中不存在的字段。

6. **帧名编码规则是元数据而非格式** — 编辑器不应要求用户手动拼接帧名，而是提供结构化表单自动生成。
