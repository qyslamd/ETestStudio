# 用例设计器 — 实现方案

## 背景

目前 TestCaseRef 数据结构已在 `ProjectInfo` 中存在，`cases/` 目录随项目创建，但缺少：
- 侧边栏面板（类似 ProtocolManagerWidget 管理 .eproto）
- 测试用例文件格式定义与编辑器
- ProjectManager 缺少 registerTestCaseRef / removeTestCaseRef

目标是实现一个完整的用例设计器，遵循与协议管理器相同的三层架构：数据模型 → 侧边栏面板 → 编辑器。

---

## Phase 1: 测试用例数据模型 + 文件格式

### 1.1 TestCaseData 数据结构 — `src/app/TestCaseData.h` (新增)

定义测试用例文件的内存模型：

```cpp
struct TestStepData {
    QString cmd;         // SET / DELAY / CHECK / WAIT
    QString target;      // 信号/变量名
    QVariant value;      // 设定值/期望值
    int delayMs = 0;     // 延迟(毫秒)
    int timeoutMs = 5000; // 超时(毫秒)
    QString description; // 步骤说明
};

struct TestCaseData {
    QString name;
    QString description;
    QVector<TestStepData> steps;
};

struct TestSuiteData {
    QString name;
    QString description;
    QString version = "1.0";
    QVector<TestStepData> setup;     // 前置步骤
    QVector<TestStepData> teardown;  // 后置步骤
    QVector<TestCaseData> cases;
};
```

### 1.2 序列化/反序列化 — `src/app/TestCaseData.cpp` (新增)

- `loadTestSuite(const QString& filePath)` → `tl::expected<TestSuiteData, QString>`
- `saveTestSuite(const QString& filePath, const TestSuiteData&)` → `bool`
- JSON 格式，与 `temp/test_case.json` 风格兼容

## Phase 2: ProjectManager 扩展

### 2.1 注册/移除方法 — `src/core/project/ProjectManager.h/.cpp`

参照 `registerProtocolRef` / `removeProtocolRef` 模式：

```cpp
void registerTestCaseRef(const QString& filePath);
void removeTestCaseRef(const QString& id);
```

- `registerTestCaseRef`: 创建 TestCaseRef，设置 id=绝对路径, name=baseName, filePath=相对路径, type="json"，addTestCase + saveToFile
- `removeTestCaseRef`: 按 id 移除 + saveToFile

---

## Phase 3: 侧边栏面板 TestCaseManagerWidget

### 3.1 面板类 — `src/app/TestCaseManagerWidget.h/.cpp` (新增)

参照 `ProtocolManagerWidget` 的设计：

- **树控件**（`QTreeWidget`）：顶层节点 = .tcase 文件，子节点 = 该文件中的测试用例
- **工具栏**：`+ 新建` 按钮
- **右键菜单**：打开、重命名、删除
- **双击**文件节点 → 发射 `openFileRequested(filePath)` 信号
- **`refreshList()`**：遍历 `project->testCases()`，读取每个 .tcase 文件，解析出用例名作为子节点

### 3.2 SidebarWidget 集成

- `SidebarWidget.h`：添加 `TestCaseManagerWidget* test_case_manager_` 成员 + getter + 前向声明
- `SidebarWidget.cpp setupUi()`：
  - 按钮索引 7（追加）：「用例」, 图标 `testcase_dark.svg` / `testcase_light.svg`
  - 页 7：构造 TestCaseManagerWidget → `stack_->addWidget()` → `view_titles_ << "用例"`
- `SidebarWidget.cpp`：实现 `testCaseManager()` getter

### 3.3 main_window.cpp 信号连接

```cpp
auto* tcMgr = sidebar_->testCaseManager();
connect(tcMgr, &TestCaseManagerWidget::openFileRequested,
        editor_manager_, &EditorManager::openFile);
connect(&projectMgr, &ProjectManager::projectOpened,
        tcMgr, &TestCaseManagerWidget::refreshList);
connect(&projectMgr, &ProjectManager::projectClosed,
        tcMgr, &TestCaseManagerWidget::refreshList);
```

## Phase 4: 用例编辑器 TestCaseEditorWidget

### 4.1 编辑器类 — `src/app/TestCaseEditorWidget.h/.cpp` (新增)

继承 `QWidget` + `IEditor`：

- **`editorType()`** → `"testcase"`
- **UI 布局**（QSplitter 或 QVBoxLayout）：
  - 顶部：用例名称输入框 + 描述文本框
  - 中间：步骤表格（QTableWidget），列：`# | 步骤说明 | 命令 | 目标 | 值 | 延迟(ms) | 超时(ms)`
  - 底部工具栏：+ 添加步骤、- 删除步骤、↑ 上移、↓ 下移
  - 左侧可切换：用例列表（suite 内切换不同 case）
- **`loadFile(path)`**：读取 .tcase JSON → 填充表格
- **`save()`** / **`saveAs()`**：表格数据 → TestSuiteData → 写文件
- 发射 `modificationChanged(bool)` 信号

### 4.2 EditorManager 注册

`EditorManager::registerEditorTypes()` 中：

```cpp
EditorFactoryRegistry::registerExtension("tcase", "testcase");
EditorFactoryRegistry::registerFactory("testcase", [](const QString& id, QWidget* parent) {
    return new TestCaseEditorWidget(id, parent);
});
```

同时 `openFile()` 中的 artifact ref 注册代码追加 `.tcase` 分支。
