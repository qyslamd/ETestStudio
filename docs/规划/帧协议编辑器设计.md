# 帧协议编辑器设计

## 1. 背景

### 1.1 现有资产

| 资产 | 位置 | 状态 |
|------|------|------|
| ICD 数据模型库 | `src/icd_utility/` | 完整：Frame/Node/Repository + 解码/编码 + XML/JSON 解析 + Loader |
| 协议编辑器 UI | `src/protocal/` | 骨架：三栏布局、位视图，数据全部硬编码占位 |
| 参考 XML Schema | `D:\sb\eph435\Schema/` | 452 个文件：IcdConfig.xsd + IcdSchema.xsd + 真实设备数据 |
| `.eproto` 注册 | `EditorManager` 中 `registerExtension` | 已有文件扩展名到编辑器类型的映射，但无加载/保存 |

### 1.2 icd_utility 分层架构

```
Loader (src/loader/loader.cpp)
  |  解析配置文件 → SchemaConfig
  |  遍历 frame 文件 → SchemaFrameDef
  v
Format (src/format/)
  |  xml_parser.cpp / json_parser.cpp
  |  输出 SchemaConfig / SchemaFrameDef
  v
Schema (src/schema/)
  |  schema.hpp: SchemaNodeDef / SchemaFrameDef / SchemaFileEntry / SchemaConfig
  |  builder.cpp: SchemaConfig → Repository
  v
Core (src/core/)
  |  node.cpp / frame.cpp / repository.cpp
  |  运行时对象：decode/encode 算法
```

## 2. 核心设计

### 2.1 .eproto 文件格式

选用 **JSON** 格式（基于 icd_utility 已有的 json_parser + 便于手写和调试）。

```json
{
  "version": "1.0",
  "frames": [
    {
      "id": 90,
      "name": "A429_00_ISI_01_发送_Label110",
      "description": "UTC 时间",
      "type": "cmd",
      "byteOrder": "littleEndian",
      "length": 4,
      "nodes": [
        {
          "name": "ISI-01#A429_IN1(110) 发送数据",
          "description": "",
          "offset": 0,
          "startBit": 0,
          "bitWidth": 32,
          "valueType": "uint32",
          "tag": "none",
          "attrs": { "unit": "", "isScaled": false },
          "children": [
            { "name": "LABEL", "description": "Label 110",
              "offset": 0, "startBit": 0, "bitWidth": 8,
              "valueType": "uint8", "tag": "head" },
            { "name": "SDI", "description": "SDI",
              "offset": 0, "startBit": 8, "bitWidth": 2,
              "valueType": "uint8", "tag": "none" }
          ]
        }
      ]
    }
  ]
}
```

**格式说明**：
- 顶层 `frames` 数组替代 ICDConfig 的 FileInfo 列表（扁平化，一个文件就是一个完整项目）
- 每帧的 `nodes` 替代 ICDSchema 的 Data/Item 列表，保留递归 children 结构
- `valueType` 使用 icd::ValueType 枚举名的小驼峰形式
- `byteOrder` 使用 `"littleEndian"` / `"bigEndian"`
- `type` 使用 `"cmd"` / `"data"` / `"dataCfg"`

### 2.2 持久化方案

在 icd_utility 中新增 **Serializer** 层（与现有 Parser 对称）：

```
icd_utility/
  src/
    format/
      json_parser.cpp     ← 已有（读）
      json_serializer.cpp ← 新增（写）
```

- `serialize_repository(path, Repository&)` — 将完整 Repository 写入 .eproto
- `serialize_frame(path, Frame&)` — 单帧写入

### 2.3 编辑器 UI 架构

继承现有 ProtocalEditorWidget 的三栏布局，将硬编码数据替换为 icd_utility 数据模型：

```
┌─────────────────────────────────────────────────────┐
│  工具栏: [帧名称] [帧类型▾] [字节序▾] [新建帧] [删除帧] │
├──────────┬────────────────────────┬──────────────────┤
│ 信号树    │  位布局视图             │  属性面板          │
│          │                        │                   │
│ 帧1       │  +0 +1 +2 +3          │  名称: LABEL      │
│ ├─ 信号A  │  ┌──┬──┬─────────────┐│  偏移: 0          │
│ │  ├─ 位1 │  │LB│SD│   Data      ││  起始位: 0        │
│ │  └─ 位2 │  ├──┼──┼──┬──────────┤│  位宽: 8          │
│ ├─ 信号B  │  │   SSM   │  P│  PAR ││  类型: uint8       │
│ 帧2       │  └─────────┴──┴───────┘│  标签: 帧头        │
│           │                        │  缩放: 否          │
│           │  模式: [32位字▾]        │                   │
├──────────┴────────────────────────┴──────────────────┤
│  状态栏: GNSS_Latitude  |  Offset: 1  |  Bit: 0~20    │
└─────────────────────────────────────────────────────┘
```

#### 2.3.1 信号树（IcdNodeTreeWidget）

- **第一级** = 帧列表（显示帧名称、ID、类型图标）
- **展开** = 帧内的 Node 树（递归子节点）
- 每个节点显示：名称 + 位范围 + 类型
- 过滤/搜索栏保留
- 右键菜单：新建子节点、删除节点、上移/下移

#### 2.3.2 位布局视图（IcdBitLayoutView）

- **数据源**：从当前选中帧的 icd::Frame 读取节点树
- **栅格**：每行 4 字节（32位），字节标尺 + 位标尺
- **色块**：每个 Node 映射为一个可交互的 BitBlockItem
  - 点击选中 → 右侧属性面板更新 + 信号树对应项高亮
  - 颜色按 Tag/GroupName 区分
  - 父节点以半透明浅色块打底，子节点覆盖其上
- **模式**：32位字 / 8位字节（保留现有 modeCombo）

#### 2.3.3 属性面板（IcdPropertyPanel）

- **基本属性**：名称、描述、偏移、起始位、位宽、值类型、标签
- **缩放属性**：是否缩放、缩放系数A/B、缩放公式、单位
- **扩展属性**：所属系统、分组、枚举值映射（ValueTextList）、通道映射（LinkTo）、最小值、最大值
- 全部可编辑，修改即更新数据模型 + 标记 modified

#### 2.3.4 工具栏

| 控件 | 行为 |
|------|------|
| 帧名称标签 | 显示当前选中帧名称（双击可重命名） |
| 帧类型下拉 | Cmd / Data / DataCfg，切换修改帧类型 |
| 字节序下拉 | Little Endian / Big Endian |
| 新建帧按钮 | 弹出对话框：输入名称、ID、类型、字节序、帧长度 |
| 删除帧按钮 | 确认删除当前选中帧 |
| 新增信号按钮 | 在选中帧/节点下添加子节点 |

### 2.4 数据流

```
加载:
  .eproto 文件
    → json_parser::parse_json_config()     ← 复用现有
    → schema::build_repository()            ← 复用现有
    → icd::Repository
    → 填充信号树 + 位视图 + 属性面板

编辑:
  UI 操作 (属性修改/增删节点)
    → 直接修改 icd::Frame / icd::Node      ← 需要新增 setter API
    → QUndoCommand 记录
    → 刷新 affected 视图

保存:
  icd::Repository
    → json_serializer::serialize_repository()
    → .eproto 文件
```

### 2.5 撤销/重做

在 `ProtocalEditorWidget` 中集成 `QUndoStack`，每个编辑操作对应一个 Command：

| Command | 操作 |
|---------|------|
| `ModifyNodePropertyCommand` | 修改节点属性（名称/偏移/位宽等） |
| `AddNodeCommand` | 添加节点 |
| `RemoveNodeCommand` | 删除节点 |
| `MoveNodeCommand` | 移动节点（拖拽调整顺序/层级） |
| `AddFrameCommand` | 添加帧 |
| `RemoveFrameCommand` | 删除帧 |
| `ModifyFramePropertyCommand` | 修改帧属性（名称/类型/字节序） |

### 2.6 与拓扑编辑器的对比

| 方面 | 拓扑编辑器 | 帧协议编辑器 |
|------|-----------|-------------|
| 数据模型 | TopologyDocument | icd::Repository |
| 序列化 | 自定义 JSON | icd_utility json_serializer |
| 撤销栈 | TopologyUndoStack | QUndoStack |
| 图形视图 | QGraphicsView (自由画布) | QGraphicsView (位栅格) |
| 属性面板 | PropertyPanelWidget | IcdPropertyPanel |
| 大纲面板 | TopologyOutlineWidget | IcdNodeTreeWidget |

## 4. 设计决策（已确认）

| 问题 | 决策 | 影响 |
|------|------|------|
| 帧长度 | **变长**（无固定长度），从节点最大 offset + bit_width 推算 | 位布局视图需要支持动态长度，无固定栅格限制 |
| 枚举值编辑器 | **需要专用 UI** — 键值对表格编辑器，内嵌在属性面板中 | 属性面板新增 ValueTextList 编辑控件；值文本列表存为 `vector<pair<string,int>>` |
| icd_utility 复用 | **保持独立可复用**，不与 Qt/etest 耦合 | icd_utility 不引入 Qt 依赖，序列化/反序列化保持纯 C++17；json_serializer 用 nlohmann/json |
