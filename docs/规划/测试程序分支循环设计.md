# 测试程序分支循环设计

## 1. 背景与问题

当前 `LOOP` / `WHILE` / `IF` 三个控制流命令在测试程序编辑器中存在两个问题：

1. **子步骤表无编辑入口**：`createSubStepTable` 只建了空表（0 行）+ 列头 + FlatOnly 命令委托 + `itemChanged` 信号，没有添加/删除/移动行的任何入口。用户面对"循环体步骤"/"then 分支"/"else 分支"的空表无从下手。
2. **控制流功能无法剔除**：LOOP/WHILE/IF 代码散落 7 个文件，日后若决定不要分支循环，没有统一开关，要逐处删。

## 2. 设计目标

1. 为子步骤表提供完整的编辑入口（添加 / 删除 / 上移 / 下移）。
2. 提供一个**开关**（编译期常量），关闭后控制流功能从 UI / 命令列表 / 校验中消失，无需改设计、无需搬代码模块。日后不要分支循环时改一个常量即可禁用，要彻底移除再删代码。

**不要求**设计独立、代码模块独立。控制流代码仍留在原文件，靠开关剔除。

## 3. 现状分析

控制流代码当前散落于：

| 文件 | 控制流相关内容 |
|---|---|
| `CommandTypeDelegate.cpp` | Full 列表含 `LOOP` / `WHILE` / `IF`（:11-12），FlatOnly 排除 |
| `StepDetailPanel.cpp` | `createLoopPage` / `createWhilePage` / `createIfPage`、`createSubStepTable`、`switchToPageForCommand` 的 LOOP/WHILE/IF 分支（:702-707）、`writePageToCache` / `fillPageFromCache` / `stepData` 的 kPageLoop/While/If 分支 |
| `TestProgramEditorWidget.cpp` | `extraCellText` / `extra2CellText` 的 WHILE/IF 分支、`readStepData` / `dataChanged` handler 对 `loopCount` / `loopIntervalMs` / `subSteps` / `elseSubSteps` 的回写 |
| `StepValidation.cpp` | LOOP/WHILE/IF 校验（:56-77） |
| `TestProgramData.h` | `loopCount` / `loopIntervalMs` / `subSteps` / `elseSubSteps` 字段、`isControlFlow()` / `hasSubSteps()` |
| `TestProgramData.cpp` | `testStepToJson` / `testStepFromJson` 的控制流字段序列化、`stepsToJsonArray` / `stepsFromJsonArray` 子步骤辅助 |

注意：`condition` 字段 `WAIT` 也用，不属于控制流专属。`tolerance`（VERIFY）、`fault`（INJECT_FAULT）同理。

## 4. 总体策略

**分两阶段。**

- **阶段1**：新建 `SubStepTableWidget`，解决子步骤编辑入口（用户痛点）。
- **阶段2**：引入编译期开关 `kControlFlowEnabled`（`constexpr bool`），在控制流相关代码处用 `if (kControlFlowEnabled)` 包裹。关闭后控制流功能不执行（编译器优化死代码，等效剔除二进制）。

**为什么用 `constexpr bool` 而非 `#ifdef`**：
- `#ifdef` 散落几十处，代码可读性差。
- `constexpr bool` 是编译期常量，`if (kControlFlowEnabled)` 在 `false` 时编译器直接优化掉整个分支，等效编译期剔除，但代码保持完整可读。
- 改一个常量即可禁用，无需改 CMake、无需重新 configure。

**为什么不搬代码到独立模块**：用户不要求代码模块独立。开关在原处加，改动最小。

## 5. 阶段1：SubStepTableWidget（子步骤编辑入口）

### 5.1 组件定义

新建 `src/test_program/sub_step_table_widget.h` / `.cpp`。

```cpp
class SubStepTableWidget : public QWidget {
  Q_OBJECT
public:
  explicit SubStepTableWidget(QWidget* parent = nullptr);
  void setSubSteps(const QVector<TestStepData>& steps);
  QVector<TestStepData> subSteps() const;
  void setReadOnly(bool ro);
signals:
  void subStepsChanged();
private slots:
  void onAdd();
  void onRemove();
  void onMoveUp();
  void onMoveDown();
private:
  void updateButtonStates();
  QTableWidget* table_;
  QPushButton* add_btn_;
  QPushButton* remove_btn_;
  QPushButton* up_btn_;
  QPushButton* down_btn_;
};
```

### 5.2 UI

- 上方一行 4 个**文字按钮**（`+` / `-` / `↑` / `↓`），零资源成本，后续要换图标再换。
- 下方 `QTableWidget`，5 列：步骤说明 / 命令 / 目标 / 值 / 延迟(ms)。
- 命令列用 `CommandTypeDelegate::FlatOnly`（子步骤不含控制流，保证不嵌套）。
- 列宽：`setStretchLastSection(true)`，第 0 列（步骤说明）`setSectionResizeMode(Stretch)`，其余列 `ResizeToContents`（沿用当前 `createSubStepTable` 策略）。
- `setReadOnly(true)`：禁用 4 个按钮 + `table_->setEditTriggers(NoEditTriggers)`；`false` 恢复 `DoubleClicked|EditKeyPressed`。当前 `createSubStepTable` 未处理 readOnly（现有遗漏），阶段1 顺手补。
- 子步骤内容靠**双击单元格**编辑（QTableWidget 默认 + FlatOnly 命令列下拉）。

### 5.3 行操作实现

- **`onAdd`**：`QSignalBlocker` 包住 `table_`，`insertRow(rowCount)` + 命令列 `setItem("SET")` + 延迟列 `setItem("0")`；解锁后**手动 `emit subStepsChanged()` 一次**。
- **`onRemove`**：`QSignalBlocker` 包住，`removeRow(currentRow)`；手动 emit 一次。
- **`onMoveUp` / `onMoveDown`**：`QSignalBlocker` 包住，**逐 cell 交换 `text()`**（不交换 item 指针，避免 delegate/选中状态错乱）；手动 emit 一次。子步骤表只有 5 列文本、无 UserRole 自定义数据，逐 cell 交换 text 足够。
- **`updateButtonStates`**：连 `itemSelectionChanged`。`-` / `↑` / `↓` 无选中行禁用；`↑` 第一行禁用；`↓` 最后一行禁用。

> **信号策略（关键）**：`table_` 的 `itemChanged` 连 `subStepsChanged`（用户单元格编辑走这条）。所有程序化改动（`setSubSteps`、行增删移动）一律用 `QSignalBlocker` 屏蔽 `itemChanged`，操作完手动 emit 一次 `subStepsChanged`。避免一次操作触发多次信号、避免填充时误触发。

### 5.4 数据读写

- `setSubSteps`：`QSignalBlocker` 包住 `table_`，`setRowCount(steps.size())`，逐行 `setItem` 5 列；**不发 `subStepsChanged`**（程序化填充，避免切步骤/加载时误触发 `dataChanged` → `setModified`）。
- `subSteps`：逐行读 5 列构造 `TestStepData`（只填 description/cmd/target/value/delayMs，扩展字段默认空——和现状一致，子步骤表不存容差/条件）。

### 5.5 接入 StepDetailPanel（阶段1）

- `StepDetailPanel.h`：`loop_sub_table_` / `while_sub_table_` / `if_then_table_` / `if_else_table_` 类型从 `QTableWidget*` 改为 `SubStepTableWidget*`。
- `createSubStepTable` 改为 `return new SubStepTableWidget(this)`，并连接 `subStepsChanged` → `dataChanged`（替代旧的 `itemChanged` → `dataChanged`）。
- `writePageToCache` / `fillPageFromCache` / `stepData` 里子步骤的逐行读写，改为调 `setSubSteps` / `subSteps()`。
- `cache_` 仍在 `StepDetailPanel`，切页"抓回旧页"逻辑（`setStepData` 开头的 `writePageToCache`）不变。
- CMake 加 `sub_step_table_widget.cpp`。
- **顺手修 bug**：当前 `createSubStepTable` 的 `itemChanged → dataChanged` 无 `internal_update_` 守卫，`fillPageFromCache` 填子步骤表时触发 `dataChanged` → handler `setModified(true)` + `saveSnapshot`（切步骤就置 modified、多压快照）。改用 `SubStepTableWidget` + `setSubSteps` blockSignals 后，填充不发信号，这个 bug 自动消失。

## 6. 阶段2：控制流开关

### 6.1 开关定义

新建 `src/test_program/control_flow_config.h`：

```cpp
#pragma once

namespace etest::app {

// 控制流功能（LOOP/WHILE/IF）开关。
// true  ：控制流命令出现在命令列表、详情页、校验中。
// false ：控制流功能从 UI/校验中消失；已有数据仍保留（序列化/字段不变）。
// constexpr 编译期常量，false 时编译器优化掉相关分支，等效剔除二进制。
constexpr bool kControlFlowEnabled = true;

}  // namespace etest::app
```

### 6.2 开关点清单

在以下位置用 `if (kControlFlowEnabled)` 包裹控制流逻辑（`#include "control_flow_config.h"`）：

| 文件 | 开关点 | 关闭后行为 |
|---|---|---|
| `CommandTypeDelegate.cpp` | Full 列表添加 `LOOP` / `WHILE` / `IF` | 命令下拉无这三项，不能新建 |
| `StepDetailPanel.cpp` 构造 | `addWidget(createLoopPage/WhilePage/IfPage)` | stack_ 不注册控制流页 |
| `StepDetailPanel::switchToPageForCommand` | `LOOP` / `WHILE` / `IF` case | 控制流命令走 default（kPageEmpty），详情页空 |
| `StepDetailPanel::writePageToCache` / `fillPageFromCache` / `stepData` | kPageLoop/While/If 分支 | 跳过，`cache_` 的控制流字段保留 ext data 原值 |
| `StepValidation.cpp` | `LOOP` / `WHILE` / `IF` 校验块 | 不校验这三类 |
| `TestProgramEditorWidget.cpp` `extraCellText` / `extra2CellText` | `WHILE` / `IF` 分支 | 返回空字符串 |

### 6.3 不开关的（数据层保留）

- `TestProgramData.h` 的 `loopCount` / `loopIntervalMs` / `subSteps` / `elseSubSteps` 字段：**保留**。`TestStepData` 是统一数据结构，字段保留保证数据层稳定，关闭开关不影响结构布局。
- `TestProgramData.cpp` 的 `testStepToJson` / `testStepFromJson` 控制流字段序列化：**保留**。关闭开关后，已有含 LOOP 的文件仍能完整加载/保存（数据不丢），只是 UI 不编辑。
- `readStepData` / `dataChanged` handler 的控制流字段回写：**保留**。关闭开关后 UI 不编辑控制流，`dataChanged` 不触发，回写自然不执行；`readStepData` 读 ext data 的控制流字段保留数据。

**原则**：开关只管"UI 显示 + 命令列表 + 校验"，数据层（字段 / 序列化 / ext data）始终保留。这样关闭后已有文件数据完整，重新打开开关仍可编辑。

## 7. 剔除方式

### 7.1 禁用（改一个常量）

`control_flow_config.h` 设 `kControlFlowEnabled = false`，重新编译。效果：
- 命令下拉无 LOOP/WHILE/IF，不能新建。
- 已有 LOOP/WHILE/IF 步骤仍在表格里显示（cmd 列文本），但详情页空（切到 kPageEmpty），不可编辑。
- 校验跳过控制流。
- 序列化保留，保存/加载不丢数据。

### 7.2 彻底移除（删代码）

禁用后若要彻底删，按以下顺序（每步可独立编译）：

1. 删 `sub_step_table_widget.h/.cpp` + `control_flow_config.h`。
2. `StepDetailPanel`：删 `createLoopPage` / `createWhilePage` / `createIfPage` 及调用、`loop_sub_table_` / `while_sub_table_` / `if_then_table_` / `if_else_table_` 成员、`switchToPageForCommand` 的控制流分支、`writePageToCache` / `fillPageFromCache` / `stepData` 的 kPageLoop/While/If 分支。调整页面索引枚举：删 `kPageLoop` / `kPageWhile` / `kPageIf`，`kPageFault` / `kPageActionLog` 索引前移（原 6/7 → 3/4）。
3. `CommandTypeDelegate`：Full 列表去掉 `LOOP` / `WHILE` / `IF`。
4. `StepValidation`：删 LOOP/WHILE/IF 校验块。
5. `TestProgramData.h`：删 `loopCount` / `loopIntervalMs` / `subSteps` / `elseSubSteps` 字段 + `isControlFlow()` / `hasSubSteps()`。
6. `TestProgramData.cpp`：删 `testStepToJson` / `testStepFromJson` 的控制流字段序列化 + `stepsToJsonArray` / `stepsFromJsonArray`。**保留** `condition` / `tolerance` / `fault` 序列化。
7. `TestProgramEditorWidget.cpp`：删 `extraCellText` / `extra2CellText` 的 WHILE/IF 分支；删 `readStepData` / `dataChanged` handler 里 `loopCount` / `loopIntervalMs` / `subSteps` / `elseSubSteps` 四行回写。**保留** `condition` / `tolerance` / `fault` 回写。
8. CMake：移除 `sub_step_table_widget.cpp`。

### 7.3 向后兼容（彻底移除后的旧文件）

彻底移除后，已有的含 LOOP/WHILE/IF 的 `.etprog` 文件：

- `testStepFromJson` 不再读 `loopCount` / `subSteps`，旧文件的 LOOP 步骤加载后 `cmd="LOOP"` 但无循环体，成为空壳。
- `CommandTypeDelegate` Full 列表无 LOOP，cmd 下拉没有 LOOP，但旧行文本仍显示 "LOOP"（可编辑框）。
- `StepValidation` 不校验 LOOP，空壳 LOOP 不报错。

**建议**：移除时在 `testStepFromJson` 处理废弃命令，二选一：
- **降级**：转为 `ACTION`，`description` 写原 `cmd` 文本（如 `"LOOP（已废弃）"`），`target` / `value` 清空。
- **跳过**：直接丢弃该步骤，日志告警。

不做静默吞数据。具体策略在移除时定。

## 9. 边界与取舍

- **子步骤表列固定 5 列**（步骤说明/命令/目标/值/延迟），子步骤不能设容差/条件/超时。若循环体需要 VERIFY 带容差等，要么扩列，要么子步骤也走 ext data + 双击弹子面板——本方案不解决，留作后续。
- **子步骤不支持嵌套控制流**：FlatOnly 委托 + `testStepFromJson` depth 限制，循环体/分支内不能再套 LOOP/WHILE/IF。保留此约束。
- **`condition` 字段归属**：WAIT（非控制流）也用 `condition`，定义保留在 `TestProgramData` 基础结构。WHILE/IF 页面只是读写 `condition`。三套 condition 编辑 UI（WAIT 的 kPageCondition、WHILE、IF）代码重复，这是现有问题，本方案不解决——可后续抽 `ConditionEditor` 复用。
- **行交换用逐 cell 交换 text**：子步骤表无 UserRole 数据，足够。若将来子步骤加 ext data，要改为交换整行数据。
- **文字按钮**：`+` / `-` / `↑` / `↓`，零资源。后续要图标再走 AppIconProvider + qrc + 主题适配。
- **开关不覆盖数据层**：字段 + 序列化保留，关闭开关后数据完整可恢复。若要求关闭后连数据也不序列化，再在序列化处加 `if (kControlFlowEnabled)`，但会让旧文件在开关切换时丢数据，不推荐。
- **`constexpr bool` 而非 `#ifdef`**：代码可读，编译器优化死代码等效剔除。若将来要按构建配置切换（如 Release 禁用、Debug 启用），可改为 CMake option + `#define`，但当前用一个常量头文件足够。
